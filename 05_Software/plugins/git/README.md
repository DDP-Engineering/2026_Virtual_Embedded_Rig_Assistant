# Git

Uses your Git >=2.40 on PATH, the standard Git for Windows paths or /usr/bin/git. Install Git yourself if missing; VERA never downloads it. Install this package from the catalog/folder and enable it for the workbench. Its three skills are git-inspect, git-commit and git-branches.

History, status, diffs, blame and branch/tag/remote/stash listings are safe. Changes and remote operations need approval outside Bypass. Discarding changes, checkout/restore/clean, hard resets, stash deletion and force/deletion pushes are irreversible and need the typed confirmation outside Bypass. The highest matching risk wins. Executable aliases, unknown command names (which may name helpers), configuration/location overrides, interactive/exec commands and explicit helper/viewer/signing options are blocked in every mode. Unrecognised options on known commands require approval. Short options are case sensitive; values and paths after -- are not flags. Output destinations require approval even under read commands. Do not treat the risk classifier as a complete Git syntax validator.

The fixed configuration disables fsmonitor, hooks and pager. External diff additionally requires VERA's execution guard: diff.external= alone fails on a nonempty diff; VERA inserts --no-ext-diff at diff/log/show and stash/reflog read-command boundaries before the original options and -- delimiter. This forces working built-in diff output without executing global or named external-diff commands. Classification, approval and run-record labels retain the original argument values/order. Bare stash show follows Git's patch fallback after the injected option; use --stat or -p explicitly for the desired shape. no-hooks/README.txt preserves the inert hooks directory in installed zips. GIT_EDITOR=: and GIT_SEQUENCE_EDITOR=: avoid interactive editors, GIT_OPTIONAL_LOCKS=0 suppresses optional index updates, and prompts are disabled using GIT_TERMINAL_PROMPT=0 and GCM_INTERACTIVE=never. Use commit -m and noninteractive branch workflows. Fetch/pull/push/clone/ls-remote contact remotes and require configured user credentials or SSH keys; otherwise Git fails with its own error under the run timeout. Credential helpers remain configured. VERA does not inject its credentials. The runner's minimal environment does not forward SSH_AUTH_SOCK or arbitrary GIT_* host overrides; configure Git's normal on-disk setup where needed.

Git is not sandboxed. Content filters (including LFS) remain enabled, and repository-local diff.<driver>.textconv or filter.<driver> programs can execute when attributes select them. Explicit textconv/filter requests are blocked, but the fixed prefix cannot disable every named driver. Other Git configuration, including signing, merge drivers, credential/SSH transport and implicit lazy fetches in partial clones, also retains Git semantics. Git safe.directory is an ownership check, not a trust guarantee for a copied repository. Review an untrusted workbench as an untrusted Git repository; this package does not promise to prevent all configured program execution or network access.

Git changes bypass VERA's write queue and do not appear in the Changes panel. The run log records the command/output and the document-index watcher observes changed files. cwd passes the workbench path guard; Bypass permits the same broader cwd scope as the file tools. Git may change tracked .vera configuration and skills.

Acceptance uses only isolated repositories and controlled loopback remotes. Platform proof distinguishes Git for Windows, Linux under Ubuntu WSL2 and ARM64; a declared platform is not an execution receipt.
