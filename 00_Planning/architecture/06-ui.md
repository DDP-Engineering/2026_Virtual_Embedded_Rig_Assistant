# 06 — User interface

PURPOSE: specify VERA's screens, layout, components, appearance settings (themes, text size),
languages, accessibility, the renderer mock mode and the reserved voice seam.
DONE-WHEN (for the work packages that implement it): every screen below renders in light and dark
themes, at every text size and in English, Romanian and German, with no missing translation key and
no horizontal overflow at 1024×640.

## 1. Layout

```
┌────────────┬──────────────────────────────────────┬───────────────────────┐
│ Sidebar    │ Session                              │ Right panel (tabs)    │
│ workbench  │ transcript                           │ Context · Docs ·      │
│ switcher   │                                      │ Changes · Artifacts · │
│ sessions   │                                      │ Plan                  │
│ + New      │ composer: text · model · mode · Send │                       │
└────────────┴──────────────────────────────────────┴───────────────────────┘
```

- Sidebar and right panel are resizable and collapsible; their sizes persist.
- Minimum window 1024×640. Below 1280 px width the right panel overlays the transcript instead of docking.

## 2. Screens

| Screen | Content |
|---|---|
| Welcome | Create workbench (folder picker and name), Open workbench, recent list with a missing-folder state |
| Session | transcript, composer, right panel |
| Workbench settings | General (name, description); Documents (include and exclude globs, index status, Reindex); Skills (list, enable or disable, open, create); Tools (internal tools with enable or disable); Agent (default mode, default model) |
| App settings | Providers; Appearance; Language; Updates; Data & privacy (paths, the egress list of 01 §8); About (version) |
| Document viewer | PDF, Markdown and text, opened from a ref or from the Docs tab |

## 3. Session components

- **Transcript**: user and assistant messages; Markdown with highlighted code; citation chips that
  open the viewer, invalid refs as warning chips; collapsible reasoning; tool rows (icon, name,
  one-line summary, expandable arguments and preview); approval cards inline; errors with Retry.
- **Approval card**: tool, path, unified diff with syntax colours, byte size; buttons Approve, Deny,
  Approve and switch to auto-edit. With the card focused, `A` approves and `D` denies.
- **Composer**: multi-line input (Enter sends, Shift+Enter adds a line); `@` completes workbench paths
  and inserts them as text; model picker; permission-mode picker; Stop while a turn runs. Input is
  disabled while an approval waits in this session.
- **Footer**: input and output tokens, context usage when known, provider and model.
- **Right panel**: Context (WORKBENCH.md preview, available skills), Docs (index status, search box,
  open), Changes (files changed in this session, with diffs), Artifacts (open, reveal, export), Plan
  (the `todo` list).
- Sidebar entries show status badges: running, awaiting approval, error.

## 4. Appearance

- Themes: Light, Dark, System. Colours are CSS variables (the shadcn/ui token set) in
  `renderer/styles/themes.css`; a new theme is a new token block, never new components.
- Text size in five steps — 87.5 %, 100 % (default, 14 px base), 112.5 %, 125 %, 150 % — applied to
  the root font size. Every component size uses `rem`, code blocks included.
- Density is fixed in 1.0.

## 5. Document viewer

- PDF through pdfjs-dist in the renderer: page navigation, zoom, text search, highlight of the cited
  snippet.
- Markdown rendered with heading anchors; text with line numbers and a highlighted range.
- Opens any ref of 05 §7 at its locator.

## 6. Languages

- i18next with JSON catalogs `renderer/locales/{en,ro,de}.json`; `en` is the source.
- `npm run check:i18n` fails on missing keys, unused keys and keys present only in a translation.
- Setting: System (default, from the OS locale), English, Română, Deutsch.
- Core errors arrive as `messageKey` and `params` (01 §3) and are translated here.
- The UI language does not constrain the agent; it answers in the user's language.

## 7. Accessibility

- Every control is reachable by keyboard, with a visible focus ring and a logical tab order.
- Text contrast meets WCAG 2.1 AA in both themes.
- Icons carry accessible names; no state is conveyed by colour alone.
- `prefers-reduced-motion` is honoured.
- Shortcuts: Ctrl+N new session, Ctrl+, settings, Esc stops the running turn (with confirmation),
  Ctrl+F searches the transcript.

## 8. Mock mode

`VITE_API=mock npm run dev:renderer` runs the renderer in a browser against an in-memory
`VeraBridge` with fixture sessions — the pattern of BenchPilot's `mockApi`. Every screen and state is
reachable in mock mode; component tests and screenshot reviews use it.

## 9. Reserved: voice (post-1.0)

- A hold-to-talk button in the composer; local speech-to-text after release (batch, not streaming),
  the pattern pi's voice extensions use.
- Seam: a `SpeechToText` port in core, `transcribe(pcm16kMono): Promise<string>`. Candidate: a Whisper
  ONNX model on the transformers.js and onnxruntime already shipped for embeddings, so voice adds a
  model, not a runtime.
- Audio capture in the renderer through `getUserMedia`; the permission handler (01 §7) then allows
  `media` for the app's own origin only.
- Local text-to-speech (Piper, Kokoro or Kitten class models) is a separate decision.
