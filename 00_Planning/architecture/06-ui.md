# 06 — User interface

Describes the implementation as of 2026-11-01 (master, 33e72b8 plus working tree). Written on
2026-10-09 as a plan and updated to the code; code paths are relative to
`05_Software/src/apps/desktop/src/`.

PURPOSE: specify VERA's screens, layout, components, appearance settings (themes, text sizes),
languages, accessibility, keyboard shortcuts, the renderer mock mode and the reserved voice seam.
DONE-WHEN (for the work packages that implement it): every screen below renders in light and dark
themes, at every text size and in English, Romanian and German, with no missing translation key and
no horizontal overflow at 1024×640.

## 1. Layout

```
┌───────────────────────────────────────────────────────────────────────────────┐
│ [◧] File Edit View Help                         [◨]  native min · max · close │ title row, 40 px
├─────────────┬────────────────────────────────────────┬────────────────────────┤
│ Sidebar     │ Main                                   │ Right panel (tabs),    │
│ VERA        │ workbench overview · new workbench ·   │ collapsed by default   │
│ New / Open  │ workbench editor · settings section ·  │ Context · Docs ·       │
│ Plugins     │ plugins — or the session (Chat and     │ Changes · Artifacts ·  │
│ workbenches │ document tabs): title, transcript,     │ Plan · Runs            │
│  └ sessions │ composer: text · model · reasoning ·   │                        │
│ Settings    │   mode · context % · activity · Send   │                        │
└─────────────┴────────────────────────────────────────┴────────────────────────┘
```

- Visual reference: the layout A mockups in `../ui/` are historical; `../ui/README.md` lists how the
  implementation differs.
- Window chrome: `titleBarStyle: "hidden"` with a themed 40 px `titleBarOverlay` for the native
  controls (`main/window-chrome.ts:18-24`, `main/index.ts:528-534`); no application menu. The title
  row holds the sidebar toggle, File/Edit/View/Help buttons that pop up native role menus through the
  `window.menu` IPC (`main/window-chrome.ts:27-44`), and the right-panel toggle. F10 focuses File;
  Left/Right/Home/End move between menus, Down opens one (`renderer/components/shell.tsx:164-326`).
- Sidebar: VERA brand; New Workbench, Open Workbench, Plugins; the workbench list (recent workbenches,
  expandable, with the active workbench's sessions nested); Settings at the bottom. In Settings it
  shows "Back to workbenches" and the section list instead. Collapsed, it is an icon rail with the
  same actions, a Workbenches button that expands the sidebar, and Settings.
- Sidebar and right panel are resizable by pointer and keyboard (arrows, Home/End) and collapsible
  (Ctrl+B, Ctrl+Shift+B). Widths in rem: sidebar 12–24 (default 17), right panel 14–28 (22).
  The geometry persists in the versioned renderer localStorage record `vera.ui.layout`
  (`version` 1); invalid or other-version data gives the defaults and has no
  read-only mode (`renderer/lib/layout.ts`). The
  settings file owns appearance and language.
- Navigation is in-memory state of one page at `vera://app/index.html` (development
  `http://127.0.0.1:5173`); IPC authorization checks that exact URL (`main/index.ts:107`, `576-586`).
- Minimum window 1024×640; first launch up to 1200×800; bounds persist in `window-state.json` (`version` 1; an invalid, other-version or off-screen file gives centred defaults). Below
  1280 px width the right panel overlays the main area (at most 45 vw) instead of
  docking (`renderer/styles.css:696-707`).

## 3. Session components
- **Transcript**: user and assistant messages; GitHub-flavoured Markdown with highlighted code; raw
  HTML skipped, images shown as their alt text, http(s) links open in the system browser after a
  confirmation dialog; citation chips open the document's tab at the locator, invalid refs render as
  inert warning chips; collapsible reasoning blocks, shown at the top of the transcript; tool rows
  (name, status, expandable arguments and preview); approval cards inline; errors with Retry, which
  resends the last user message; context-limit advice. Ctrl+F opens a transcript search that marks
  and counts matching messages; a scroll rail controls the transcript viewport
  (`renderer/components/session/transcript.tsx`, `transcript-scroll.tsx`, `workspace.tsx:140-175`).
- **Approval card**: tool, path, unified diff (added and removed lines coloured, no syntax colours),
  byte size; for `web_download` the source URL and size limit. Buttons Approve, Deny, Approve and
  switch to auto-edit. With the card focused, `A` approves and `D` denies. A decided card shows the
  outcome and whether the user or the mode decided.
- **Composer**: auto-growing multi-line input (Enter sends, Shift+Enter adds a line); `@` completes
  workbench paths and inserts them as text; model picker (04 §3); reasoning picker when the model
  offers levels (04 §9); permission-mode picker (read-only, ask, auto-edit, bypass; bypass shows a
  warning dialog that can be suppressed); a context gauge (percent of the window); an Agent activity
  button; Send; Stop while a turn runs. Input is disabled while an approval waits in this session.
  Esc while a turn runs opens a Stop confirmation (`renderer/components/session/workspace.tsx:103-116`,
  `248-277`).
- **Usage** (no footer): the gauge opens the Context window dialog with skill settings, input and
  output tokens, the estimated or counted context, input budget, output reserve, window, safety
  margin, compaction status, request-view tokens and the model, followed by `.vera/WORKBENCH.md` and
  the enabled skills. The Agent activity dialog lists prompts with their usage, replies, tool calls
  and reasoning (`renderer/components/session/session-inspector.tsx`, `usage-meter.tsx`). Estimates are
  labelled; `context.budget_exceeded` advice explains how to reduce the input or adjust a custom
  model's window, and the full transcript stays visible.
- **Right panel** tabs (Left/Right/Home/End switch tabs; a tab without content shows a placeholder):
  Context (skill settings, rendered `.vera/WORKBENCH.md`, enabled skills; session view only); Docs
  (index status and progress, indexer restart, keyword search, Open, Reindex, volume warning, the
  "Downloaded files" list with open and reveal); Changes (files
  changed in this session with diffs, reveal, history); Artifacts (open in the panel's artifact viewer, reveal, export,
  history); Plan (the `todo` list with pending, in-progress and done icons); Runs (plugin program runs of
  the open workbench, newest 50, refreshed every second: command line, plugin, start time, state and exit
  code; Open log shows the last 1 MiB in a dialog that refreshes while the run runs; Stop on a running run;
  `renderer/components/runs-tab.tsx`).
- **Session list** (under the active workbench): New session, search, archived view; each row shows
  title and last activity, and a menu with move up or down (also Alt+Shift+Up/Down), export as
  Markdown or JSON, archive or restore, rename, delete with confirmation; rename, archive and delete
  wait while the session runs or awaits approval. The status (idle, running, awaiting approval,
  error) is screen-reader text only; visible status badges are Not implemented as of 2026-11-01
  (`renderer/components/session/session-list.tsx:97-174`).

## 4. Appearance

- Themes: Light, Dark, System, as theme cards. The renderer sets `data-theme`; System follows OS
  colour-scheme changes. Main applies `nativeTheme.themeSource` from loaded and updated settings and
  recolours the title-bar overlay (`main/index.ts:78-81`, `463`, `750`).
- Theme colours are CSS variables named after the shadcn/ui token set in
  `renderer/styles/themes.css`; a new theme is a new token block, never new components. Components
  are hand-written CSS (`renderer/styles.css`); shadcn/ui is only scaffolded (`renderer/components/ui/card.tsx`).
- Interface text size in six steps, "Extra small" to "Largest": 75 %, 87.5 %, 100 % (default, 14 px
  base), 112.5 %, 125 %, 150 %, applied to the root font size (`textScale`). Layout sizes use `rem`.
- Chat text and code have separate absolute sizes, 10, 12, 14 (default), 16, 20 or 24 px, set as
  `--chat-font-size` and `--code-font-size` and not scaled by `textScale`; "Reset sizes" restores all
  three (`shared/src/settings.ts:20-44`, `renderer/hooks/use-preferences.ts`).
- Density is fixed in 1.0.

## 5. Document viewer

- Documents open as tabs of the chat area: Chat first (never closed), then one tab per document;
  opening a document that has a tab selects it at the new locator. Tabs close by their button, Delete
  on a focused tab or a middle click (the right neighbour, else the left one, else Chat is selected);
  each tab keeps its place (PDF page, the text's first visible line, other documents' scroll
  offset), the conversation keeps its draft and scroll, and each session keeps its own tabs. A
  session's tabs, their order, the selected tab and each place are saved in renderer localStorage
  (`vera.tabs.<workbenchId>.<sessionId>`, version 1) and come back the first time the session is
  shown after a restart, without documents that no longer exist; deleting the session deletes the
  record (`lib/document-tabs-store.ts`). Esc returns to Chat and to the control that opened the
  document; Ctrl+F shows a find field in PDFs and text, Ctrl+G a go-to-line field in text, and the
  document's right-click menu offers Copy and these commands (with zoom for PDFs)
  (`renderer/components/documents/document-tabs.tsx`, `viewer-context.tsx`, `find-bar.tsx`).
- The panel shows only the document; the path is the tab's tooltip. Document tabs move by drag and
  drop or Ctrl+Shift+PageUp/PageDown, switch with Ctrl+Tab / Ctrl+Shift+Tab or Ctrl+PageUp/PageDown,
  close with Ctrl+W, and their context menu offers Close, Close others, Close to the right, Move left,
  Move right and, for workbench files, the Files actions (Attach, Open in with Default app, Show in
  Explorer, Copy, Properties); a download's tab offers Show in Explorer (`file-actions.tsx`).
- PDF through pdfjs-dist in the renderer, loaded lazily, as one continuous scroll of pages (only the
  pages near the view are drawn) with a page indicator, zoom 50-200% by Ctrl+wheel and
  Ctrl+= / Ctrl+- / Ctrl+0, text search across pages with next and previous match, the cited page
  range, and the cited snippet highlighted on the text layer (`pdf-viewer.tsx`).
- Markdown with heading anchors; HTML, Word and ODT documents and spreadsheets as extracted sections;
  presentations as slides; text with line numbers in one continuous, virtualized scroll and the cited
  range marked; session artifacts as Markdown or text (`shared/src/documents.ts:116-167`,
  `viewer-context.tsx` DocumentBody, `text-viewer.tsx`).
- Opens any ref of 05 §7 at its locator, a workbench path, or a downloaded file.

## 6. Languages

- i18next with JSON catalogs `renderer/locales/{en,ro,de}.json`; `en` is the source and the fallback.
- `npm run check:i18n` (`05_Software/scripts/check-i18n.mjs`) fails on used keys missing from `en`,
  unused `en` keys, keys missing from a translation, keys present only in a translation, and
  unregistered dynamic keys.
- Setting: System (default, from the OS locale reported by `app.info`), English, Română, Deutsch; any
  other locale falls back to English (`renderer/lib/language.ts`).
- Core errors arrive as `messageKey` and `params` (01 §3) and are translated by `ErrorMessage`.
- The UI language does not constrain the agent; it answers in the user's language.

## 7. Accessibility

- Every control is reachable by keyboard, with a visible focus ring and a logical tab order: a
  skip-to-content button, arrow-key tab lists (right panel, settings sections, window menus), keyboard
  resizers, and dialogs that return focus to their opener.
- Text contrast meets WCAG 2.1 AA in both themes; the mock-mode e2e checks contrast and the absence
  of horizontal overflow at 1280, 1279 and 1024 × 640 per theme and text size
  (`05_Software/tests/e2e/mock.spec.ts:89-171`).
- Icons carry accessible names; no state is conveyed by colour alone.
- `prefers-reduced-motion` is honoured (`renderer/styles.css:708-716`).
- Shortcuts are customisable in Settings › Keyboard shortcuts: up to four combinations per command,
  conflicts and reserved native combinations (copy, paste, undo, reload, quit and similar) are
  rejected, Restore default per command or for all (`shared/src/keyboard-shortcuts.ts`,
  `renderer/components/keyboard-shortcuts.tsx`). Defaults (stored as `Mod`, shown as Ctrl):

| Command | Default |
|---|---|
| New session | Ctrl+N, Ctrl+Shift+O |
| New workbench | none |
| Open workbench | Ctrl+O |
| Open settings | Ctrl+, |
| Keyboard shortcuts page | Ctrl+/ |
| Toggle sidebar | Ctrl+B, Ctrl+Shift+S |
| Toggle right panel | Ctrl+Shift+B |
| Find in conversation | Ctrl+F |
| Focus message input | none |
| Focus model selector | Ctrl+Shift+M |

Fixed keys: Esc asks to stop the running turn; F10 focuses the window menus; `A`/`D` on a focused
approval card; Alt+Shift+Up/Down reorders sidebar rows; Enter and Shift+Enter in the composer.

## 8. Mock mode

`VITE_API=mock npm run dev:renderer` serves only the renderer through Vite
(`05_Software/scripts/dev-renderer.mjs`) against the in-memory `mockApi` with fixture sessions and
documents instead of the IPC bridge (`renderer/api/index.ts:5-6`, `renderer/mocks/`) — the pattern of
`09_Others/benchpilot-reference/apps/web/src/mocks/`. Normal builds drop the mock branch. Component
tests and the e2e specs that build the renderer with `VITE_API=mock` use it.

## 9. Reserved: voice (post-1.0)

Not implemented as of 2026-11-01: no `SpeechToText` port and no audio capture exist.

- A hold-to-talk button in the composer; local speech-to-text after release (batch, not streaming),
  the pattern pi's voice extensions use.
- Seam: a `SpeechToText` port in core, `transcribe(pcm16kMono): Promise<string>`. Candidate: a Whisper
  ONNX model on the transformers.js and onnxruntime already shipped for embeddings, so voice adds a
  model, not a runtime.
- Audio capture in the renderer through `getUserMedia`; the permission handler (01 §7) then allows
  `media` for the app's own origin only.
- Local text-to-speech (Piper, Kokoro or Kitten class models) is a separate decision.

## Implemented session workspace (WP14)

The session view keeps the last session per workbench in renderer localStorage
(`vera.session.<workbenchId>`). It loads `session.get` before subscribing from that sequence number,
applies the shared reducer and the final authoritative text, and cancels obsolete snapshots and
subscriptions (`renderer/hooks/use-session-events.ts`). The new-workbench draft stays mounted across
navigation. Native acceptance covers restart, reload and a real worker abort and recovery. Component
details are in §3; the Context tab now lists enabled skills, and transcript links open after
confirmation rather than rendering as inert text.
