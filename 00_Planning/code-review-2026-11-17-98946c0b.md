## 1. Verdict

VERA is in good shape where it matters most. The security-critical mechanics are carefully built:
path confinement, hash-bound single-use approvals, Electron isolation, the IPC gate, catalog
signature checking, SSRF defence in downloads and secret scrubbing all held up under review.
**No Critical defect was found, and no secret is committed anywhere in the tree or its history.**

The risk sits in four places:

1. **Gaps between what a rule says and what the code enforces.** Several safety gates exist only as
   prose in a skill, or as an allow-list of dangerous words with a permissive default.
2. **The indexing pipeline's cost model.** Every reconcile re-hashes every file, failed documents
   are retried forever, and one fixed deadline covers a whole document.
3. **Release assurance.** An unsigned build verifies green, no Electron fuses are set, and the
   release-hook check lists only some of the test hooks.
4. **Documentation drift.** The architecture set is frozen at 2026-11-01 while the product moved on;
   `00_Planning/plan/` has become a log of delivered work.

Running the suites on both platforms added three things that reading the code did not show:
17 end-to-end tests broken by the most recent test change (H-07), one unit test that fails only on
Linux (H-08), and shell commands that cannot run at all under PowerShell Constrained Language Mode,
which this workstation enforces (P-17).

## 6. Themes across the areas

1. **Prose is doing a gate's job.** O-02, O-10, O-14 and A-01 share one shape: the document
   or the skill says "never", and the code lets it through. In an agent product the model reads the
   prose and the attacker writes the input. Each such rule needs a check in a script, a manifest
   rule or the host.
2. **Allow-lists with a permissive default.** The command-prefix check (A-03), the plugin rule sets
   and the release-hook markers (T-03) each list known bad items. What nobody listed passes.
3. **Work repeated per event.** K-01, K-02, K-07, K-09, P-10, U-03, U-04 and M-16 repeat full-size
   work on every event or poll. None fails a test; together they decide how VERA feels with a real
   workbench of datasheets.
4. **No recovery from one bad file.** M-04, M-07, K-04, K-09 and A-10 turn one damaged file or one
   transient error into a state that needs a manual fix or a restart.
5. **Checks that pass without checking.** T-01, T-02, Q-01, Q-02 and Q-04 are green when the thing
   they guard is absent.
6. **Documents describe 2026-11-01.** See 5.10.
7. **The newest commits are the least checked.** Both suite regressions (H-07, H-08) come from
   commits of 2026-11-17, and the install on this checkout predates the dependencies added the day
   before (H-01). At this commit the unit suite and the end-to-end suite are red on Linux.

## 7. What is solid

- **Electron isolation.** Context isolation, sandbox, no Node integration; navigation, new windows
  and permissions denied; CSP as header and meta tag. The preload exposes `invoke` and `subscribe`
  only (`main/security.ts`, `main/content-policy.ts`, `preload/index.ts`).
- **The IPC gate.** Sender, frame and URL checks, a closed channel list and schema validation on
  both sides (`main/ipc-router.ts`, `preload/bridge.ts`).
- **The write path.** Approvals are bound to a hash of the exact bytes, single use, re-checked
  before the rename; hard links are refused (`core/tools/changes.ts`, `core/agent/approvals.ts`).
- **Path confinement.** Drive-relative paths, stream syntax, reserved names, links and junctions,
  with an identity re-check after reading (`core/workbench/path-guard.ts`).
- **Download SSRF defence.** The address is resolved once and pinned, private ranges are refused,
  and every redirect is re-validated (`core/web/download-transfer.ts`).
- **Catalog trust.** Ed25519 over the raw bytes before parsing, the channel inside the signed
  bytes, fallback to the bundled index on any failure (`core/plugins/catalog.ts`).
- **Credentials.** Operating-system encryption, explicit consent for the weak Linux backend, atomic
  writes; keys never reach the renderer; scrubbing works on streamed output across chunk borders.
- **Process spawning.** Never through a shell, a minimal allow-listed environment, tree kill.
- **Storage.** Prepared statements throughout, transactions with an ownership check; no SQL or
  full-text injection found.
- **Hostile-input handling.** Netlist, schematic, Office and S-expression parsers refuse what they
  do not recognise and bound what they read.
- **Electrical engines.** Correct formulas, conservative table lookups without interpolation, and
  "unknown" instead of an invented verdict.
- **Tooling.** Node, `uv` and the embedding model are pinned by version and hash; the release
  payload is checked in several layers.
- **Tests.** Compile-time test hooks verified by building both modes; negative security tests
  against real links and junctions; fixture provenance written down.
- **Discipline.** 2,995 passing unit and integration tests on Linux and 136 of 138 end-to-end tests
  once the colour problem (H-07) is set aside; no stray markers or suppressions; one commit identity;
  consistent line endings; a requirement register of 1,631 records with no malformed entry.
