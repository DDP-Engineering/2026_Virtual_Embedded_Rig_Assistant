# Bounded historical context compaction

Status: active. Requirement: REQ-FUNC-e5b6a1c9. Architecture: 03 §2/7/8, 04 §3/7/8.

## Request flow

1. Build the repaired transient transcript view. Reuse a derived summary only when the SHA256 of its covered stable repaired prefix still matches. After a restart, the session restores the latest durable `context.compacted` record at its first model request, never while the session opens (REQ-DATA-d9ca38e5).
2. Count the complete request before M1 reduction with the session's calibrated count (REQ-NFR-4721c12f). The calibrated count is the conservative byte estimate x (reported input / conservative estimate of the latest reported normal request with the same model) x 1.1, capped at the conservative estimate; without a report it is the conservative estimate. A report whose ratio is below 0.12 (about 8 bytes per token, a partial count from a prefix-caching server) is ignored and the earlier ratio stays. The same calibration applies to M1 reduction, to the session gateway's final fit check and to the meter. The trigger is strictly greater than 80% of the current input budget. The budget is context window minus maxOutputTokens minus max(1024,ceil(window*0.05)).
3. Keep system/tools/current user and current tool chain intact. If that current context is irreducible under M1, return the M1 view without a summary request.
4. Choose the cut. History is every message before the current user instruction. A valid cut index is one where every earlier tool call has its result earlier and the message at the index is not a tool result. This includes turns split by delivered queued steering, aborted turns, limit turns and interrupted-repair markers. The recent tail is the shortest suffix of the history whose size, counted like the request, reaches min(20,000 tokens, 20% of the input budget). It is kept only while the unreduced view fits the budget; an over-budget view may summarize into it. The summarized range runs from the covered prefix to the largest valid cut at or before the tail start. With no valid cut, nothing is summarized.
5. Build the summary request from the previous derived summary, the summarized range and explicit instructions, with original system rules and no tools. Each tool result text is cut to its first 2,000 characters plus a truncation marker (REQ-FUNC-bd5e5e8d). Selected historical user image references become one-line path notes. When the request does not fit, the largest valid cut whose request fits is used. Every summary dispatch reserves the same effective output/safety as a normal dispatch.
6. Dispatch at most five summary calls (passes) per normal request: after a completed pass whose view still does not fit or remains above the trigger, the next pass summarizes the previous summary with the next fitting range. A later pass that finds nothing more keeps the earlier completed view. A successful text-only assistant stop must parse as JSON with nonempty string summary and string arrays decisions/outstandingWork. No tool calls execute; summary deltas/messages stay outside transcript events.
7. Attach the exact union of source refs from the full (uncut) selected history and the previous summary. Structured tool-result JSON refs and inline citations are collected before truncation. Carry the selected historical image paths forward as one-line notes.
8. Adopt only a strictly smaller raw request view. Keep the covered prefix length and hash, derived note, exact refs and image paths in the session compactor, and record them, masked like the stored transcript, in one durable `context.compacted` session event. Return a detached M1-budgeted normal request view. Resolve capabilities again immediately before the normal dispatch.
9. Missing fitting history, provider failure, invalid/empty/length/tool summary or non-shrinking output uses M1 fallback. A failed durable record write keeps the in-memory summary. An irreducible normal view emits CONTEXT_LIMIT/context.budget_exceeded and turn.done limit. Cancellation publishes a terminal compaction usage status and stops the normal dispatch. A summary request is never itself compacted, and a failed pass is not retried.
10. After a turn ends with stop end or limit, the session runs the same compaction in the background over the stored (masked) transcript the next turn starts from (REQ-FUNC-99acfc19); below the trigger it makes no model call. A message sent meanwhile is admitted at once, and its first model request waits for the background compaction, then reuses its result. Stop, session delete and workbench close abort it.

## Ownership and presentation

SessionService owns one ContextCompactor per session. The compactor holds the derived summary, the calibration ratio and any background compaction in flight. SessionService clears it on session delete and workbench close. ReferenceRuntime owns a default compactor across sends and replaces it on start unless the session owner supplies one. Summaries never replace durable messages or become citation provenance. The `context.compacted` event is part of the session event log and its JSON export. The transcript projection and the Markdown export ignore it.

Usage fields are optional in the current format. compactionStatus is none/running/completed/unavailable/failed. requestViewTokens equals the current calibrated whole-request count (system, schemas, framing and messages), labeled with the existing estimated flag. A usage report after a normal request carries the optional calibration {modelRef, ratio}. Running reports the summary request; the final preflight reports the normal view. Summary provider usage accumulates with normal provider usage, separately from estimates.

## Verification

Authored replay scenarios cover repeated small-window turns with decisions/refs, all dispatch budgets, current-input/first-turn/smaller-window failures, invalid/failed/length/tool summaries, interrupted repair with stable source timestamps/advancing-clock cache reuse, cancellation terminal usage, cached structured refs, unchanged history and restart transcript. Shared projection and en/ro/de meter scenarios cover optional fields. Runtime execution and all plan Done proof are deferred by explicit user instruction; source review and static checks are independent evidence.
