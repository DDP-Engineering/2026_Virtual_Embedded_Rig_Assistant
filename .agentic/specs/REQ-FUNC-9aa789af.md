# Prepared confined changes

INFERRED: expose immutable prepared changes to the existing PermissionEngine port; WP17 supplies production permission decisions. No schema migration is needed.

write(path,content) returns path/bytes/created; edit(path,oldString,newString,replaceAll=false) returns path/replacements/added/removed. Empty oldString is invalid. Matching is literal and non-overlapping. Counts come from diff hunks, excluding headers. write emits exactly its supplied UTF-8 text; edit preserves input BOM/CRLF. Binary input is refused.

Preparation owns copies of exact output bytes, validated arguments, canonical target/key, expected existence/before hash, after hash, full diff, counts, protected status and identities workbench/session/turn/call where host provides them. The executable closure does not recalculate content. Public metadata is detached/read-only; bytes stay private. Approval receives that metadata before enqueue. A prepared application is one-use, including denial/error. Execution rechecks current scope/canonical identity, expected existence/hash, abort and host ownership/permission mode before pending insert and again immediately before rename. An abort before rename removes the temporary file; an abort after rename leaves applied bytes and their row. No rollback writes.

WorkbenchService owns WriteQueue and exposes it to desktop/CLI SessionService. SessionService has one shared queue for all its contexts and receives the workbench-owned queue in product composition; application config/pinned saves enter the same queue with writable/path checks inside their callback. Lifecycle drains session work and queue before database close.

changes stores prepared hashes/diff. Pending recovery reads guarded paths, never writes files; outside recorded Bypass filesystem changes, inaccessible/escaped/ignored paths become conflict. Missing file hashes as null, permitting removal of uncommitted new-file rows. Applied events persist through SessionHub. Read-only constructors preserve pending rows. Hosts await SessionService.waitReady before exposing recovered snapshots or starting turns; core execution also gates dispatch on readiness. The constructor remains synchronous. Applied SQL and change-event records share a transaction, with subscriber publication after commit; recovery records the missing event for after-hash pending rows.

The production default ApprovalGate implements read-only, Ask, Auto-edit and Bypass decisions with durable exact grants. Injected PermissionEngine can authorize prepared writes for deterministic integration acceptance. Read-only mode filters writes and rejects execution even with an injected engine. All product core code remains independent of Electron; original worker/network/preload contracts remain.

## Explicit Bypass filesystem scope

The user-selected Bypass mode permits enabled ordinary file tools outside the workbench and through ignore/metadata restrictions, with OS rights and existing text/integrity limits. Its prepared request marks filesystem scope and records canonical absolute change paths. Scope signals and current-mode checks revoke queued/in-flight authority on downgrade. Recovery reads those recorded targets only to reconcile hashes and never writes file contents. Other modes retain canonical workbench confinement and metadata denial.
