# Scoped plugin trust

STATED: #69, #54, PLG-13 and user delegation define scope; existing store/readPluginPackage and review UI define hash and risk presentation.

A scoped store combines global installed ids with immediate .vera/plugins ids. A scoped id reserves that name: collisions are visible and neither source loads. No fallback bypasses trust. Invalid/linked ancestors or entries are refused under the existing package policy. A source install.json is not authority and is refused as package input.

Trust selects a verified content-addressed installation snapshot under <userData>/plugins/workbenches/<SHA256(canonical workbench path)>/snapshots/<package SHA256>/installed/<id>/install.json (format 1). The machine-local reserved/<id> entry reuses a validated format-1 install record to select the current reviewed hash; only explicit user trust writes it. Its hash covers every portable package file. It is never written to the workbench or exported. Different paths and data roots have separate trust. Restoring bytes matching the currently selected trusted hash at the same path restores consumption; an older retained hash needs explicit selection by a new user review. One current reviewed hash per id is selected. Old content-addressed bytes remain available to already prepared/running processes; retained bytes alone grant no trust. Changing the selected hash also changes managed pip tool roots. Source/reserved or combined views exceeding 1024 entries fail with INVALID instead of returning a partial list; collision checks do not depend on truncated presentation lists.

load rehashes source and verifies its equality to the machine snapshot; consumption uses the snapshot path, never mutable source code. Runtime revalidates canonical workbench identity, source and snapshot immediately before spawn, after any approval wait. Changed/deleted source, cache tamper and stale review are conflicts or unavailable; list shows untrusted/changed/unavailable. No mode grants trust. Agent tool registry has no scoped trust operation.

Enablement remains plugins.enabled. Program-name ambiguity retains existing refusal; skills retain established workbench/user/plugin precedence. requires remains descriptive metadata as in installed plugins, with no automatic install or enablement. The user must install/review/enable required plugins separately. No hooks/download/install during discovery; existing user-triggered provisioner resolves only trusted snapshots. Scoped runtime environments are partitioned by workbench identity to avoid id reuse of managed tools.

Desktop uses explicit scoped review/trust IPC naming open workbench id and package id, reusing PluginReview. CLI plugin list/review/trust requires --workbench and --data; trust requires --id and --sha256 printed by review. No agent-facing tool exposes trust. Agent write/edit rejects .vera/plugins as user-managed installed files, including Bypass; drafts live outside that folder. Desktop existing full review shows programs, rules, sources and danger notice plus exact hash and scope.

Desktop request-scoped provisioners are owned by ProvisionerHosts: shutdown closes every active host, awaits process exits and asynchronous tree kills, and refuses new admission; the singleton runtime resolver retains its existing lifetime. Core close() retains its synchronous cancellation contract, while drain() awaits children/tree kills for shutdown owners. Native shutdown acceptance uses a real hanging Node probe and requires prompt application close plus a stopped heartbeat.
