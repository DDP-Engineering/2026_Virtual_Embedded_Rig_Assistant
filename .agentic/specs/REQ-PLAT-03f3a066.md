# Desktop distribution contract

`package` fixes release mode regardless of inherited VERA_TEST; `package:test` fixes instrumented mode. Both construct native host x64 targets with publication disabled. Windows: per-user NSIS and ZIP. Linux: AppImage/deb. Names: VERA[-test]-version-os-arch.ext. Test executable/product/appId are distinct. ZIP alone carries vera.portable; installed NSIS uses normal data.

The manifest-pinned BGE under resources/models is delivered as real models extraResources. SQLite/ORT are unpacked, target-specific CPU native libraries. Bundled pdfjs CMaps/standard fonts/WASM remain local; renderer typography uses system-ui and monospace without external font requests. Runtime model downloading stays disabled.

Windows includes five unmodified app-local VC++14.44.35211.0 DLLs selected by actual ORT PE imports, alongside the ORT addon under app.asar.unpacked/node_modules/onnxruntime-node/bin/napi-v6/win32/x64. windows-runtime-manifest.json pins bytes/SHA256 and Microsoft provenance; preparation verifies Microsoft signatures on source files and pins on sources/cache before materialization. VERA_VC_REDIST_DIR can provide the approved source folder; default source is Windows System32. Mismatched versions fail instead of changing approved fingerprints. Linux artifacts exclude this Windows resource. Actual loaded module paths are observed on the current host; clean/offlineWindows remains pending.

Check staged runtime before construction and final ASAR/unpacked payload afterwards. Require nonempty SQLite prebuild, ORT addon/CPU library/companions and manifest files. Every non-license offline CMap/font/WASM resource from the exact-pinned pdfjs-dist package must be present with identical bytes in the stage and final ASAR. Reject secret filenames/material and relative paths longer than160; diagnostics contain category/path only. Prune foreign binaries in owned stage and reject any in final payload.

Release emitted and ASAR app code excludes every test environment hook and replay/probe marker. Test code requires representative probe/replay/dialog markers. Actual release launches are driven independently through ordinary IPC/UI with hostile replay/dialog/audit environment; no test hook supplies release evidence.

Explicit CSC_LINK/WIN_CSC_LINK or configured certificate selector enables Windows signing and forceCodeSigning. When SHA1 and subject selectors are both provided, the signer receives both constraints. Absence permits unsigned. Immutable compiled signature intent supplies localized About; requested signing must succeed and actual executable/installer signatures are inspected before acceptance. Linux signature identity is not applicable.

Schema2 report names each current artifact/target/bytes/SHA256, mode/platform/arch, appASAR hash, source/config hashes, pinned runtime versions and check outcomes/contributors. Persist FAIL report before throwing if NSIS exceeds250000000bytes. Stale output cannot satisfy expected targets. External launch proof names artifactSHA, executable path/SHA, OS/runtime, process/command/return and isolated data; before/after artifact hashes agree.

Clean/offlineWindows and VC++ self-containment require real manual evidence and remain explicitly deferred until final release by standing user authority. Current-host scans/mocks cannot discharge them. Linux clean acceptance is recorded only for an actual clean environment. No credentials are requested to permit unsigned implementation. WP31–33 own full indexing/session/egress/upgrade smoke; WP30 owns target launches.
