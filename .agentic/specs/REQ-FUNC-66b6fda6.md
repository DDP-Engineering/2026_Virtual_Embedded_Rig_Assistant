# Demo delivery and onboarding

Requirements: REQ-FUNC-66b6fda6, REQ-UX-194ecc98.

`workbench.demo.open {}` returns the existing WorkbenchSnapshot under the normal authorized
IPC and SessionsHost lifecycle. Main alone chooses the bundled source and destination.
Development reads fixtures/workbenches/demo-board; packaged builds deliver the same allowlisted
files as resources/demo-board. No .vera, credentials, caches or host profiles enter the bundle.

Main uses the existing OS-released IPC installation guard in userData/demo-workbenches, copies into an owned
temporary directory and renames the complete candidate to VERA-DEMO-01. Existing ordinary
folders with workbench.yaml are reopened without replacing any files. An incomplete or
redirected target is refused. Failed installation removes only its owned temporary directory. The OS releases the guard on crash; interrupted staging stays unreferenced and retry preserves unknown contents.
The ordinary workbench open creates runtime state, validates format, takes locks, indexes
documents and records recents. The fixture retains its stable demo identity.

The file inventory retains workbench.yaml, WORKBENCH.md, three generated PDF files and their
Markdown sources, docs/notes/bringup.md, docs/pinout.csv and logs/boot-0412.log; adds GETTING-STARTED.md
and the three SKILL.md files. PDFs already generated by make-demo-pdfs.mjs remain byte-identical.
Facts remain revision A, regulated 3.3V (3.15..3.45V), PB7 SDA/PB6 SCL, 4.7kohm pull-ups,
16MHz clock, 0x48 sensor/0x00 ID register/0xA1 expected ID, illustrative timing values and
20ms I2C initialization warning followed by ready. The log proves no sensor-ID/LED acceptance.

Welcome offers demo whenever no workbench is active, including fresh userData. Opening is
explicit; an existing user's workbench is never replaced automatically. The demo Welcome
guide explains fictional data, model setup, draft/send and citation inspection. Three buttons
create separate ordinary sessions and seed their composer draft, without automatic sending:
datasheet pins/limits; boot log evidence vs hypotheses; bring-up checklist/remaining measurements.
Guide buttons honor readonly and operation state; errors use the existing localized path.
The guide and prompts are localized en/ro/de; skills and source documents are English.

Future proof: isolated copy/reopen/failure/path scenarios, strict empty demo IPC, draft-only
renderer scenarios and fresh-userData realmodel by-hand acceptance. All runtime execution is
deferred by current human policy; static checks and read-only reviews do not prove acceptance.
