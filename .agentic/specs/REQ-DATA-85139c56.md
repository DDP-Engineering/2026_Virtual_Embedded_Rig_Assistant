# REQ-DATA-85139c56 — Workbench lifecycle contract

Authoritative behavior: planning architecture02 sections1–3/6/8,06 section2,08 section3; ADR0004.

## Data / interfaces
Shared workbench schema retains extension keys on established configuration objects and validates embedding policy strictly: format1; id wb_ +26 Crockford ULID characters; name1–80; description optional; docs defaults include docs/** and exclude[]; skills/tools disabled[]; agent defaults ask/model null. Unknown key paths produce structured warnings. Unknown disabled names warn using supplied catalogs; until catalogs exist all names are unresolved. Agent model resolution uses the provider catalog.
Config patch strictly accepts known mutable fields, deep-merges nested values onto current raw document, retaining nested unknown keys. id/format are immutable. YAML configuration extensions use JSON-compatible values for IPC; non-finite numbers and circular aliases are refused without changing source bytes. YAML parsing caps aliases and reports parse/schema location without returning file content in errors. The only valid format is 1; any other format fails CONFIG_INVALID at path format before preparing runtime.
Snapshot {folder,config,readOnly,warnings}; warnings {code,path?}, codes UNKNOWN_KEY/UNKNOWN_NAME/NETWORK_SHARE_UNSUPPORTED/LOCK_GUARD_BUSY. Pinned {content,oversized} counts UTF8 bytes >16384; UI warns while saving full content.
IPC: app.chooseFolder{} -> {folder:string|null}; workbench.create{folder,name}/open{folder}->snapshot; close{}->{}; recent{remove?:folder,pin?:{folder,value},reveal?:folder}->[{folder,id,name,lastOpened,pinned?,missing}]; config.get{}->{config,warnings}; config.update{patch}->same; pinned.get{}->pinned; pinned.update{content}->pinned; files{query}->string[] max50. Requests/responses strict at boundary; extensions inside configuration are retained. Workbench subscription overload (topic,id,on) routes validated events opened{workbench},closed{},config.changed{config,warnings} only for id. App overload preserved.

## Lifecycle / errors
Absolute existing folder required; canonical real root used. UNC detector supplies network warning. Reserved management paths must be regular files/directories with no symlink redirection. Create checks prospective layout before writes, exclusive config publication, preserves user .vera/WORKBENCH.md and ignore content, adds metadata only under .vera. Every open re-evaluates ownership, retaining a matching owned token and allowing a reader to acquire a released/dead lock on same-folder reopen. Operations serialized per service; config saves re-read disk to preserve externally-added extensions and detect external id changes.
Exclusive lock file holds pid/app/since and unique ownership token. A short exclusive process-owned local IPC guard serializes stale takeover/publication/removal: Windows named pipe and Linux abstract Unix socket keyed by SHA256 of canonical folder (Windows case-normalized). The OS releases it on process exit; no filesystem coordination residue, TCP listener or native dependency is involved. EADDRINUSE contention yields read-only with LOCK_GUARD_BUSY; other errors propagate. Dead lock taken over inside guard; malformed lock is a CONFLICT. Owner writes recheck lock ownership; close removes only matching token. Live foreign lock triggers read-only and no runtime mutations. Failed switch retains previous open workbench; accepted settings writes finish before close; failed recent persistence cleans new owned lock and leaves preceding snapshot.
Files completion walks ordinary entries only, skips links entirely, applies .vera/.git/node_modules (case-insensitive and permanent even negated) and root .vera/.veraignore through ignore package; case-insensitive substring query, sorted traversal and50 matches. Not an agent tool or WP11 path guard.
Settings schemaVersion 1 stores the workbench registry and optional pinned flags. Entries remain until explicitly removed and survive reopen while known metadata refreshes. Missing state derives from ordinary directory existence. Pinning/removal changes application settings; Explorer accepts registered existing folders.

Embedding policy uses the installed BGE model, character chunkSize 200–1400 and requested overlap 0–600 smaller than chunk size. The token ceiling and actual fragment capacity bound effective overlap; text overlap continues across lines, while page/section boundaries remain separate. A persisted configuration fingerprint invalidates derived document data on changes. Session list/search/create and editor updates can carry expected workbench identity, checked inside their lifecycle admission.

Known errors are VeraError codes; YAML_INVALID params line/column/path; CONFIG_INVALID path/line; I/O failure returns INTERNAL and logs only safe operation metadata. Missing files NOT_FOUND, duplicate config CONFLICT, read-only DENIED.
