# Foundation UI contract

## Behavior
Welcome and App Settings use memory routing, preserving the exact authorized renderer URL.
Settings contains Appearance, Language, Providers, Updates, Data & privacy and About navigation.
Appearance/Language and provider/update controls use their existing feature APIs. Data retains
its placeholder. Home provides workbench creation/opening and recents; About contains application
metadata. Session panels display their implemented content through existing APIs.
A compact title/menu row and persistent sidebar/icon rail frame the memory routes. F10 focuses
File/Edit/View/Help; native popup menus preserve host keyboard commands. Ctrl+, opens Settings.

## Preferences and boundary
Use the existing strict app.settings snapshot {settings}, API and Query cache.
Update responses apply preferences immediately after successful persistence; settings.changed
invalidates the snapshot. Pending saves serialize through core and controls indicate saving.
Failures retain the last confirmed snapshot and translate validated messageKey/params; unknown
failures use errors.INTERNAL. Settings are never read-only.
No settings.json shape, UUID, no-op or IPC authorization changes.

Light/Dark token blocks live in styles/themes.css. System listens to prefers-color-scheme.
Main assigns nativeTheme.themeSource after load and after successful settings update.
Root data-theme is light/dark; root font size is 14 * scale px: 12.25,14,15.75,17.5,21.
Component geometry, icons and code use rem; viewport breakpoint alone is 1280px.
Language system resolves the primary subtag of app.info.locale (en/ro/de), otherwise en.
Catalogs contain all visible strings including accessible labels and percentages/native language names.
Structured errors are validated with the shared VeraError schema; a finite translated message dictionary
uses explicit catalog calls, with safe INTERNAL fallback for unknown message keys.

## UI geometry data
Renderer-owned localStorage key vera.ui.layout stores strict version-1 JSON:
{version:1,sidebar: number,right:number,source:number,sidebarCollapsed:boolean,rightCollapsed:boolean}.
Widths are rem units, sidebar range 12..24 (default17), right 14..28 (default22), source
20..90 (default36, the right panel width while its Source tab is selected, capped at 60vw,
TASK-1c2ea187); source is required;
collapse defaults false for sidebar, true for right. No application settings schema extension.
Absent, invalid or other-version state uses defaults, and the next layout change overwrites it.
There is no read-only layout mode. Storage denial leaves functional transient layout. Resizers support pointer drag,
ArrowLeft/Right, Home/End with accessible separator min/max/now metadata.
CSS clamps rendered widths to viewport fractions to retain a usable centre at maximum scale.
Below1280px right panel is a non-modal overlay over the centre, with its close control reachable;
sidebar stays docked, retaining Home/project/Settings icons when collapsed. Expanding through
the project icon focuses the project navigation. Panel tabs expose Context/Docs/Changes/Artifacts/Plan.

## Verification
Actual Electron/browser acceptance uses roles and stable translation-key selectors, real computed
styles, bounds, keyboard navigation and pointer drag. Every scale and theme is checked at1024x640.
Both platforms retain sandbox/CSP/permission/strict IPC and WP-01/02/03 acceptance.
Checker reads TypeScript AST for literal translation references and finite registered key
collections; a missing-key JSON fixture exercises the actual CLI nonzero exit, and other fixtures demonstrate each required rejection. No key pattern silently exempts unused keys.
Visual checks use light/dark reference images and browser screenshots; contrast uses actual colors.
