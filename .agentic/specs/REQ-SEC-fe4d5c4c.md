# Credentials and provider settings

Status: active

## Evidence and scope

STATED: M1 WP08,04 sections1/2/5,01 L7/6 and ADR0011 define this feature. OBSERVED: upstream pi-ai1.1.0 auth/types.d.ts and InMemoryCredentialStore define the structural port: read(id,options?), list(options?), modify(id,async callback,options?), delete(id,options?), optional AbortSignal; undefined callback result is unchanged. ApiKeyCredential has type api_key, optional key/env; OAuthCredential has type oauth, access/refresh/expires and extension fields. Core declares these structural types without a runtime model dependency. OAuth orchestration belongs to its later work package.

## Store and redaction

Main owns credentials.json schema1 with encrypted entries keyed by provider ID. Each credential value is JSON serialized and safeStorage.encryptString encrypted then base64 encoded. A same-file global mutex serializes modify and delete; accepted mutations drain at close. Reads and callback values are detached; callback undefined preserves current; callback rejection propagates unchanged within the main-only port, including cancellation. Abort is checked before queued execution and before commit. Failed save changes neither memory nor target. Missing file means empty. The only valid schemaVersion is 1; any other version or invalid content fails INVALID before decryption and preserves bytes. Unknown keys are invalid.

Secure means isEncryptionAvailable and, on Linux, backend other than basic_text. Weak writes require storageConsent true or false; omission yields a structured consent-required outcome. False keeps the new credential solely in memory and removes any persisted entry for that slot. True uses safeStorage when available, including basic_text; if unavailable it writes an explicitly marked unprotected base64 value. This encoding supplies no encryption and the product warning states that risk. Consent is per explicit save and never inferred from implementation authorization. Metadata reports storage encrypted/unprotected/memory and secureStorage capability. An invalid file remains protected even for weak saves.

Loaded, submitted and callback-produced secret strings register immediately in the logger and a main-owned known-secret set. API key plus string env values, OAuth access/refresh and string extensions are secret. Redaction retains replaced/deleted secrets until process exit so in-flight errors remain safe. scrub(text,secrets) replaces longest known keys first, including JSON-escaped forms; empty strings ignored. Main sanitizes structured errors and event user text/extensions before transport, preserving schema field names, identities and enum discriminants, and returns generic storage errors without raw crypto/file diagnostics. Future model/runtime error persistence consumes the same exported scrub contract. No provider/model traffic occurs here.

## Settings and configuration

Settings schemaVersion 1 providers contains openai{model?}, custom[]{name,slug,baseUrl,model,contextWindow,maxOutputTokens,supportsTools?}. Defaults openai{}, custom[]. Provider settings are strict: unknown keys are invalid. Writable configuration and IPC exclude credential fields.

Names are trimmed, unique ignoring case; derived slug uses normalized ASCII lowercase name with punctuation collapsed to hyphens. Empty/colliding slugs reject. Edit ID retains its original slug so keys remain associated; changing name updates label only. Base URL is absolute HTTP(S), nonempty host, pathname ends /v1 (optional trailing slash), no username/password/query/hash. Model required for custom. Context/output positive safe integers, defaults32768/4096; context minus output minus safety margin max(1024,ceil(context*0.05)) must be positive (03 section2). supportsTools is retained optional capability metadata, with connection testing owned by the LLM gateway contract. Reserved credential-looking extension names are rejected recursively; metadata containing a known secret is rejected; short keys match whole text values, longer keys match embedded occurrences. Protocol field names remain intact.

## IPC and UI

providers.list({}) returns {openai:{id:openai,model?,configured,hint,storage},custom:[{id:custom:slug,...config,configured,hint,storage}],secureStorage}. Only strict known public fields return. Hint null when no credential; length<=7 Unicode characters yields null hint; length>=8 yields first3 + ellipsis + last4 unless it reconstructs a complete current or previously registered secret, which also yields null. No secret read method is exposed over IPC.

providers.save is a strict discriminated request for openai (model optional, empty clears override) or custom (id optional for edit, config). apiKey optional means retain existing; empty string means remove credential. storageConsent optional boolean controls weak writes. Response {status:saved|consent-required}; no values or echo. providers.remove({id}) removes key and custom configuration (OpenAI clears key and retains model). Serialized provider operations coordinate settings and store; settings persistence failure restores the exact prior encoded entry and memory/location snapshot without re-encryption or a new consent decision. invalid requests fail before mutation; cross-file crash atomicity is not claimed.

UI supplies labeled password inputs with autocomplete off, bounded hint, Save/Remove, custom add/edit/remove and optional-key clear. Drafts live only while entering/pending consent; after successful save or cancellation secret input and React draft are cleared. Query mutation caches never contain a secret request; use an imperative request and invalidate metadata queries after success. Weak host first returns consent-required without saving; localized prompt offers explicit unprotected save, memory-only use and cancel. Error text uses localized codes. Controls retain WP04 focus/AA/rem/layout contracts at minimum viewport and five scales. The credential editor owns save/consent; adjacent Test controls use the LLM gateway contract. OAuth has its own seam.

## Verification

Store unit tests use deterministic reversible crypto and real temporary filesystem/logger for ciphertext roundtrip, mutex/no-op/delete, other-version/corrupt/failure, secure/basic_text/unavailable choices, memory restart and redaction. Provider tests exercise list hints/short keys, all CRUD/defaults/budgets/stored-option/transaction failures and strict router boundaries. Native Electron acceptance observes all IPC success/error envelopes and events, page text/attributes/input values, actual Query query/mutation state and reload/restart; only hint text may include permitted key fragments. Existing full native/browser regressions run serially on Windows and Ubuntu with separate platform dependencies and identical source manifests. No real API/model call or real secret is used.
