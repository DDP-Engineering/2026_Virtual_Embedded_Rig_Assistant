# Plugin dependency management

## Contract

`plugins.programs` remains passive cached inspection. A workbench-scoped request loads and verifies the package through its scoped store and reads the singleton runtime resolver’s observations for that identity. A new scope therefore cannot display recorded Ready over a checked failure. Passive probes use the singleton’s process lifetime, which the app drains on quit. `plugins.check {id, workbenchId?}` is an explicit user action returning the same status array from fresh actual probes, without installation. Checks share work for the same identity and serialize with provisioning. Scoped checks publish the complete checked observations, including negative version/range states, atomically to the session runtime resolver before leaving their queue. An intervening runtime invalidation supersedes an older pending check, which refuses CONFLICT rather than replacing newer authority. Completed checked failures survive later unrelated toggles/invalidation in an in-memory per-runtime/plugin/program authority layer, matched against package SHA, installedAt and that program record. Ready observations clear prior failures and use the ordinary disposable resolution cache, so invalidation still rechecks file/discovery state. Actual fresh check or provisioning supersedes the previous checked failure, including successful same-version repair. Archive integrity refusal leaves prior healthy runtime authority intact. A generation of older program queries is cancelled/ignored in the renderer before publishing a newer action result.

`plugins.installArchive {id, program, sha256, workbenchId?}` invokes a native file picker in main and returns the refreshed status array or null on cancel. The `sha256` binds the installed package reviewed by the UI, not the archive. Main checks the active workbench and loaded package identity both before and after the picker. Core verifies the same package and current platform download entry inside the provisioning queue.

Local input is an ordinary file, at most the existing 2 GiB download limit. It is copied through an opened file handle into an owned staging file while hashed. Hash validation occurs even when the extracted hash-addressed cache already exists. The selected archive cannot supply a URL, expected hash, entry path or executable arguments. The manifest alone determines those values. Verified staged bytes follow the existing safe extraction, executable existence, probe and version recording path. Wrong identity throws CONFLICT; invalid/missing/local-link/oversize/hash/archive failures report the corresponding program problem and actionable detail. Integrity, identity and extraction refusals publish no tree or version, and owned staging is removed. A valid hash-addressed blob may be retained when its later version probe fails, as for existing remote provisioning; no version is recorded on that failure.

Version failures retain bounded diagnostic output and the declared external-install hint/link. Only safe HTTP(S) guidance links use the existing external-link approval path. Find-only dependencies show recheck and vendor guidance; they do not offer automatic install. Their ready state is explicit. Managed unavailable version/range states may retry installation; pip/script repair requests uv reinstall. A discovered executable from a combined find/download declaration has external:true and is never replaced automatically unless the manifest already permits a preferred download. Download programs may choose a local verified archive independently of remote publication.

## UI

Global top controls group Catalog, install folder, install ZIP, check all dependencies and refresh list. Catalog controls/content live behind an explicit top toggle, avoiding duplicate catalog rows during normal installed-package management.

Installed rows start compact: accessible expand/collapse, name/version/source and dependency summary. Expansion reveals description and per-program details. Stable actions include Check dependencies and Install dependencies (disabled Installed when ready, unavailable when no automatic installer), with export and uninstall as secondary controls. Error details are expandable, while the error summary remains visible. Pending actions report checking/installing and do not disable unrelated navigation. English, Romanian and German have equivalent presentation. Workbench enablement stays draft-only and defaults to empty. Same-hash reinstalls invalidate retained dependency queries; installedAt also binds query/card identity. Redacted details and hints are capped again after secret replacement so every status remains within its IPC schema.

## Runtime and responsiveness

Windows inherits only PATHEXT in addition to the existing environment allowlist. All other runner restrictions and final execution integrity checks remain unchanged. Managed uv is pinned and verified. A user-triggered failed Python install may retry once after unlinking only the exact runtime-owned minor alias whose target is a real managed patch interpreter in the same Python folder. It never recursively deletes an interpreter or follows an outside alias.

Desktop package listing runs the existing complete PluginStore listing in a dedicated worker; concurrent identical pending listings share work, completed results are not retained as a stale integrity cache, and shutdown terminates pending workers. Load, trust, review and execution checks stay in their existing owners. Version probes retain30s for ordinary executables and allow120s for declared vendor activation launchers, with existing injected timeout overrides. This accommodates observed EIM startup variance while retaining a deadline and a truthful timeout failure. Lightweight session listing uses the current recovered SessionService/database and retains ordering/redaction/workbench/shutdown guards without initializing skills or program prompts. The original intermittent freeze remains unproven; regression tests and native pending-operation checks establish the bounded paths changed here.
