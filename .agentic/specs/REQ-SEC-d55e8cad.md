# Git option classification

The official Git program opts into `optionSyntax: git` in manifest format 1. The projection is used only for classification; approval and run-record labels retain original argv; execution adds the fixed guard described below. Before generic token normalisation, it preserves Git case, option/value roles, attached values, accepted short bundles and `--` boundaries. Long option abbreviations of sensitive options escalate conservatively, including negation forms. Global configuration/location/execution escapes are blocked; only explicitly harmless global switches can precede a command. Builtin command names are case sensitive. An unknown name may be an executable Git alias or external helper, so it is blocked; unrecognised options on known commands default to device-write.

The projected command is matched using the official manifest rows corresponding to git.md section 5. Additional role markers `<list>`, `<write>`, `<discard>`, `<execute>` participate in the same highest-risk selection: blocked > irreversible > device-write > safe. Values and path operands are not reinterpreted as options. No listing can hide a write or destructive role. Push deletion refspecs (`:dst`, `+:dst`) and leading `+` force refspecs escalate; reset --hard, clean/restore/checkout, switch force/discard, stash drop/clear, gc prune and reflog expiry/deletion are irreversible. `--` ends options but does not hide a push refspec.

Safe reading requires a known read-only option shape. Explicit output destinations escalate to write; describe --dirty=<mark> remains read-only but rev-parse --resolve-git-dir reads rather than changes cwd. rev-list bitmap/disk outputs and ls-files --with-tree remain reads; describe --broken is read-only. Explicit helper execution (external diff/textconv/filters, pager open, config override, interactive/edit/exec, signing/helper strategy) is blocked. Cat-file --batch output remains a read with closed stdin; cat-file --filters/--textconv is blocked. Help without a topic and help listing flags are safe; opening manual/browser/info viewers is blocked, including --version/-v followed by --help. The -P alias disables pagination like --no-pager. Interactive pull rebase values are checked after canonicalising long abbreviations and -r optional attached values. Signature pretty placeholders (including conditional modifiers and unknown %G suffixes), peeled ref atoms, ref sort keys and shortlog format groups are explicit helper execution and blocked. This policy does not sandbox Git or remove configured credential helpers, local filter/textconv drivers, merge/signing/transport configuration or implicit lazy fetches. The fixed prefix and required execution guard specifically neutralise fsmonitor, hooks, pager and external diff, as required by git.md section 3.

Verification: tests/integration/git.test.ts loads the actual manifest and covers every original row plus collisions, aliases and parser traps, then real installed-package replay and marker fixtures on each available platform. Git's native options may grow; unreviewed read-command options require approval, and an unsupported option may still fail in Git itself. No Git configuration is executed merely to classify a request.

### Working external-diff suppression

`diff.external=` is deliberately fail-closed: Git treats the empty value as an external executable name, so by itself a nonempty ordinary diff fails with exit 128. The Git execution policy additionally inserts `--no-ext-diff` immediately after `diff`, `log`, `show`, explicit `stash list/show`, or the read/default `reflog show` command. The guard precedes every original option/operand and `--` delimiter. The same shared global-option parser locates commands for risk classification and guard placement; `ProgramTools` constructs the same guarded invocation during prepare and application. Raw agent argument values/order remain intact in classification, approvals, file binding and run-record labels. Effective spawned argv includes the fixed guard. Explicit enabling requests remain blocked before spawn; unknown commands retain the fail-closed prefix.

`stash` subcommands must be genuine immediate subcommands: `stash -- list`, `stash -- show` and `stash -q list` are push/path forms and remain device-write. Read-only stash list/show use their log/diff option roles, so `-p` is a read flag there and remains interactive/blocked on default stash push. A guard is not inserted into stash mutations or reflog exists/list/expire/delete/drop/write. Adding a diff option makes bare `stash show` use Git's patch fallback rather than the no-option stash.showStat/showPatch defaults; request `--stat` or `-p` explicitly to select the shape.

Native acceptance parses tool result summaries and requires Git exitCode 0 and nonempty expected staged/worktree/tag/log/show/stash/reflog patch content before approving commit. Positive controls show both configured global and named external diff commands can run without the fixed policy; accepted tool invocations cannot run their markers. A transport-success flag alone is not successful Git execution. Original exit-128 receipts remain archived as superseded evidence.
