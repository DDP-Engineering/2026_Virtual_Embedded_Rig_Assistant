# Workbench storage contract

STATED: M1 WP07; 02-workbench §9; 07-packaging-updates §6; ADR0005/0013.
OBSERVED: existing WorkbenchService serializes operations and uses process-owned takeover guards.
INFERRED technical representation: module catalogue versions are contiguous starting at1; each SQL string is hashed as UTF8 exactly and stored as migration_0001_sha256. Schema_version is canonical nonnegative decimal. Invalid metadata/catalogue fails INVALID before writes. Changed/missing applied checksum fails INVALID with checksum diagnostic. Newer version fails WORKBENCH_TOO_NEW first.

Compatibility must precede SQLite writable opening and lock changes. An isolated temporary copy of db and existing WAL is queried with the real driver so original DB/WAL/SHM bytes stay untouched (including live-owner reads). Read-only handles retain this snapshot; close removes it. This is a stable snapshot, refreshed on workbench reopen. Absent foreign-owner database yields no handle and creates nothing. Writable opening repeats compatibility under ownership, configures pragmas and executes each SQL plus checksum/version in one immediate transaction. Backup uses SQLite backup API on real WAL state to an exclusive reserved backup path before each migration; an existing backup fails CONFLICT and is preserved. Fresh version0 also has a pre-initial backup. Migration failure rolls back that step; successful earlier steps remain committed; an occupied backup filename requires explicit recovery before retry. Identity metadata workbench_id/created_by is initialized atomically with initial migration, and existing identity must match the folder configuration.

Initial SQL supplies meta, sessions, messages, events, tool_calls, approvals, changes, artifacts, todos, documents, chunks and requested indexes. Session child foreign keys cascade; chunks reference documents. No FTS or embeddings tables.

Repositories expose raw typed storage records with ISO UTC strings, supplied session IDs (ses_ULID), title/model/mode/status/archive and verbatim JSON strings. Sessions list by created_at DESC,id DESC; messages/events use caller-supplied nonnegative safe integer seq, session-scoped composite keys, ascending list (events afterSeq optional). No session engine, sequence assignment, title generation, IPC or artifact-file deletion. Missing get returns undefined, delete returns whether row existed. Duplicate/FK violations remain native SQLite errors.

Open checks config/layout/storage compatibility, acquires lock, prepares new handle, saves recents, releases prior lock and closes prior handle, then publishes state. Failed handle/recent preparation closes new handle and releases only newly acquired token, retaining previous state. Same owned reopen validates existing handle metadata without replacing it; ownership loss closes the prior writable handle before returning read-only. Each writable handle holds an auxiliary read-only source connection activated while owned. Before owned lock removal, a checkpoint runs under its guard while keeping storage usable; if unlink fails the previous handle remains open. After successful lock release or token loss, writer-first/read-only-last close suppresses SQLite checkpoint/sidecar cleanup and preserves source bytes. Standalone normal close uses read-only-first/writer-last order for ordinary SQLite cleanup. Close disposes both storage connections and owned lock. Managed db/WAL/SHM/backups paths reject links/nonregular types consistently with WP06.

Unknowns: no blocking decisions; future runtime APIs belong to their owning packages.
