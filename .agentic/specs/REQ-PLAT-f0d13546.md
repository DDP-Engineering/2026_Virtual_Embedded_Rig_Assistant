# Workbench storage contract

STATED: M1 WP07; 02-workbench §9; ADR0005/0013; AGENTS.md development compatibility policy.
OBSERVED: existing WorkbenchService serializes operations and uses process-owned takeover guards.
INFERRED technical representation: the database has one current format. meta schema_version is "1". Any other value, missing metadata, an invalid embedding_epoch or an incomplete schema fails INVALID before writes, and the file stays untouched. There are no migrations, migration checksums or backups.

Current-schema validation must precede SQLite writable opening and lock changes. An isolated temporary copy of db and existing WAL is queried with the real driver so original DB/WAL/SHM bytes stay untouched (including live-owner reads). Read-only handles retain this snapshot; close removes it. This is a stable snapshot, refreshed on workbench reopen. Absent foreign-owner database yields no handle and creates nothing. Writable opening repeats validation under ownership and configures pragmas. Only an empty database is initialized: the complete schema, schema_version, workbench_id and created_by are written in one immediate transaction. An existing database is never rewritten. Existing identity must match the folder configuration; a mismatch fails CONFLICT. No backup files are created.

The schema SQL supplies meta, sessions, messages, events, tool_calls, approvals, changes, artifacts, todos, documents, chunks, the chunks_fts and chunks_tri keyword indexes, embeddings, document_extractions, their triggers and the requested indexes. Session child foreign keys cascade; chunks reference documents.

Repositories expose raw typed storage records with ISO UTC strings, supplied session IDs (ses_ULID), title/model/mode/status/archive and verbatim JSON strings. Sessions list by created_at DESC,id DESC; messages/events use caller-supplied nonnegative safe integer seq, session-scoped composite keys, ascending list (events afterSeq optional). No session engine, sequence assignment, title generation, IPC or artifact-file deletion. Missing get returns undefined, delete returns whether row existed. Duplicate/FK violations remain native SQLite errors.

Open validates config, layout and storage, acquires lock, prepares new handle, saves recents, releases prior lock and closes prior handle, then publishes state. Failed handle/recent preparation closes new handle and releases only newly acquired token, retaining previous state. Same owned reopen validates existing handle metadata without replacing it; ownership loss closes the prior writable handle before returning read-only. Each writable handle holds an auxiliary read-only source connection activated while owned. Before owned lock removal, a checkpoint runs under its guard while keeping storage usable; if unlink fails the previous handle remains open. After successful lock release or token loss, writer-first/read-only-last close suppresses SQLite checkpoint/sidecar cleanup and preserves source bytes. Standalone normal close uses read-only-first/writer-last order for ordinary SQLite cleanup. Close disposes both storage connections and owned lock. Managed db/WAL/SHM/journal paths reject links/nonregular types consistently with WP06.

Unknowns: no blocking decisions; future runtime APIs belong to their owning packages.
