# Offline hexdump import profile

`wireshark_derive` operation `import_hexdump` accepts a saved workbench `path` and a required `hexdumpProfile`. The profile specifies `parser: "ascii-offset-v1"`, `timestamps: "trace_utc" | "synthetic"`, and `encapsulation`.

- `encapsulation: { kind: "ethernet" }` preserves complete Ethernet frames of at least 14 bytes. `{ kind: "user0" }` stores opaque payloads as LINKTYPE_USER0 with no added frame bytes. `{ kind: "udp_ipv4", sourcePort, destinationPort }` adds Ethernet, IPv4 and UDP headers with documentation addresses 192.0.2.1 and 192.0.2.2, the specified ports (1–65535), and Ethernet zero padding when required.
- ASCII only, with at most 256 bytes per line. LF and CRLF are supported. Space and tab may surround a line or separate tokens. Blank lines are ignored. A data line is a 3–8 digit hexadecimal offset, then 1–32 separate two-digit hexadecimal bytes. Offsets are hexadecimal byte counts. Zero starts a packet and every subsequent offset must equal the bytes already accumulated in that packet. A packet ends at the next zero, the next timestamp or EOF. Offset-only records, comments, shorthand, ASCII columns and tool directives are invalid.
- In `trace_utc` mode every packet must be preceded by exactly one `@YYYY-MM-DDTHH:mm:ss[.fffffffff]Z` line, with an actual UTC date from 1970 through 2099 and up to nine fractional digits. A time can repeat or move backwards as in the source. In `synthetic` mode timestamps in the source are invalid. The first generated timestamp is 2000-01-01T00:00:00Z and subsequent timestamps are one microsecond apart in file order.
- The host accepts at most 4 MiB of source text, 16 KiB of input bytes per packet and 10,000 packets, and captures at most 8 MiB of binary output. Input errors name the line without echoing source content. Unsupported paths or modes, failed or invalid output and cancellation return no complete import.
- Verify the generated PCAPNG interface, record count, frame length, payload and timestamp against the parsed input. Accept only Section Header, Interface Description and Enhanced Packet blocks in the converter's output. Publish the binary and version-1 JSON provenance together through managed capture storage. The provenance records exact source size and SHA-256, explicit profile, converter name/version, timestamp origin, generated header list, and the managed output size and SHA-256.
