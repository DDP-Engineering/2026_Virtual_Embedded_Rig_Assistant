## Design

### Approach
REQ-FUNC-ac637f1a: add current-schema WebAccessSettings default enabled/exa/anonymous (no version bump/migration). A core ConfiguredWebProvider reads preferences per invocation, resolves the key only in API-key mode and gates both methods. Desktop WebAccessService owns policy, metadata, serialized credential/config writes and tests. Main passes its provider to SessionsHost; global-disabled tools are also omitted from model definitions. CLI uses the same gate and explicit EXA_API_KEY for headless API-key mode; desktop safeStorage is not decrypted by CLI.
REQ-SEC-ef8590c6: dedicated web.access.get/save/removeKey/test/cancel IPC, strict schemas and metadata-only reads. Keys use CredentialFile id web:exa, registration/redaction/checkpoint and existing weak-storage consent. Exa adapter accepts a private per-call key snapshot, added only as x-api-key to its fixed guarded HTTPS endpoint. Anonymous ignores stored key; API-key mode with no key fails closed. Public settings patch cannot write webAccess; dedicated save owns authority changes.
### Interfaces and data
Preferences: enabled:boolean, provider:exa, authentication:anonymous|api-key. Web access metadata: preferences,keyConfigured,storage,secureStorage,readOnly. Save takes full preferences and optional apiKey/storageConsent, returns saved|consent-required. Anonymous retains stored key; Remove key deletes it and selects anonymous atomically with rollback.
REQ-FUNC-67f02224: Test takes client UUID, authentication and optional draft key. A fixed benign public search verifies actual tools/call, not only initialize. No key/config write. Results contain UUID, status pass|fail|disabled|key-required|cancelled, selected authentication, checkedAt,durationMs; no remote error text/key echo. Saved disabled blocks tests. Closing the result dialog invokes matching test cancellation; stale results cannot replace another attempt.
REQ-REL-410f64a5: saves serialize, validate/read-only-check, request weak consent before mutation, temporarily gate and revoke current calls before key/config changes. Checkpoint restores credentials on failed settings write. Mode changes/removal/disable invalidate active work; following calls use committed state. Policy close cancels/drains. A failed save retains old settings/key while revoked requests remain cancelled.
### Files and test seams
shared web-access.ts/test,settings,ipc,index; core web/configured-provider.ts/test,exa.ts/test,index; desktop main web-access.ts/test,index,sessions; CLI run; renderer settings,web-access.tsx/test,mocks/locales. Native web-access.spec.ts exercises real main/credential/transport with owned loopback MCP, global disabled current/future calls, key/header selection, restart persistence and localized page/modal. Existing web-search acceptance remains relevant. Manual live anonymous test verifies production Exa, synthetic private key only in scripted transport.
### Risks and open decisions
REQ-UX-ea2e6709: separate Web access tab, explicit Save and Test actions in one row, provider Exa, anonymous/API-key selector, password input never prefilled, stored-key metadata/removal and cost/free-limit text. Stable centered modal with one Close button (no duplicate X), pending/result content, cancellation/focus restoration. Reuse ConsentDialog for weak storage. No account management, OAuth or paid fallback. Preserve baseline8 paths and historical journals; stop dev for native build then restore. No blocking unknowns; real successful private-key account test unavailable without a user key.
### Requirement map
FUNC-ac637f1a -> preferences/policy/exposure; SEC-ef8590c6 -> credential/IPC/header; FUNC-67f02224 -> explicit temporary test; UX-ea2e6709 -> translated UI/dialog; REL-410f64a5 -> transaction/revocation/drain.
