## Frame

Problem: The parent chat shows a Delegated sessions section that takes chat space while the same children also appear as ordinary separate rows in the sidebar, so the parent-child relation is unclear (STATED, #407).
Desired outcome: The workbench session sidebar shows delegated children as indented rows under their parent with an accessible expand/collapse control; selecting a row opens that session's existing chat; the parent chat no longer lists children; the child chat keeps its parent link (STATED, #407 Proposal).
Actors: The Desktop user; the session sidebar (`session-list.tsx`); the parent and child chats; main-process session ordering.
Primary scenario: A parent launches two children; the sidebar shows the parent with an expanded group of two indented child rows with their activity and delegated outcome; the user collapses the group, a child starts awaiting approval, and the collapsed parent shows an attention indicator.
Examples: Selecting a child from workbench activity or a notification while its parent is collapsed expands the parent and marks the child row current. Moving a child down swaps it with the next sibling only.
Counterexamples: A child whose parent is archived, or absent from search results, stays visible as a top-level row (STATED, #407 "matching children and active children remain discoverable"). Independent sessions stay top-level.
In scope: Tree rendering, expand/collapse with persisted collapsed state, reveal of the active child, attention indicator, child outcome on its row, sibling-only Move up/down, removing the children list from the parent chat, help and translations (en/ro/de/fr), requirements, knowledge, CHANGELOG and release notes, component and native E2E tests.
Out of scope: Delegation authority, ownership and lifecycles (STATED); deeper than one delegation level (backend denies recursive delegation, OBSERVED `delegation.test.ts` "denies recursive delegation"); wiring sidebar search, which App does not pass to SessionList today (OBSERVED `App.tsx` SessionList props) - the tree handles filtered lists when given.
Constraints: Reuse `SessionSummary.delegation.parentSessionId` (OBSERVED `session.ts`); branch master (STATED "pe acelasi branch"); UI style rules: no helper texts (memory); pre-release, no compatibility code.
Success signals: Component tests for nesting, orphans, expand/collapse with persistence, reveal, attention and sibling moves; shared ordering tests for sibling swaps; native E2E following children from the sidebar and returning through the parent link.
Evidence: `session-list.tsx` flat render; `delegation-links.tsx` children list and parent link; `ordering.ts` swap with peer predicate; `session-order.ts` move via `moveSession`; E2E `session-delegation.spec.ts` helpers use `[data-session-delegations]` (all OBSERVED).
Assumptions: Design decisions the ticket delegates to implementation (INFERRED, made explicitly): D1 parents start expanded and collapsed parent IDs persist per workbench in localStorage; D2 the active child always expands its parent; D3 a child nests only under a parent shown in the same section (main list, Archived, or search results), otherwise it is top-level; D4 Move up/down swaps with the nearest sibling; D5 a collapsed parent shows the most urgent child attention (question, approval, error, running); D6 each child row shows its latest delegated outcome.
Unknowns: None blocking.
Decision-blocking questions: None; the ticket leaves cross-archive presentation, ordering and persistence to implementation.
Proposed behaviors: D1-D6 above, accepted as design under the ticket's instruction.
