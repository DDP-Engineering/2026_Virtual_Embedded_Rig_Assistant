## Frame

Problem: every live event is its own `setView` and commit (OBSERVED `renderer/hooks/use-session-events.ts:54-71`, reasoning/updates spread-copied per delta); the transcript autoscroll `useLayoutEffect` has no dependency array and reads `scrollHeight` after every commit (OBSERVED `transcript.tsx:56-66`); the navigator's MutationObserver watches `characterData` over the whole subtree, so every streamed character schedules a full anchor measure (OBSERVED `transcript-navigator.tsx:122-153`). The performance harness never streams, so this cost is unmeasured (STATED #252 Problem; OBSERVED `runner.mjs` has only first/warm/cross).
Desired outcome: at most one transcript update per animation frame while streaming; no per-token forced layout; the navigator measures at most ~4 times per second while a turn streams and once when it ends; no renderer gap above 100 ms while a reply streams into a 2,000-message session on this host (STATED #252 Goal).
Actors: the user watching a reply stream in the desktop renderer; the session-event subscription; the developer running `perf:sessions`.
Primary scenario: a 2,000-message session is open; a turn starts and 2,000 `message.delta` events of 20 characters arrive, then `message.done` and `turn.done`; the transcript follows the end, the reply renders completely and the renderer stays responsive.
Examples: 100 `message.delta` events within one frame produce one `setView`; `turn.done` applies the queue at once; unmount cancels the pending frame (STATED #252 Tests). `perf:sessions run --cases large --scenarios stream` reports `rendererGapMs` and time to the final render.
Counterexamples: a user who scrolled up (or jumped to a marker) is not pulled to the end while text streams (existing follow/suspend behaviour, OBSERVED transcript scroll tests).
In scope: (a) `stream` harness scenario with a test-only injector in the existing probe modules (`main/session-performance.ts`, `renderer/api/session-performance.ts`) behind `__VERA_SESSION_PERF__`; report validation per scenario metrics; (b) rAF-batched event queue in `use-session-events.ts` with immediate flush on `turn.done`, `error`, `session.updated` and cancel on unmount/session switch; (c) autoscroll layout effect with explicit content deps and a `scrollHeight` growth check; (d) navigator without `characterData`, measure throttled to ~4 Hz while a turn is active and immediate on turn end; (e) `useDeferredValue` for the streaming Markdown only if the measurement still shows long gaps (STATED coordinator brief 3a-3e).
Out of scope: windowing/virtualization, validation on read (PERF-05), main-process streaming changes, plain-text streaming fallback unless measurement demands it (STATED #249 ordering, coordinator brief).
Constraints: no new dependency; Windows and Linux; behaviour identical apart from timing; ordinary builds must not contain the injector; targeted tests only; 1-2 review rounds; do not commit (STATED coordinator brief).
Success signals: hook test (one setView per frame, immediate flush on turn.done, cancel on unmount) green; transcript scroll and CHAT-NAV-01 navigator tests green; `tests/tooling/session-performance*.test.ts` green; typecheck and biome clean on changed files; `stream` scenario on `small` and `large` before and after, `rendererGapMs` max <= 100 ms on `large` (STATED #252 Tests/Measurement).
Evidence: OBSERVED reads of the files above; `aegis explain` lists REQ-REL-4bea0006 (resume renderer streams) for the hook, REQ-REL-c8ac2ecc (navigator geometry, coalesced per frame) for the navigator, REQ-UX-4bea0002 for the transcript; harness REQ-TEST-df5ff0ba / a14f8f9b / 58d27601 (OBSERVED requirement files).
Assumptions: INFERRED from `hub.ts` that `SessionHub.emit` records durable events and publishes every event to the renderer subscription, so a main-side injector through the real hub keeps the renderer's durable cursor consistent with `session.revision` (a renderer-only injector would make the 2 s reconcile replace the streamed state). INFERRED that the stream target must be a session no other scenario verifies by hash (side `b`), because injected durable events persist.
Unknowns: native Ubuntu timing (no Ubuntu host here; Chromium rAF behaviour is the same, STATED #252 Windows and Linux).
