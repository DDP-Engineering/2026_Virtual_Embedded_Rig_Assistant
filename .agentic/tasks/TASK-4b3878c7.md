## Design

### Approach
REQ-UX-1739d053: WorkbenchNavigation owns the common ancestor of both native action-menu details. Scoped capture handling closes other action details before a new trigger's default click; document pointer handling dismisses outside and Escape restores the open trigger. Use native summary/buttons unchanged; exclude ordinary archived/workbench expansion details. No per-row independent React menu state or delayed toggle races.
REQ-FUNC-9a6da7bb: extend session.create with optional reuseEmpty flag, false for explicit ordinary creation. Core checks eligibility and inserts if needed within one synchronous SQLite transaction. Select newest eligible row using existing rows/messages/events, never title; preserve existing settings. Main keeps current workbench ownership validation, mock implements equivalent semantics. App New session opts in, keeps operationBusy's immediate guard, deduplicates the returned cached row and sends a one-shot composer focus request.
### Interfaces and data
Existing API response unchanged. Optional reuseEmpty is an explicit command, not compatibility logic. Eligible means idle, not archived, no messages.role=user and no message.user/message.queued event. No schema migration. Existing read-only/errors remain authoritative. Workbench ownership remains in main and separate service DBs. Most recent eligible ordering is updated_at then id. No old session deletions. Composer focus waits for loaded state; subsequent unrelated updates do not steal focus and same-ID reuse preserves draft.
### Files and test seams
Menu: workbench-navigation.tsx and session-list.tsx behavior tests in workspace.test.ts and native navigation-actions.spec.ts. Reuse: shared/ipc.ts, main/index.ts, core/sessions/service.ts/service.test.ts, App.tsx, workspace.tsx, mocks/sessions.ts. Existing explicit-creation tests remain intact; native concurrent API and rapid click checks exercise host wiring and persistence.
### Risks and open decisions
Preserve existing eight baseline paths/hunks. Stop the real dev app before native build overwrites desktop/out, restart normal dev afterwards; no live provider calls needed. Native details focus and cross-boundary menu behavior require real Chromium/Electron inspection. No remaining open decisions.
### Requirement map
REQ-UX-1739d053 -> one scoped coordinator, native details preserved, outside/Escape/keyboard proof.
REQ-FUNC-9a6da7bb -> transactional opt-in reuse, UI immediate lock, cache deduplication, one-shot focus and mock parity.
