## Frame

Problem: Settings pages save in three different ways. OBSERVED in `renderer/components/`:
- Appearance and language (`settings.tsx`), Updates (`updates.tsx`), Keyboard shortcuts (`keyboard-shortcuts.tsx`) and Advanced (`advanced-settings-panel.tsx`) save each change at once.
- Command shell (`command-settings.tsx`) and Data (`privacy-settings.tsx`) keep a draft with Cancel and Save at the top right.
- Web access and Providers save from buttons inside their forms.
- "Back to workbenches" (`shell.tsx` `leave-settings`) neither saves nor warns. Only the workbench editor guards unsaved edits (`App.tsx` `leaveEditor`, `window.confirm(projects.discardChanges)`).

The user asked for one policy (STATED: "propune un mod unificat pentru settings aplicatie") and chose option B (STATED: "B: Save/Cancel everywhere"), recorded in `00_Planning/settings-save-policy.md`.

Desired outcome:
- Every editable Settings page in this package has Cancel and Save at the top right, in the same place.
- Changes stay in a page draft until Save. Cancel restores the saved values.
- Leaving a page that has changes asks Discard or Stay, the same prompt as the workbench editor (STATED: "Discard / Stay").
- Appearance previews theme, text size, fonts and language live, and Cancel or Discard restores them.
- The session Advanced dialog applies its values on Save.

Actors: The user in Settings and in the session Advanced dialog.

Primary scenario: The user opens Appearance, picks Dark and 125%, and sees them at once. They press Cancel and the saved theme returns. They pick Dark again and press Save, so it persists. They change the shell on Command shell and click "Back to workbenches", which asks Discard or Stay. Stay keeps the draft.

Examples:
- Switching from Updates (changed mode) to Shortcuts asks first.
- Discard drops the draft and moves on.
- In the session Advanced dialog, typing 300 and closing with Cancel changes nothing; Save records 300.
- Save stays off while a page has no changes or an invalid value.

Counterexamples:
- Actions are not drafts and stay immediate (STATED in the proposal, point 5): Check for updates, Download, Restart to update.
- Reset to defaults fills the draft and Save applies it.
- Providers and Web access are SAVE-02 (STATED decision).

In scope:

- The unsaved-changes guard on Settings page switches, "Back to workbenches" and every other navigation that leaves Settings.
- Cancel/Save in the session Advanced dialog.
- Help text for Settings and Advanced in en/ro/de/fr.

Out of scope:

- A Save/Discard/Stay three-button dialog (STATED: "Discard / Stay").

## Design

**Approach**: Each editable page owns a local draft and renders a shared `SettingsPageHeader`: the title, then Cancel and Save at the top right. Save calls `save(patch)`, which is `mutation.mutateAsync` from `usePreferences`, so a page knows when the write succeeds (it clears the draft) or fails (it keeps the draft and the existing Settings error shows) (REQ-UX-032aab57).

Each page reports `dirty` to `Settings`, which forwards it to `App` as a `settingsDirty` ref. The existing `leaveEditor` guard becomes one `leaveDrafts()` check over the editor ref and the Settings ref, with the same `window.confirm(projects.discardChanges)`. Every navigation that already calls it is covered: Back to workbenches, opening workbenches, sessions, Help and Plugins. A new `selectSection` guard covers Settings page switches by click or keyboard (REQ-UX-6a1c936e, RULING-002).

Pages render conditionally per section, so a discarded draft unmounts with its page. Appearance moves out of its `hidden` section for this reason.

Rejected alternative: one global Settings draft shared by all pages. It would keep edits across page switches, contrary to the guard's discard semantics.

**Interfaces and data**:
- `components/settings-page-header.tsx`: `SettingsPageHeader({ title, dirty, valid, saving, onCancel, onSave })`, with `data-settings-cancel` and `data-settings-save`. Save is the green primary button. Both buttons are disabled when the page is clean; Save is also disabled when invalid or saving.
- `hooks/appearance-preview.ts`: a tiny external store (`setAppearancePreview(partial | undefined)`, `useAppearancePreview()`). `usePreferences` merges the preview over the saved theme, scale, fonts and language before its existing layout effects. `AppearanceSettings` sets the preview from its draft and clears it on Save success, Cancel and unmount, so a discard restores the saved values (REQ-UX-58a693f3, REQ-UX-4a040003, REQ-UX-4a040004).
- Pages:
  - `AppearanceSettings` is extracted from `settings.tsx`. Its draft holds language, theme, textScale, chatFontSize and codeFontSize; Reset to defaults fills the draft.
  - `UpdatesPanel`: mode and channel go into the draft. Check, Download and Restart stay immediate actions.
  - `ShortcutsSettings` wraps `KeyboardShortcuts`, passing the draft bindings and `setDraft` (REQ-UX-098273a3 bindings persist on Save).
  - `CommandSettings` and `PrivacySettings` replace their own header with the shared one and report dirty.
  - `AdvancedSettingsPanel`: the draft holds `showAdvanced` and an Advanced map. Save sends `advancedEditPatch(saved, draft, "app")` and `showAdvanced`; the fields run in draft mode.
- `AdvancedField`: the commit mode is removed, so every scope edits a draft.
- `SessionAdvancedDialog`: a draft map with a Cancel/Save footer. Save sends `session.advanced.set` for each changed key from `advancedEditPatch`, in order, then closes. An error keeps the dialog open. Cancel and Escape close it without changes (REQ-UX-8663749f).
- `Settings` props: `update` becomes `save: (patch) => Promise<void>`, plus `dirtyChanged(boolean)`.

**Files and test seams**:
- `renderer/components/settings.tsx`, `appearance-settings.tsx` (new), `settings-page-header.tsx` (new), `updates.tsx`, `keyboard-shortcuts.tsx` wrapper, `command-settings.tsx`, `privacy-settings.tsx`, `advanced-settings-panel.tsx`, `advanced-field.tsx`, `session/session-advanced.tsx`, `hooks/use-preferences.ts`, `hooks/appearance-preview.ts` (new), `App.tsx`, locales, styles, and help (`settings.md`, `advanced-settings.md`).
- Tests:
  - a new jsdom `settings-save.test.ts` covering the header, draft, Cancel, a failed save and the preview;
  - `advanced-settings.test.ts` updated, with commit-mode tests removed;
  - `workspace.test.ts` for guard and page switch;
  - e2e: `settings-navigation.ts` `changeSetting` presses Save; specs that change language or theme through Settings press Save.

**Risks and open decisions**:
- A large e2e surface: about 31 specs open Settings, and every place that changes a setting needs the header Save.
- Live preview must never persist without Save.
- No open product decisions.
