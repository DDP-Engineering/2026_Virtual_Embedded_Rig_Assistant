## Frame

Problem: VERA has no help content and no way to load it: the document viewer reads workbench files only and the
package ships no help folder (STATED plan `00_Planning/plan/help.md` decisions; OBSERVED `main/document-viewer.ts`
workbench-confined reads, `electron-builder.yml` extraResources without help).
Desired outcome: main reads app help from `<resources>/help/<lang>/*.md` (development: `05_Software/help/`) through two
strict read-only channels: `help.list` (page names with titles for a language) and `help.read` (one page by name and
language, English fallback); no path outside the help folders is reachable; packaging copies `help/` into resources
(STATED plan HELP-02).
Actors: the renderer Help view (HELP-03), the agent help tool (HELP-05, reuses the core library).
Primary scenario: the renderer asks `help.read {page:"permissions", language:"fr"}`; main returns the French page, or
the English one marked `language: "en"` when `fr/permissions.md` does not exist.
Examples: `help.list {language:"de"}` → `[{page:"index", title:"VERA-Hilfe", language:"de"}, …]` in the order the
index page links them; `help.read {page:"../secret"}` is rejected as INVALID by the schema.
Counterexamples: a page missing in every language is NOT_FOUND, never an empty page; a symlink inside the help folder
pointing outside it is not followed.
In scope: shared `help.ts` schemas and the two channels, core `help/library.ts`, main handlers and help root, mock API
handlers, `package.mjs` staging and package check, `electron-builder.yml`.
Out of scope: the Help view and button (HELP-03), plugin help (HELP-04), the pages themselves (HELP-06).
Constraints: on `master` (STATED coordinator); help is read-only (STATED plan "read-only IPC"); core stays
Electron-free (STATED `.agentic/context/project.md` "Core remains independent of Electron").
Success signals: unit tests show fallback, ordering, confinement and NOT_FOUND; the package stage contains
`resources/help/en/index.md`.
Evidence: OBSERVED `main/index.ts` resolves packaged resources with `process.resourcesPath` and development paths
relative to `here`; `ChannelHandlers` requires a handler for every channel; core already uses `node:fs`.
Assumptions: page names are lowercase file stems `[a-z0-9-]` (INFERRED from the plan's file table).
Unknowns: none blocking.

Proposed behaviors: list order follows the links of `index.md`, then the remaining pages by name (decided here as the
simplest stable order; serves the Help view's page list).

## Design

**Approach.** A core `HelpLibrary(root)` reads `<root>/<lang>/<page>.md` with `node:fs`; main constructs it with
`<resources>/help` when packaged, else `05_Software/help`, and the two channel handlers call it. Core placement lets
the agent tool (HELP-05) and the CLI reuse the same reader. Rejected: reusing the document viewer (workbench-bound).
**Interfaces and data.** `helpLanguageSchema` en|ro|de|fr; `helpPageNameSchema` `^[a-z0-9][a-z0-9-]{0,63}$`;
`help.list {language}` → `[{page,title,language}]` (max 256); `help.read {page,language}` →
`{page,title,language,content}` (content ≤ 256 KiB). Title = first `# ` heading, else the page name. Order: pages
linked from `index.md` as `(page.md)` in link order, `index` first, then the rest by name. Errors: NOT_FOUND when
neither file exists (REQ-REL-e038060c); a file whose realpath leaves the root, or over the size cap, counts as absent.
**Files and test seams.** shared `help.ts` (+ `help-ipc.test.ts` schema rejection, REQ-SEC-8e27b5ca); core
`help/library.ts` (+ `library.test.ts` with temp folders: list, fallback, NOT_FOUND, symlink outside);
main `index.ts` handlers; renderer mock `mockApi.ts` (glob of `05_Software/help`); `02_Tools/release/package.mjs`
`stageHelp` (+ `tests/tooling` staging test); `electron-builder.yml` extraResources.
**Risks.** Symlinks: realpath check (REQ-SEC-8e27b5ca). The package step fails when `help/en/index.md` is missing.
**Requirement map.** REQ-FUNC-2e84bc58 list; REQ-FUNC-a2db3ddc read with fallback; REQ-SEC-8e27b5ca schema and
realpath; REQ-REL-e038060c NOT_FOUND; REQ-PLAT-73bc566c staging and help root.
