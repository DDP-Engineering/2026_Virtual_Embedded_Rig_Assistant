## Design

**Approach.** Keep the Full Language prompt and dispatched line exactly as they are and add a second path for
any other language mode (REQ-PLAT-36fa33bf). The PowerShell startup script becomes
`if ($ExecutionContext.SessionState.LanguageMode -eq 'FullLanguage') { <current script> } else { <CLM script> }`.
The CLM script prints the same visible `PS <path>> ` with `Write-Host -NoNewline`, followed by a second private
marker, reads one line with `Read-Host` and runs it with `Invoke-Expression` (all allowed in CLM, probed on this
host). TerminalCommandPrompt recognizes both markers; the constrained one also records that the shell is
constrained. `execute` reads that flag before `consume` and, for a constrained shell, writes
`Invoke-Expression (-join [char[]](<UTF-16 code units, comma separated>))`; otherwise the base64 line as today.
Rejected: one mode-agnostic payload for both modes (changes the Full Language path and its tests for no gain);
detecting the mode by a separate probe before the prompt (an extra round trip and another proof to secure).

**Interfaces and data.** `TerminalCommandPrompt` gains `constrainedMarker` and a read-only `constrained`
boolean, false until the constrained marker is seen. Startup replies, split-marker holding, the 5 s timeout,
`wait`, `consume` and `invalidate` are unchanged; a terminal that shows neither marker stays unverified with
`chatActions.promptNotReady`. The dispatched text is the block's exact UTF-16 code units, so quotes, newlines
and surrogate pairs need no escaping and the line is ASCII only. No IPC, schema or renderer change.

**Files and test seams.** `main/terminal-command-prompt.ts` (startup script, markers, flag);
`main/terminal-command-prompt.test.ts` (both branches in the script, the constrained marker sets the flag and
is stripped, split constrained marker); `main/terminals.ts` (`execute` payload);
`main/terminal-command-dispatch.test.ts` (constrained dispatch decodes to the text, Full Language unchanged);
`tests/e2e/chat-actions.spec.ts` native on this CLM Windows host and Ubuntu (WSL2) as the acceptance proof.

**Risks and open decisions.** Security: the line is still written once, only after the proven pristine prompt and
ownership recheck; it carries only the approved text, decoded by `-join` (no further parsing than the text
itself). UNKNOWN until build: Read-Host's line length limit in a ConPTY for the largest block (16384 characters
become up to about 98k characters of codes); build probes it natively and records the result. Read-Host echoes
the line like `[Console]::ReadLine` does today.

**Requirement map.** REQ-PLAT-36fa33bf -> second marker + flag + CLM branch + code-unit line; tests above.
