## Design

**Approach.** Use one optional application cache in the CLI and desktop composition. At model preparation, SessionService seeds a compactor that has no session sample. Its existing context policy, gateway preflight and compaction then use the same scale. Save accepted normal usage after the session event is stored and finish the save before the turn settles (REQ-NFR-4721c12f, REQ-FUNC-e5b6a1c9).

**Interfaces and data.** ModelCalibrationStore binds a provider/model reference and custom connection address/protocol to a SHA-256 record name under the host application data folder. A strict format-1 JSON record holds only the ratio and version. Existing FileAccess performs atomic writes. Missing, malformed and inaccessible cache records are optional hints, so I/O failure never fails a turn.

**Files and test seams.** Core agent calibration store and SessionService, CLI run composition and desktop SessionsHost. Store tests cover model, endpoint, folder and validation boundaries. The durable SessionService suite exercises new-session dispatch and a CLI integration exercises fresh processes on an over-budget fixture.

**Risks and open decisions.** Files for different models do not share an update. Concurrent writes to one key leave the last atomically committed sample. The cache does not save provider URLs, prompt text or credentials. Existing session events still restore ratios and format-1 storage is unchanged.

**Requirement map.** REQ-NFR-4721c12f owns persisted measurement and sample selection. REQ-FUNC-e5b6a1c9 uses the already seeded count and keeps its existing compaction behavior.
