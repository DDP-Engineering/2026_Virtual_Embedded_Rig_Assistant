## Frame

Problem: VERA balances P/Q per scenario and computes fault levels (PWR-02) but nothing imports measured P/Q/S and
harmonic profiles, separates displacement factor from total power factor, sizes reactive compensation or checks a
capacitor bank against load variation, equipment limits and resonance (OBSERVED: 00_Planning/plan/electrical-power.md
lists PWR-05 planned; no PFC engine in core/src/electrical/).
Desired outcome: plugin `power-quality-pfc` (ecosystem electrical, pack "Electrical power and distribution") plus a pure
engine in core and a write tool `power_quality`, gated on its own plugin (PWR-04 RULING-001), that: imports a declared
measurement file (CSV or JSON rows, time, units and sign/reactive conventions declared); computes per scenario
(network-result scenarios at the board and measured intervals) P, Q1, displacement factor and total power factor;
the compensation need to a stated target; proposes a fixed or automatic bank with step size, step count and control
logic; checks overcompensation, step resolution, capacitor/reactor/contactor/protection conditions from cited catalog
data and product/reactor combinations only from cited tables; assesses parallel resonance from the network fault level
and measured harmonic orders; missing data makes the verdict unknown; stores one result with input snapshots
(STATED: ticket PWR-05, coordinator brief).
Actors: the agent with power-quality-pfc loaded; the engineer who keeps model, catalog and measurement files and
approves result writes (STATED: brief).
Primary scenario: after electrical_network stored a current result, the agent calls `power_quality` naming the board,
the network run, a measurement file, a catalog with capacitor/reactor/contactor/protection items, the target displacement
factor and the resonance margin; VERA prepares result.json (approval like a write) with per-scenario values, the need,
the bank proposal and criteria; a later change of the board's loads makes the result stale.
Examples: Schneider EIG simplified method 500 kW from cos 0.75 to 0.93 -> 0.487 kvar/kW, 244 kvar; EIG resonance
example Ssc ~10 MVA, Q 350 kvar -> h0 ~5.5; EIG capacitor protection examples 50 kvar 400 V -> IN 72 A, long-time
108 A (1.5) / 94 A (1.31); DPF 0.9 with THDi 40 % -> total PF ~0.836 (STATED: EIG pages read 2026-11-15; hand calc);
a plant whose night load Q1 is below the day need -> fixed bank fails overcompensation, automatic steps proposed
(INFERRED: physics).
Counterexamples: a total PF from capacitors alone reaching 1 under distortion; a passing resonance verdict without
fault level or harmonic orders; a detuned capacitor/reactor pair accepted without a cited combination; a regulator
parameter written or a step switched; a capacitor bank treated as a battery/UPS (STATED: ticket).
In scope: measurement file format 1 (shared + core reader, CSV or inline rows); engine + write tool + request schema;
catalog conventions for capacitors, detuned reactors, capacitor contactors and step protection; plugin package, skill,
README, pack; en/ro/de/fr tool texts; fixtures (fictional plant model, fictional labelled measurement day, cited
Schneider items); spec/requirements/knowledge/plan/CONTRIBUTING.
Out of scope: active filter design, EMT model, online regulator parameterisation, switching steps (STATED: ticket);

(STATED: ticket "a kvar approximation is not a full PQ report"); transformer no-load compensation; cable sizing of

## Design

**Approach**: like PWR-02..04, product code next to the model: shared `power-measurements.ts` (format-1 zod schema,
folder `electrical-automation-measurements`, limits); core `electrical/measurements.ts` (pure `checkMeasurements`/
`parseMeasurements(text, csvText?, fileId)` -> samples, and the confined `readMeasurementFile(root, id)` -> {file,
samples, stamp}); pure engine `electrical/power-quality.ts` (`powerQualityRequestSchema`, `analyzePowerQuality(input)`
-> ElectricalResult, exported `compensationNeed`, `resonanceOrder`, `capacitorCurrentRatio`, `totalPowerFactor` for
the reference tests) and write tool `electrical/power-quality-tool.ts` (`power_quality`, class write) that reads the
model, the named network result (current, refused otherwise, same helper pattern as motor-drives-tool), the measurement
file (board must match) and the catalog, runs the engine and prepares ONE result through `prepareResultChange`
(REQ-DATA-4dc5e2c7, REQ-FUNC-7c320847, REQ-REL-0f24c593).
Rejected: a measurement read tool (keeps tool specs small; refusals name the problem); recording measurement samples
as model entities (the model holds design data, measurements are files with a stamp - freshness of the file is a
stated limit like PWR-03's cable table); computing capacitor/reactor pairs from L and C (combinations only from cited
tables, PWR-05-C); hard-coded duty tables (the guide's 15 % and Gh/Ssc rules and 10 x IN are cited rules in code with
their source; product limits come from the catalog); result-format changes (none needed).
Reuse: `selectItems` on a one-item catalog and `findItems` for cited values, `coordinationFor` for `detuned step`
tables, PWR-02 stored `activePower:<s>`/`reactivePower:<s>`/`ik3Max`/`nominalVoltage`, `result-change.ts`,
`renderResultReport` (no own renderer), units.ts (new known properties: `reactivePowerMax`, `overcurrentRatio`,
`capacitanceToleranceMax`, `nonLinearShareMax`, `tuningFactor`, `harmonicVoltageMax`, `thdVoltageMax`,
`harmonicOrder`), `linkProblem` for the source link, gating `electricalPluginTools` (RULING-001 of PWR-04).
**Interfaces and data**: spec REQ-DATA-4dc5e2c7 (request, measurement file, catalog conventions, method, result
names). Fixtures `tests/fixtures/power-quality-pfc/`: `plant-q.json` (fictional: network A transformer 630 kVA Dyn11,
MDB with motor group, VFD group, lighting; two scenarios), `meas-fictional-mdb-day.json` + `.csv` (origin fictional,
96 x 15 min, P/Q/S/PF/THD/harmonic orders), `cat-pfc.json` (BLRCH125A150B48, LVR07125A40T, LC1DFKP7 from se.com UK
pages read 2026-11-15 + the Bussmann C10G fuses copied from the PWR-03 fixture; no detuned-step table because no
public pairing table was found - tests add a fictional in-memory table). Errors: invalid request/file/catalog or a
refused result -> thrown, nothing prepared; data gaps -> unknown criteria.
**Files and test seams**: shared power-measurements.ts, index.ts, tools.ts, events.ts, session-state.ts; core
electrical/measurements.ts (+ test), power-quality.ts (+ test: EIG references, hand calcs, conventions, fixed/automatic,
equipment, resonance, configuration rule, fixture pipeline network -> pfc), power-quality-tool.ts (+ test: prepared
result, stale/foreign/board refusals, model unchanged, gating), result-change.ts, tools.ts, units.ts, index.ts,
tools/registry.ts (+ test), tools/changes.ts; sessions/electrical-model.test.ts; desktop workbench-tools.tsx + 4
locales; plugins/power-quality-pfc/ (plugin.yaml, README, skill power-factor-correction), catalog.yaml, packs.yaml;
CONTRIBUTING, knowledge, plan page, fixtures README.
**Risks and open decisions**: real measurement set needs coordinator approval (HIPE asked); no cited capacitor/reactor
pairing table -> detuned candidates stay unknown with real data; Ssc only at maximum (cmax) since PWR-02 gives no
minimum fault level at boards (stated limit); harmonics assumed unchanged after compensation (stated); tool-schema size
against the 32k replay window; WSL is not native Ubuntu.
