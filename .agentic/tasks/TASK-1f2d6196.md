## Frame

Problem: ORT_DISABLE_TELEMETRY is set only by the core EmbeddingHost constructor (OBSERVED `core/src/knowledge/embedding.ts:118`), which the desktop creates lazily inside the Indexer utility process since EMB-02 (OBSERVED `main/index.ts` indexer.embeddings, commit b8e8d0d4). The Whisper dictation host (OBSERVED `main/dictation/worker-host.ts`, `whisper.ts`) loads ONNX Runtime through Transformers.js without it, so dictation before any embedding service can initialize ORT with its native telemetry; the release smoke fails its startup check "Native telemetry must be disabled by the app before workers start" (OBSERVED dry run 2026-11-21 on this branch's ZIP).
Desired outcome: The desktop main process disables ONNX Runtime native telemetry in its real environment at startup, before any inference host or worker exists, as REQ-SEC-b4170ade requires (STATED user "Fix it here"; requirement text).
Actors: desktop user (dictation, indexing); release smoke.
Primary scenario: VERA starts -> ORT_DISABLE_TELEMETRY=1 before the first window, so the smoke's identity check passes and a later Whisper or embedding worker inherits it.
Examples: start VERA, dictate without opening a workbench: the Whisper worker sees ORT_DISABLE_TELEMETRY=1.
Counterexamples: none supplied.
In scope: desktop main startup module and its test; requirement paths.
Out of scope: the CLI (its only ORT consumer is EmbeddingHost, which still sets the variable itself) (OBSERVED grep: no other ORT_DISABLE_TELEMETRY site).
Constraints: ESM evaluation order: a side-effect import listed first is evaluated before later imports.
Success signals: unit test that the module sets the variable and that it is index.ts's first import; release smoke dry run passes the telemetry check.
Evidence: files above; smoke report of the dry run.
Assumptions: none.
Unknowns: none.
Decision-blocking questions: none.
Proposed behaviors: (accepted, user go-ahead) a side-effect module `main/inference-telemetry.ts` imported first by `main/index.ts`.
