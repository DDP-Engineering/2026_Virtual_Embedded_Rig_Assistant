## Design

### Approach
STATED four choices/defaults and explicit draft semantics use existing Settings and WorkbenchConfigForm seams. Add PrivacySettings (app draft), WorkbenchPrivacy (existing config draft), and shared PrivacyControls/agent-warning presentation. Reuse shared maskingDefaults for labels; core resolver remains authoritative.
### Interfaces and data
OBSERVED strict SettingsPatch and WorkbenchPatch already merge privacy per area at format1. App keeps only changed area booleans and sends that partial patch; successful confirmed snapshots clear acknowledged edits, failure preserves them (REQ-UX-a57996c8, REQ-REL-53b7d5ce). Workbench draft updates spread existing privacy and mask objects; editor Save adds privacy without altering vendor/config/prefix/folder ownership (REQ-UX-65f41205).
Use the existing app.settings query cache shared with usePreferences, consuming fresh confirmed updates and cancellation-aware reads so a stale initial read cannot overwrite newer app defaults (REQ-REL-53b7d5ce). Disable editing before a trustworthy settings snapshot is available; show localized error/retry. App snapshot comes from the confirmed Settings owner.
Effective agent on->off opens a portaled native dialog; Cancel/Escape restores focus; Confirm updates only local draft. No other area prompts. Owner identity keys reset dialogs/drafts; live app labels never mutate workbench draft (REQ-SEC-01bc890a).
### Files and test seams
Renderer components/settings.tsx, workbench-config-form.tsx, workbench-editor.tsx; new privacy components and focused tests. Shared query hook/confirmed update handling only as required for stale fetch proof. Four catalogs/help pages, release notes/CHANGELOG, inventories and current AEGIS knowledge. Focused native privacy-settings.spec.ts covers both pages, inheritance, two owners, confirmation and persistence; component tests cover async races/failure/readonly/new defaults.
### Risks and open decisions
STATED no core imports in renderer, no competing backend resolver, no migration/version changes. Backend persistence/consumer proof is reused; immediate schema/service focused regressions remain available. Full suites/native Ubuntu/clean install/exact-source delivery are deferred by user; no open product decisions.
