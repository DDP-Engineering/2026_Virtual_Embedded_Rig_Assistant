## Frame

Problem: STATED (Gitea #364, user): bookmarks in a chat can only be reached through the conversation rail,
message buttons and next/previous shortcuts; there is no list to find, filter and manage them. OBSERVED:
`shared/src/workbench.ts` `rightPanelTabIds` has seven tabs, all on by default; bookmark state is the snapshot's
`bookmarkedMessageIds` plus an optimistic overlay owned by `Transcript` (`use-bookmarks.ts`); the only write is
`session.bookmark` for one message (`core/src/sessions/service.ts` `bookmark`, DENIED when archived, writable check).
Desired outcome: An opt-in Bookmarks tab lists, filters, jumps to and removes the current session's bookmarks,
kept in sync with the message controls and rail through one shared bookmark state.
Actors: The engineer in a workbench chat; the workbench editor (Interface > Right-panel tabs); the session engine.
Primary scenario: The engineer enables Bookmarks for a workbench, opens a long chat, filters the tab by a word,
presses Enter on a row; Chat is shown, the older message is mounted, scrolled to and highlighted, and the tab stays
open. They select two rows and remove them; both bookmarks disappear from the tab, rail and messages.
Examples: STATED (#364): unchecked by default and after Restore defaults; "show matches out of the total when
filtered"; "Bulk removal is atomic; on failure show an error and leave bookmarks unchanged"; archived sessions and
read-only workbenches browse, filter and jump but cannot remove. RULING-001: the filter matches message and reply
excerpt. RULING-002: the tab sits after Plan.
Counterexamples: Hiding the tab keeps bookmarks, rail, shortcuts and other preferences. Removing a bookmark never
deletes a message. Clear all removes every bookmark of the session even while a filter hides some.
In scope: Shared tab id and opt-in default; atomic bulk removal in core, IPC and main with the archived/read-only
guard; a shared renderer bookmark state for transcript and tab; the tab UI (list, filter, count, previews,
selection, remove, confirmed clear all, keyboard, ARIA); jump through the existing transcript navigation; mock API;
en/ro/de/fr text and help.
Out of scope: STATED (#364): cross-session browsing, labels and notes, bookmarking agent replies, document
indexing or RAG, export and agent visibility changes, a second store.
Constraints: On `master` (STATED: user asked for the same branch). Pre-release: no migration; workbench format
stays 1. Workbench `right_panel_tabs` is a strict enum array. User UI rules: no helper texts, pager on lists
(INFERRED: the tab lists one session's bookmarks in a scrolling list, see Unknowns).
Success signals: Focused tests cover opt-in default and restore, persistence, filter and count, session isolation,
keyboard activation and long-session jump, rail sync, atomic removal and failure, clear-all scope, and the
read-only/archived restriction; typecheck, lint, check:i18n and check:help pass.
Evidence: OBSERVED files named above; `renderer/components/right-panel-tabs.ts`, `workbench-interface.tsx`,
`shell.tsx`, `App.tsx` (SessionViewProvider shares one session view with the side tabs), `use-bookmark-navigation.ts`
(mounts unmounted history then retries a jump), `help/*/chat-and-sessions.md` (Bookmarks section).
Assumptions: none.
Unknowns: Whether the memory rule "pager on lists" applies to a per-session bookmark list; the issue asks for an
independently scrollable list, so the list scrolls (STATED by the issue wins).
Decision-blocking questions: none left; filter scope and tab position answered (RULING-001, RULING-002).
Proposed behaviors (not accepted): none.

## Design

**Approach.** Lift the existing optimistic bookmark overlay (`use-bookmarks.ts`) into a session-scoped
context, `SessionBookmarksProvider`, mounted in App inside `SessionViewProvider` around Shell, so Transcript (buttons,
rail) and the new `BookmarksTab` read and write one state (REQ-REL-2b8d452f). The provider also carries a jump request
`{ id, seq }`; the tab selects Chat through `useDocumentTabs().select(CHAT)` and posts the request; Transcript hands it
to `useBookmarkNavigation`, which already mounts unmounted history and retries (REQ-UX-53130782). Bulk removal is one
new IPC call executed by core in one SQLite transaction that records the existing `message.bookmarked` event per id,
so export, agent visibility and the reducer stay unchanged (REQ-FUNC-10d85a47, REQ-FUNC-d65a3585). Rejected: a new
"bookmarks cleared" event (changes export and replay) and a renderer loop of `session.bookmark` calls (not atomic).

**Interfaces and data.**
- shared `workbench.ts`: `rightPanelTabIds` gains `bookmarks` after `plan` (RULING-002); new `defaultRightPanelTabs`
  (all but bookmarks) is the schema default and the Restore defaults value (REQ-UX-effec625). Format stays 1.
- shared `ipc.ts`: `session.bookmarks.remove` input `{ sessionId, messageIds: string[1..10000] }` or
  `{ sessionId, all: true }`, output `{}`.
- core `SessionService.removeBookmarks(id, target)`: writable, archived -> DENIED, deleting -> BUSY; inside one
  transaction resolve ids (`all` = current `bookmarkedMessageIds`), refuse INVALID when any id is not a user or queued
  message of the session, record `message.bookmarked false` for each; publish after commit (REQ-SEC-8c0cc59a).
- main `index.ts` routes the channel; renderer `mocks/sessions.ts` mirrors it for browser e2e.
- renderer `useBookmarks` gains `remove(ids | "all")`: one optimistic overlay entry per id, one request, failure
  restores the previous values and sets the shared error (REQ-UX-dc45c39a). `useSessionBookmarks` returns the provider
  value for its session, else an own instance (isolated tests), like `useSessionView`.
- `BookmarksTab({ sessionId, readOnly, archived })`, keyed by session: rows from snapshot items in conversation order,
  `previewText` for message and reply excerpt (same reply binding as the rail), case-insensitive filter over both
  (RULING-001), count status, empty and no-match messages, roving ArrowUp/Down/Home/End over row buttons, checkboxes,
  Select all filtered, Remove selected, per-row Remove, Clear all with a modal `<dialog>` like session delete. With
  readOnly or archived only browsing, filtering and jumping render (REQ-UX-8a37ed29, REQ-SEC-8c0cc59a).
- Shell gets a `bookmarks` slot and `rightPanelTabs` an icon and `panel.bookmarks` label; en/ro/de/fr text; help
  `chat-and-sessions.md` Bookmarks section.

**Files and test seams.** shared workbench.ts + workbench.test.ts; shared ipc.ts; core sessions/service.ts +
sessions/bookmarks.test.ts; main index.ts; renderer use-bookmarks.ts, new session-bookmarks.tsx (provider),
use-bookmark-navigation.ts, transcript.tsx, new bookmarks-tab.tsx + bookmarks-tab.test.ts (jsdom), right-panel-tabs.ts,
shell.tsx, workbench-interface.tsx, App.tsx, mocks/sessions.ts, locales, styles.css; tests/e2e/bookmarks-tab.spec.ts.

**Risks and open decisions.** Moving the overlay out of Transcript must keep the existing rail and shortcut tests
green; Transcript keeps working without the provider. Existing tests that treat `rightPanelTabIds` as the default
list change to `defaultRightPanelTabs`.

**Requirement map.** effec625: shared ids/default, editor, Shell slot. 8a37ed29 and 53130782: BookmarksTab, jump
request. 10d85a47, d65a3585, 8c0cc59a: removeBookmarks, IPC, tab controls. dc45c39a and 2b8d452f: shared overlay.
