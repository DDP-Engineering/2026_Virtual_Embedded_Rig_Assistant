## Design

**Approach.** The manifest carries the declarations (`settings`, REQ-DATA-af8807e1); the renderer already has every installed manifest from `plugins.list` (PLG-03), so it sends the declared settings of the listed plugins to one batched channel `plugins.configuration`, and main answers each parameter's state from the existing services (REQ-FUNC-cbdb46ac). Rejected: main re-listing or loading plugins for the channel - that repeats the hashing `plugins.list` already did. The page reuses `PluginCredentialsPanel` and `PartsAccessPanel` inside a new Configuration section (REQ-UX-efe126c0, -664afc86, -c553435b, -4b90fed2); their channels and main services stay as they are (STATED: move, don't rewrite). The library's readiness gains the configuration needs (REQ-UX-05e0ed17).

**Interfaces and data.**
- Shared `plugin-settings.ts`: `pluginParametersSchema` = record name (`^[a-z0-9](?:[a-z0-9-]{0,62}[a-z0-9])?$`) -> discriminated union on `kind`: `secret {description, scope: mqtt|wokwi|parts}`, `workbench-file {description, path, format?: lab-resources|json, optional?: boolean}`, `value {description, value}`; max 32; default `{}`. `path`: POSIX relative, segments `[A-Za-z0-9._-]+` or `*`, no `.`/`..`, at most 8 segments. Manifest `settings: pluginParametersSchema.optional()` (format 1, no bump; absent means no parameters, so typed manifest fixtures stay unchanged; renamed from pluginSettingsSchema, which the app settings already export).
- State: `{name, kind, state: stored|missing|present|invalid|unchecked|value, refs?: string[] (references or supplier ids, never secrets), paths?: string[] (matches), problem?: string}`. `configurationNeeds(settings, states): string[]` - names of missing secrets, missing non-optional files and invalid files.
- IPC `plugins.configuration` request `{workbenchId?, plugins: {key, settings}[] (max 128)}` -> `{plugins: {key, settings: state[]}[]}`; a workbench id that is not the open one -> CONFLICT (same as plugins.list).
- Core `plugins/configuration.ts` `settingStates(settings, {workbench?, secrets(scope)})`: secret -> stored with refs / missing; workbench-file without workbench -> unchecked; `*` expands one folder level (dot folders skipped, 64 matches); each match through PathGuard, regular file <= 256 KiB; format lab-resources -> `parseRegistry` (extracted from `readRegistry`, same messages), json -> UTF-8 JSON parse; none matched -> missing; any invalid -> invalid with the first problem; value -> value.
- Main: secrets(mqtt|wokwi) = `PluginCredentialService.list()` refs; secrets(parts) = supplier ids whose key is configured from `PartsAccessService.get()`. The renderer re-asks on the app event `settings.changed` (already emitted by both services) and on Check again.

**Files and test seams.** shared `plugin-settings.ts` (+test), `plugins.ts`, `ipc.ts`; core `plugins/configuration.ts` (+test), `resource-registry.ts`, `plugins/index.ts` export; core store test for official manifests (REQ-DATA-7c79b1b5) and an invalid entry; main `index.ts`, `ipc-router.test.ts`, preload `bridge.test.ts`; renderer `plugin-configuration.tsx` (new), `plugins.tsx`, `plugin-library.ts`, `plugin-credentials.tsx` (Replace), `parts-access.tsx`, `settings.tsx`, `mocks/mockApi.ts`, locales; tests `plugins.test.ts`, `plugin-library.test.ts`, `plugin-credentials.test.ts`, `parts-access.test.ts`, `session/workspace.test.ts`; 11 official manifests; texts that point to Settings > Parts search / MQTT credentials / Wokwi tokens (core `parts/configured.ts`, `parts/http.ts`, plugin READMEs and skills).

**Risks and open decisions.** Secrets: the state carries references and supplier ids only - the same data the list channels return today (REQ-FUNC-cbdb46ac, PLG-05-C). The renderer chooses which declarations are checked; paths stay inside the workbench through PathGuard, the same reach `docs.read` already has. No compatibility: the three Settings pages are deleted (STATED).

**Requirement map.** REQ-DATA-af8807e1 schema; REQ-FUNC-cbdb46ac core + channel; REQ-UX-efe126c0 Configuration section + Settings tabs; REQ-UX-05e0ed17 programReadiness + card text; REQ-DATA-7c79b1b5 manifests; REQ-UX-664afc86/-c553435b/-4b90fed2 moved forms + Replace; REQ-SEC-2fda27e4, REQ-SEC-1ffb429b, REQ-TEST-d3aeb7d8 no design impact (wording).
