## Design

**Approach.** Two programs (REQ-FUNC-1ae67789): `kicad-cli` is a manifest find that gives VERA's status, version range and install hint and whose rules only allow version/help (REQ-SEC-17f1e8d5); `kicad-tool` is a standard-library PEP 723 script like `elec-calc`, so it runs offline on uv's managed CPython. A script program receives no other program's path (OBSERVED: `plugins.ts` env placeholders, `runner.ts` toolPaths), so `discovery.py` repeats the manifest's search order (REQ-FUNC-9383047c); a core placeholder for sibling program paths was rejected because it changes manifest format 1 and approval binding for one plugin. Every operation is validate-then-run-then-write: (1) parse options and judge paths from their text (REQ-SEC-85467169); (2) read the project's file set once, hash it, parse it, refuse defects (REQ-REL-c4b14f26, REQ-REL-426ec335) and check the run folder does not exist yet; (3) locate and version-check KiCad (REQ-REL-24dba971); (4) write the bytes read into a temporary work folder `<tmp>/project/` and let kicad-cli write only into `<tmp>/out/` (OBSERVED: kicad-cli rewrites `.kicad_prl`; REQ-REL-09628127); (5) parse KiCad's outputs; (6) re-hash the sources (REQ-REL-da746e30); (7) only then create the run folder exclusively, re-check it is still inside the working directory and outside `.vera`, copy KiCad's outputs and write `result.json`/`report.md` with exclusive creates; (8) print the fitted document (REQ-REL-1ab91569) and remove the temp folder in `finally`. So kicad-cli never writes into the workbench, a refusal or failure before (7) leaves nothing, and a failure in (7) removes the run folder (REQ-REL-05743834). Connectivity always comes from KiCad's own netlist (`sch export netlist --format kicadsexpr`), never from schematic geometry; native files are parsed only for the hierarchy, versions, flags and board facts (REQ-FUNC-57feb0b5, REQ-FUNC-fa7fc405).

**Shared path rules.** As the first consumer of ELEC-01's contracts (planning page: "a verified copy"), the path rules move from `elec_support/report.py` into a standalone `workspace.py` without package imports (text judgement, confinement, `.vera`, run ids, device names, UTF-16 lengths, results directory, run-folder re-check), raising `PathRefused(message)`; `elec_support/report.py` keeps thin wrappers (`_confined`, `read_input`, `results_directory`, `_allowed_output`) that turn it into its `path` problem with identical messages, and `kicad_support/workspace.py` is a byte-identical copy checked by a test (REQ-SEC-85467169). Only `electronics-calc` code moves; its 57 tests must stay green.

**Interfaces and data.** Spec REQ-DATA-c32834e3 fixes the command line, file roles, parser limits, document fields, operations, export table and exit codes. Exit 2 problems (`usage`, `path`, `project`, `kicad`, `layer`) are raised before step (4); exit 3 (`run`, `source`, `output`) after it. kicad-cli runs through `subprocess.run` with closed stdin, captured output and a 1500 s timeout per call, in the helper's process group (VERA's tree kill covers it); a nonzero exit, a timeout or a missing expected output is `run` with the last 2000 characters (REQ-REL-05743834); the helper never passes `--exit-code-violations`, so violations exit 0 (REQ-FUNC-25b51df0, REQ-FUNC-3c1c35b7). Command lines come only from `kicad.py`'s builders over fixed option lists (REQ-SEC-40a76c91); layers are checked against the board's layer table before any call (REQ-REL-3fe4718a, OBSERVED: kicad-cli plots partially on an unknown layer). Instance identity is `<sheet tstamps><symbol tstamp>` from the netlist (REQ-DATA-5ff34212); BOM groups as in spec 6.3 (REQ-DATA-1adc8a2b).

**Files and test seams.** New `05_Software/plugins/kicad/`: `plugin.yaml`, `README.md`, `skills/schematic-review/SKILL.md`, `skills/pcb-review/SKILL.md` (REQ-UX-f366d2db), `scripts/kicad_tool.py` (sets `sys.dont_write_bytecode`, REQ-REL-20ece322) and `scripts/kicad_support/` with `__init__`, `workspace` (shared), `sexpr`, `discovery`, `project`, `kicad`, `netlist`, `board`, `checks`, `bom`, `exports`, `review`, `document`, `operations`, `cli`.
