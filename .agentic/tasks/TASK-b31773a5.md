## Frame

Problem: File size limits are fixed in code (100 MiB PDF/Office, 20 MiB text) and the number of
indexed files is unbounded; a user cannot keep large scanned PDFs or dumps out of the index except
by listing them one by one, and the selection does not report skipped files with a reason (STATED
#276 Problem; OBSERVED knowledge/kinds.ts PDF_LIMIT/TEXT_LIMIT/sourceLimit, selection.ts
selectDocuments returns `{paths, retry}` only).
Desired outcome: `docs.maxFileMB` (optional, positive) and `docs.maxFiles` (positive integer,
default 10,000) exist in the shared workbench schema at format 1; the selection applies the lower
of the fixed limit and `maxFileMB` and returns oversized files as skipped with reason `too-large`;
Documents & RAG offers "Maximum file size (MB)" and "Maximum indexed files" with validation and no
helper text; the Files tab shows skipped files with their reason in en/ro/de/fr (STATED #276
Deliverables, #274 Decisions).
Actors: workbench user (New Workbench and editor Documents & RAG; Files tab); desktop indexer
process (selection, ingest).
Primary scenario: A user sets "Maximum file size (MB)" to 25 and saves; on the next reconciliation
a 30 MB scanned PDF is not indexed and its Files tab row reads "Unsupported · Size limit exceeded".
Examples: IDX-02-A..C of #276 (STATED): 30 MB PDF skipped under 25 MB, indexed without the setting;
a value above the fixed limit (e.g. 500 MB) does not raise it (a 101 MiB PDF stays skipped); 0,
negative and non-numeric values refused by schema and form; skipped files listed with reason in
en/ro/de/fr.
Counterexamples: an empty "Maximum file size (MB)" means the fixed limits, not 0; maxFiles does not
yet stop or cut indexing (IDX-03, STATED #274 Children).
In scope: shared schema fields + patch fields (patch `maxFileMB: null` clears it); `sizeLimit(kind,
docs)` in kinds.ts; `Selection.skipped` with reason `too-large` from selectDocuments; Ingester

## Design

**Approach.** One size rule, `sizeLimit(kind, docs)` in `knowledge/kinds.ts`: the fixed
`sourceLimit(kind)` lowered to `floor(docs.maxFileMB x 1 MiB)` when set (REQ-FUNC-133f57ee).
`selectDocuments` already lstat's each selected file; a file above `sizeLimit` goes to a new
`Selection.skipped` list (`{ path, size, reason: "too-large" }`) instead of `paths`. The Ingester
keeps rows for `paths` and `skipped`, walks both in path order, and its existing size branch in
`ingest()` uses `sizeLimit(kind, config().docs)`, so a skipped file is recorded `unsupported` /
`SIZE_LIMIT` from lstat alone, never read. The volume event counts `paths` only. A config save
already calls `ingest.request()` (service.ts updateConfig), so a changed limit reconciles on the
next run without a new policy key. Rejected: dropping skipped files from the selection entirely
(their rows would vanish and the Files tab could not show the reason, REQ-UX-b333a5d6); a new
reason code (SIZE_LIMIT already names it in four languages). The processor's and inspect's fixed
budgets stay as read guards.

**Interfaces and data.** Shared `docs`: `maxFileMB: z.number().positive().optional()` (zod 4
numbers reject NaN/Infinity), `maxFiles: z.number().int().positive().default(10000)`; workbench
default includes `maxFiles: 10000`; patch `maxFileMB: positive().nullable().optional()`,
`maxFiles: int().positive().optional()`; `mergeWorkbench` deletes `docs.maxFileMB` when the patch
gives null (REQ-DATA-9fd427f1, REQ-DATA-3bae7e69). Export `workbenchDocsSchema` so the renderer can
validate a draft. Renderer: `WorkbenchDocuments` gains two text fields (`inputMode` numeric/decimal) under "Use
.gitignore"; each keeps its typed text locally, writes a valid value (or undefined for an empty
size) to the draft, and writes NaN for invalid text so the draft fails `workbenchDocsSchema`; an
invalid field gets `aria-invalid` and a `role="alert"` line (REQ-UX-4c2257b2). Editor Save and
Create are disabled while the draft's docs fail the schema; the editor patch sends `maxFileMB ??
null` and `maxFiles`, create sends both (REQ-UX-b189ed46). Files tab: unchanged code, status ·
reason via `useDescribeDocument` (REQ-UX-b333a5d6).

**Files and test seams.** shared `workbench.ts` (+ `workbench.test.ts`); core `kinds.ts`,
`selection.ts`, `ingest.ts` (+ `ingest-selection.test.ts` for skip/record/volume, existing
`ingest.test.ts` limits), `service.test.ts` (YAML write); desktop `indexer-handler.test.ts` /
`indexer-host.test.ts` mocks gain `skipped: []`; renderer `workbench-documents.tsx`,
`workbench-editor.tsx`, `workbench-create.tsx`, `mocks/mockApi.ts` if it builds docs literals,
locales x4 (+ `documents.test.ts` for fields, alerts, Files tab reason in four languages;
`workbench-plugins.test.ts` for the editor patch); help documents page x4; CHANGELOG; release notes.

**Risks and open decisions.** A selection result from an older indexer build is not a concern
(pre-release, one build). Reconciling a large skipped set costs one lstat per file, as today.
No migration: the schema default adds `maxFiles: 10000` to configurations without it.

**Requirement map.** REQ-DATA-9fd427f1: schema fields, default, null clears. REQ-DATA-3bae7e69:
zod positive/int/finite. REQ-FUNC-133f57ee: sizeLimit, Selection.skipped, ingest branch, volume.
REQ-UX-b189ed46: fields and payloads. REQ-UX-4c2257b2: NaN draft, alert, disabled Save/Create.
REQ-UX-b333a5d6: existing describe path, tested in four languages.
