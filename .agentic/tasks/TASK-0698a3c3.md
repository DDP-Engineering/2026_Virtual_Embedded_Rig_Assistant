## Design

### Approach
OBSERVED existing toolPathGuard derives scope from current host mode and preserves application-data exclusions.
Pass that host-owned guard into ordinary program request preparation, verification and runner admission (REQ-FUNC-0a6906be).
Keep a confined default for standalone runner/request consumers and HIL preparation (technical constraint: BYP-02 owns HIL widening).
Named files use canonical guard paths; existing outside files/directories are refused outside Bypass (REQ-DATA-b4e317de).
Preserve Windows alias normalization and stream refusal, with exclusion preflight before fallback.
### Interfaces and data
Internal optional PathGuard objects are host-selected; model parameters gain no scope switch.
Prepared request cwd/files remain strings, relative inside and canonical absolute outside; outside directory args add optional directories [{arg,path}] without content hashes or argv rewriting (REQ-DATA-96d008d8). Shared strict schema, desktop redaction/card and CLI prompt carry it; Markdown/JSON exports retain it. SessionService persists outside canonical program metadata on tool.done independently of approvals and capped summaries; safe commands retain their no-approval behavior.
Run records/logs remain format 1 under the workbench, independent of process cwd.
Capture the durable session Bypass epochs before asynchronous preparation and apply admission; background runs omit turn cancellation but retain both original epochs, even across leaving/re-entering Bypass (REQ-SEC-c4553379).
Recheck plugin integrity, cwd identity, files and current guard authorization before spawn; finish record I/O before final verification (REQ-SEC-370f2d9b).
### Files and test seams
program-request.ts, program-tools.ts, runner.ts, path-guard.ts, shared program-rules.ts, desktop main events.ts/renderer approval-card.tsx and CLI approval-prompt.ts; adjacent request/tool/runner tests and sessions/programs.test.ts.
Prompt tests and four-language tool descriptions/Permissions help; native program-bypass acceptance with declared local fixture.
### Risks and open decisions
STATED arbitrary program behavior is not sandboxed. Only recognized paths are checked; no claim about opaque arguments or child actions.
OS permissions remain authoritative. No storage migration or dependency changes.
Native Ubuntu is unavailable unless discovered; WSL2 evidence is named separately.
