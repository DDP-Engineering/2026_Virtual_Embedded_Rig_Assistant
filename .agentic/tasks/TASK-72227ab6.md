## Design

Diagrams: [diagram_TASK-72227ab6.md](diagram_TASK-72227ab6.md)

### Approach

One declarative package on the unchanged plugin platform, plus one value in the catalog activity vocabulary (named constraint: script installs, safe rules and the catalog source already exist). `plugins/electronics-calc/` ships program `elec-calc` = `scripts/elec_calc.py`, a PEP 723 script without third-party dependencies (REQ-PLAT-c87a001f: nothing to fetch offline), and the support package `scripts/elec_support/`, which holds the quantity, result and report contracts and every numeric model once (ticket: common logic published once). Primary flow: `scripts/elec_calc.py` (bytecode flag, `sys.path`) -> `elec_support/cli.py` (argument parser with the field reference in each operation's help, request bytes, SHA-256, strict JSON) -> `engine.run_operation` -> a `Reader` validates fields and collects every problem -> one model function computes in SI -> `Result` rounds and formats -> one document on standard output (REQ-DATA-3d15fdfc); a `CalcError` becomes the error document and exit 2. `tolerance` re-enters `engine.run_model` for the nominal, each corner and each sample (without the input record); `report` calls it per calculation and only then writes files. The entry script sets `sys.dont_write_bytecode` before it imports the package (REQ-REL-29808598; named constraint: the store hashes every installed file).

Rejected: pint or numpy (network at install, larger trust surface, nothing the models need); one single-file script (the ticket asks for a reusable support module); an expression evaluator (excluded by the ticket); later plugins importing this module across installed folders (forbidden by the ticket - a later consumer receives a verified copy, decided by its own work package).

### Interfaces and data

Exact names, formulas, limits and error codes: spec `REQ-DATA-3d15fdfc`. Modules of `elec_support`:

- `quantities.py`: unit table, prefix parsing, `Quantity`, result rounding (12 significant digits) and engineering text (REQ-DATA-f4cc4198, REQ-REL-61e234ea).
- `contract.py`: `Problem`/`CalcError` (code, path, message), strict JSON loading, `Reader` (exact keys, typed getters that record inputs, error accumulation), `Result` (assumptions, formulas, results, details, checks, warnings, limits) and the document header (REQ-DATA-3d15fdfc, REQ-REL-6c99b9c7, REQ-REL-7b943f73).
- `waveforms.py`: shape factors and the current descriptor (REQ-FUNC-49d4ab63, REQ-FUNC-8943ed4c, REQ-REL-e2517e0e).
- `electrical.py` (`dc`, `divider`, `rc`), `losses.py`, `thermal.py`: one function per model in the table `MODELS[operation][model]` of `engine.py`.
- `tolerance.py`: path access on a copy of the target input, ranges, corners, the three-point check, seeded sampling and statistics (REQ-FUNC-cd05145a, REQ-FUNC-4ac67c0d, REQ-REL-62a00f96).
- `cli.py`: the command line, operation help with every field, exit codes, and `contract.fitted` on every printed document (REQ-UX-b186323e, REQ-REL-c46a7e47).
- `report.py`: path guards judged from the text before the file system, exclusive folder and file creation, JSON and Markdown rendering, removal of every created file and folder on failure (REQ-REL-fd2fa08d); (REQ-FUNC-a39b04ed, REQ-REL-8c73edc4, REQ-SEC-6c075f30).

Errors: every validation happens before computing; refusals exit 2; an output failure exits 3 after removing what the run created. No state between runs; the only writes are the report folder. Manifest: format 1, ecosystem `electronics`, windows-x64 and linux-x64, one script program with version probe `^elec-calc (\d+\.\d+\.\d+)` and timeout 120 s (REQ-FUNC-5ddc54a6), four `safe` rules, with 600 s for `tolerance` and 1800 s for `report` (REQ-SEC-79d36216). Catalog: `official`, metadata activities `[design]` with keywords, pack `electronics` (Electronics design), group Calculations, default on (REQ-DATA-0f278063). Activity: `design` appended to `CATALOG_ACTIVITIES`, label key `plugins.library.activities.design` - en Design, ro Proiectare, de Entwurf (REQ-UX-a7a3f2a9). Skills `electronics-sizing` and `thermal-analysis` (REQ-UX-e13eef8a).

### Risks and open decisions

- Bytecode written into the installed folder would break integrity: guarded by the flag and proven by the integrity test.
- Floating point across platforms: results are rounded to 12 significant digits and tests compare with tolerances; identical Monte Carlo results are promised per runtime only.
- A safe rule lets `report` write without approval, like other safe programs' output files; it is confined to the working directory, refuses `.vera` and never overwrites (REQ-SEC-6c075f30).
- Open for the user: the activity name `design`, the pack and program names; native Ubuntu evidence (REQ-PLAT-7f86133e) is pending a host.

### Requirement map

Model requirements map one-to-one to model functions: REQ-FUNC-a7be6767, REQ-FUNC-9897d628, REQ-FUNC-fa29ca17 in `electrical.py`; REQ-FUNC-af6f7e42, REQ-REL-c4a6c310, REQ-FUNC-d476ec79, REQ-FUNC-0e71b135, REQ-FUNC-8cbe08aa, REQ-FUNC-da9b750b, REQ-FUNC-634a2c7e in `losses.py`; REQ-FUNC-29e71501, REQ-FUNC-452dd186, REQ-REL-003ccb83, REQ-FUNC-d1afe1f3 in `thermal.py`.
