## Frame

Problem: VERA cannot run any external process: there is no ProcessHost port, no runner, no run logs and no background-run registry (OBSERVED: `core/src/ports.ts` has WorkerPool only; `rg child_process` finds only `desktop/main/openers.ts` and tests; ADR-0016 "Today VERA cannot run any external process").
Desired outcome: core runs a declared executable through a host-implemented ProcessHost port with an argument array, no shell, closed stdin, a minimal environment, a guarded cwd, a timeout and Stop that kill the whole process tree on Windows and Linux, UTF-8/ANSI-clean output with a capped tail in the result and the full output in `.vera/runs/<run-id>.log` (newest 200 kept), at most 4 background runs per session killed on session stop, workbench close and app exit, a serial-port guard and launcher quoting (STATED: ticket #58 scope; architecture §3.2, §3.3).
Actors: PLG-04 tools (`run_program`, `program_output`, `program_stop`) that will call the runner; desktop main and the CLI that implement ProcessHost and own app/workbench lifecycle; the engineer whose bench tools run (STATED: plan PLG-04 depends on PLG-02).
Primary scenario: a caller asks the runner to run `<node> echo.mjs "a b" "q\"uote" "żółw"` in the workbench root with a 120 s timeout; the program receives exactly those three arguments, its output is decoded, stripped of ANSI codes, written to `.vera/runs/<id>.log`, and the result carries exit code, duration, the tail, the log path and `truncated` (STATED: done-when "echo-program fixture proves argument fidelity (spaces, quotes, Unicode)").
Examples: a foreground run that exceeds its timeout returns `timedOut` and its grandchild process is gone (STATED: done-when); a 5th background run in one session is refused (STATED: "at most 4 per session"); `esptool --port COM3 read-mac` while a background `serial-monitor COM3` runs fails and names that run's handle (STATED); a launcher in one-string mode receives `"idf.py" "build"` and an argument `a&b` is refused (STATED: §3.3 metacharacters); the 201st log deletes the oldest (STATED: newest 200 kept).
Counterexamples: the runner never resolves a program name to an executable, matches rules or asks for approval (PLG-03/04/05, STATED plan); a foreground run naming COM3 with no background run on COM3 is not refused; `OPENAI_API_KEY` in VERA's own environment never reaches the program (STATED: credentials never enter it).
In scope: ProcessHost port in `core/src/ports.ts`; Node implementations in desktop main and the CLI (no shell, windowsHide, closed stdin, process group on Linux); core `ProgramRunner` (env, cwd guard, spawn, decoding, ANSI stripping, tail, run log, retention, timeout, Stop, tree kill, background registry and limit, serial-port guard, abort signal); launcher argument composition and quoting; composition in desktop main and CLI with stop on session stop, workbench close and app exit; an `echo-program` fixture; a lint boundary that keeps `child_process` out of core sources.

## Design

**Approach.** Core owns all run policy in `ProgramRunner` (`core/src/plugins/runner.ts`) and talks
to the OS only through a new `ProcessHost` port in `core/src/ports.ts` (spawn with fixed options,
signal a pid or group, platform and environment snapshot). The Node implementation of the port is
`NodeProcessHost` in `core/src/plugins/node-process-host.ts`, which receives `spawn` as a
constructor argument: desktop main (`main/process-host.ts`) and the CLI (`cli/src/process-host.ts`)
import `node:child_process` and inject it, so core never imports it (REQ-NFR-d056ff66) and the two
apps share one tested implementation, the way both compose `NodeWorkerPool`. Rejected: a full copy
of the host in each app (two diverging spawn paths to prove on two systems). Flow: `start(request)`
checks the background limit and the serial-port guard and reserves the run synchronously, resolves
`cwd` through `PathGuard`, opens `.vera/runs/<ulid>.log`, prunes old logs, builds the environment,
spawns, and streams decoded output into the log, the tail and the unread buffer; `done` settles on
the host's exit. Timeout, Stop, abort and the lifecycle stops call `killProcessTree`
(`process-tree.ts`): win32 runs `%SystemRoot%\System32\taskkill.exe /T /F /PID <pid>`; elsewhere the
run was spawned as a group leader and receives `signal(-pid, SIGTERM)`, then `SIGKILL` after
`clock.sleep(3000)` (REQ-PLAT-8423a400, REQ-PLAT-c76610c6).

**Interfaces and data.** `ProcessHost { platform; env; spawn(executable, args, {cwd, env, group,
output}) -> {pid, exit: Promise<{code, signal, error?}>}; signal(pid, name) -> boolean }`.
`NodeProcessHost.spawn` always passes `shell:false, windowsHide:true, stdio:[ignore,pipe,pipe],
detached:group` (REQ-FUNC-e08c858b, REQ-FUNC-dbcd3311); a spawn error before a pid exists resolves
`exit` with `error` = the errno code (REQ-REL-e594e725). `ProgramRunner({host, clock, toolPaths?,
tailChars=12000, maxBackground=4, logsKept=200, killGraceMs=3000})`; `start({sessionId, workbench,
executable, args, cwd?, env?, timeoutMs?, background?, signal?}) -> ProgramRun {id, done, read(),
stop()}`; `run()` = start + done; `get(handle)`, `stopSession(id)`, `stopWorkbench(root)`,
`stopAll()`. `RunResult {runId, exitCode, signal, error?, durationMs, output, truncated, log,
timedOut, stopped}` (REQ-FUNC-85bf8a14); `read()` returns unread text (capped at tailChars, with
`truncated`), `running`, `exitCode` (REQ-FUNC-b7e0b968). Errors as VeraError: DENIED for a guard
failure or a non-directory cwd (REQ-SEC-7a6c3f5f), BUSY `{limit}` for the fifth background run in a
session (REQ-FUNC-f678fbd7), BUSY `{handle, port}` for a held port (REQ-SEC-016c9aad); all before
any spawn. Environment per RULING-002 (REQ-SEC-f5c114de). `run-output.ts`: one streaming
`TextDecoder` (fatal false) and one ANSI stripper per stream that holds back an unfinished escape
(CSI, OSC, two-character ESC, C1 CSI) (REQ-FUNC-2871462b); `TailBuffer` keeps the last N
characters and a total. Logs: ULID names, complete decoded text, spawn errors appended
(REQ-DATA-6491c211); after creating its log a run deletes ULID-named logs beyond the newest 200,
skipping active runs (REQ-DATA-49ebfb15). `launcher.ts`: `launcherArgs(launcher, command, mode)`
(REQ-FUNC-efbc6124) refusing per REQ-SEC-7b3e7ed4 with INVALID `{index}` (RULING-001). Serial ports:
`COM\d+` (optionally `\\.\`, case-insensitive, normalised upper case), `/dev/tty*`,
`/dev/serial/by-id/*`, whole argument or the value of `--name=value`; registry is runner-wide.

**Files and test seams.** Core: `ports.ts`, `plugins/{runner,run-output,launcher,process-tree,
node-process-host}.ts`, `index.ts` exports; unit tests `plugins/{runner,run-output,launcher,
process-tree}.test.ts` with a fake host (env, cwd, limits, guard, retention, read, lifecycle, Linux
and Windows kill, timeout, abort). Apps: `main/process-host.ts`, `cli/src/process-host.ts`;
composition in `main/index.ts` (session.stop -> stopSession, workbench.close -> stopWorkbench of the
snapshot folder, before-quit drain -> stopAll) and `cli/src/run.ts` (resources -> stopAll)
(REQ-FUNC-39d5e6d9). Real processes: `tests/integration/process-hosts.test.ts` compiles each app's
host with esbuild (as `worker-hosts.test.ts` does) and runs the runner on the
`tests/fixtures/echo-program/echo.mjs` fixture (modes via `ECHO_MODE`: argv, stdin, env, flood,
ansi, grandchild) for fidelity, stdin, env, tail/log, ANSI, ENOENT, timeout and Stop grandchild
kills. Boundary: `biome.json` core override forbids `node:child_process` outside tests;
`tests/tooling/boundaries.test.ts` probes it.

**Risks and open decisions.** The program is not sandboxed (architecture §3.2); risk rules and
approvals arrive in PLG-03. Linux behaviour is proven by unit tests only on this host: DEVIATION to
log. `stop()` waits for the host's exit; a process that survives `taskkill /F` or SIGKILL would keep
it pending (accepted: both are forced kills). The one-string quoting targets the parser of
`eim run`, unverified until PLG-10 (plan R-P5). A signal to `-pid` after the group leader exited
could reach a reused group id within the 3 s grace (accepted: negligible window).

**Requirement map.** REQ-FUNC-e08c858b, REQ-FUNC-dbcd3311: NodeProcessHost fixed options, real
fixture tests. REQ-SEC-f5c114de: runner env builder. REQ-FUNC-cb84887a, REQ-SEC-7a6c3f5f: PathGuard
in start. REQ-FUNC-58d65f31, REQ-FUNC-691dd257: timer/stop/abort -> killProcessTree.
REQ-PLAT-8423a400, REQ-PLAT-c76610c6: process-tree.ts branches. REQ-FUNC-2871462b: run-output.ts.
REQ-FUNC-85bf8a14, REQ-DATA-6491c211, REQ-DATA-49ebfb15: tail, log, retention in runner.
REQ-FUNC-b7e0b968, REQ-FUNC-f678fbd7, REQ-FUNC-39d5e6d9, REQ-SEC-016c9aad: runner registry and app
composition. REQ-FUNC-efbc6124, REQ-SEC-7b3e7ed4: launcher.ts. REQ-REL-e594e725: host exit error
and runner log. REQ-NFR-d056ff66: biome boundary and injected spawn.
