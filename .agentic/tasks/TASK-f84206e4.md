## Frame

Problem: Dependencies are visible only after the package is downloaded for review; required plugins are not installed together with their programs; there is no re-install (repair). (STATED, ticket PLG-04 #265 `F:\ProjectsDDP\VERA_Plugin_Management_Tickets\PLG-04.md`.)
Desired outcome: `vera catalog build` writes a dependency summary per index entry (each program's install kind - pip requirement, script path, download platform/size/SHA-256, find with supported range and vendor guide - plus required plugins); the catalog card details and the plugin page list each dependency with where it installs (VERA's program folder) or where it was found (path, version) and whether VERA installs it automatically; Install with dependencies installs the plugin, its required plugins and every pip/script/download program and lists what stays manual with the vendor guide and Check again; Re-install verifies/downloads the pinned files again and replaces VERA's copy without migrating anything. (STATED, ticket deliverables.)
Actors: the user on the Plugins page; the catalog maintainer running `vera catalog check/build`.
Primary scenario: the user opens arduino-cli's card details (no package download) and sees its pinned download (size, SHA-256) and serial-monitor; chooses Install with dependencies; serial-monitor and arduino-cli are reviewed and installed, then their pip/script/download programs are installed; the result lists what stays manual. (STATED PLG-04-A/B.)
Examples: arduino-cli -> requires serial-monitor; program arduino-cli download windows-x64 20 404 890 bytes / linux-x64 20 111 675 bytes (OBSERVED, HTTP HEAD 2026-11-15), program arduino-tool script `scripts/arduino_tool.py`. KiCad -> kicad-cli find, range `>=10.0,<11`, guide https://www.kicad.org/download/ - reported manual (OBSERVED `05_Software/plugins/kicad/plugin.yaml`). Re-install of a download whose file no longer matches its SHA-256 downloads it again and reports ready (STATED PLG-04-C).
Counterexamples: VERA never installs a `find` (vendor) program (STATED, coordinator brief); Re-install never migrates settings or records (STATED).

## Design

- Shared `plugins.ts`: download entry gets optional `bytes` (positive int). `pluginDependencySchema` + `pluginDependencies(manifest)` - one flat item per program: `name, kind (pip|script|download|find), automatic, pip?, script?, downloads?: {platform, sha256, bytes?}[], find?: ("windows"|"linux")[], range?, guide?` (guide = hint text; the link is derived in the renderer with the same rule as provisioning's `linkOf`). `automatic` = kind is not find. Status gets optional `path` for a ready program found on this computer.
- Shared `plugin-catalog.ts`: entry requires `dependencies` (max 64). Core `catalog-source.ts`: build writes `pluginDependencies(manifest)`; check adds code `dependency` for a find program without hint.
- Core `provisioning.ts`: `download()` limit = declared `bytes` (exceed -> `sha256`) and a `replace` mode that swaps the new tree in for an existing folder (old folder moved to staging, removed). `installOne(repair)` re-downloads downloads when repairing. New `reinstall(id, signal, authority)` shares `install()`'s loop with a selection predicate: every program that is not find and not an external-only found program. `examine(fresh)` hashes a single-file (`downloadForm === "file"`) download and returns `unavailable/sha256` on mismatch; find-found ready statuses carry `path`.
- IPC `plugins.reinstall` (same request/response as `plugins.provision`); main handler mirrors provision through `ProvisionerHosts.run` (its hosts are Provisioners, so no change there).
- Renderer: new `plugin-dependencies.tsx` (`CatalogDependencies` for the card details, `RequiredPlugins`); `Programs` shows automatic/manual and the found path; card action Re-install; catalog card action Install with dependencies -> `reviewCatalog(ids, {programs: true})`: after the queue installs, `plugins.provision` per installed id; the page shows a `data-install-result` block (Programs per plugin + Check again). Locales en/ro/de.
- DEVIATION design: no diagrams - data fields, one provisioner mode and display components.
