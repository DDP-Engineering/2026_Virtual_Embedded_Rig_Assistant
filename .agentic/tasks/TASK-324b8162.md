## Design

Diagrams: [TASK-324b8162 diagrams](diagram_TASK-324b8162.md)

### Approach

Two declarative packages on the unchanged plugin platform (named constraint: PEP 723 script and pip install kinds exist; no platform change). `can-python` ships program `can`, a PEP 723 script `scripts/can_bus.py` on `python-can[serial,gs-usb,pcan,multicast]==4.6.1` with argparse subcommands `list`, `capture`, `send`, `replay` (abbreviations disabled so rule tokens are exact). `can-dbc` ships pip program `cantools` (`cantools>=45,<46`) for dump/list/convert/generate_c_source and script program `can-decode` (`scripts/can_decode.py` on cantools 45.1.2 + python-can 4.6.1) because `cantools decode` reads stdin, which the runner closes (Frame counterexample; REQ-FUNC-7951af72). Rejected: a stdin bridge in the runner (platform change, out of scope); find programs for drivers (drivers are shared libraries without a version probe), so driver detection and hints live in the script (REQ-FUNC-ed24ef4a, REQ-REL-07f029dd).

### Interfaces and data

- `can list` → JSON `{configs, drivers}`: `can.detect_available_configs` limited to pcan, vector, kvaser, slcan, gs_usb, socketcan (udp_multicast is passed directly, virtual is in-process only); `drivers` reports pcan/vector/kvaser library presence (ctypes), slcan (pyserial), gs_usb (libusb backend), socketcan (Linux) with a hint each. Opens no bus.
- `can capture --interface --channel [--bitrate] [--fd --data-bitrate] (--duration S | --max-messages N) [--output f.asc|.blf|.log] [--active]`: listen-only kwargs pcan `state=PASSIVE`, vector/slcan `listen_only=True`, kvaser `driver_mode=False`; every Bus gets `ignore_config=True`, with digit-only channels passed as integers (ignore_config skips python-can's casting); pcan, kvaser and gs_usb require --bitrate (checked after the listen-only refusal); the output file must be new and is created before the bus opens; software buses (virtual, udp_multicast, socketcan `vcan*`) need none; a socketcan channel whose `ip -json -details link show` ctrlmode lists LISTEN-ONLY is accepted; anything else exits 2 unless `--active` (REQ-REL-35df942b). Writes via `can.Logger` (flushed per frame for text formats) or prints candump-style lines; summary `[can] N frames ... stopped by duration|max-messages` on stderr (REQ-FUNC-cd61ecee).
- `can send --id HEX --data HEX [--extended] [--fd [--brs]] [--count N --period-ms P]` and `can replay --input LOG [--ignore-timestamps] [--max-messages N]` (MessageSync timing, stopping right after the limit) (REQ-FUNC-4adc847a, REQ-FUNC-835a17ea). The first argument must be a command (a leading `--` would otherwise reach a subcommand on CPython 3.12+); FD payloads use canonical lengths and --brs needs --fd (REQ-REL-292d1dd5). Exit 0 done, 2 usage/refusal before any bus opens, 3 open/IO failure with backend hint.
- `can-decode --dbc DB --input LOG [--id HEX]... [--limit N] [--no-choices] [--no-strict]`: one line per decoded frame `time id name sig=value unit`, then per-message and unknown-ID counts; exit 2 for unreadable inputs.
- Rules (REQ-SEC-2eb33af8, REQ-SEC-9be4b959): `can {--version,--help,-h}` and `can list *` safe; `can capture *` device-read; `can capture * --active *` device-write; `can send *`, `can replay *` and, as a backstop, `can * {send,replay} *` irreversible (confirm word = that token); `cantools {--version,--help,-h}`, `cantools * {dump,list,convert,generate_c_source} *` safe; `cantools * {decode,plot,monitor} *` blocked; `can-decode *` safe. Program timeouts: can and can-decode 300 s, cantools 120 s.
- Packs: new `can` pack (Bus capture and transmit: can-python; DBC decoding: can-dbc; both default on). Skills can-capture, can-transmit (can-python), can-decode (can-dbc) (REQ-UX-c9e6cb02).
