## Design

### Approach

Use the shared registry and committed manifests as the authority for staging and verifying model bytes (REQ-PLAT-ac20d6f5, REQ-REL-70db8095, REQ-PLAT-03f3a066).

### Interfaces and data

Both models use the existing resources/models layout with a per-model licence file. Verify copied files before and after builder assembly. Delivery verification inspects every desktop artifact via a full 7-Zip CLI. It compares exact members to the source pins and handles nested containers using owned scratch, without launching delivery binaries. Other delivery parts keep their existing paths.

### Files and test seams

The package and delivery tools share one pinned payload list. Packaging tests cover staging and delivery tests cover recognition and refusal. Isolated release smoke uses the normal workbench and document APIs.

### Risks and open decisions

Use a full archive utility with support for NSIS, ZIP, Debian ar/tar and AppImage SquashFS. Local names and hashes are fixed by the source checkout. Artifact or tool errors fail verification.

### Requirement map

- REQ-PLAT-ac20d6f5 maps to staging, real resources and offline indexing.
- REQ-REL-70db8095 maps to archive checks of every pinned member.
