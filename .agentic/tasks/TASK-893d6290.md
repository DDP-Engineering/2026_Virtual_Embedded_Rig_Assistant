## Design

**Approach.** OBSERVED Ingester owns path outcomes, SQLite publication and queued
passes. Its status collector tracks per-pass counters and the set of published
searchable document ids. Seed that set once in the background from indexed rows
with a published passage, then update it after committed writes and removals.
A delayed count notification coalesces progress independently of the snapshot.
Phase transitions produce current status promptly. The search phase stays an
in-memory lookup with no dependency on the snapshot or the tally.

**Interfaces and data.** REQ-FUNC-310efe8f scopes the strict status request and
update to the current workbench activation. Workbench snapshots carry a
process-local lease and status carries a monotonic revision. The current snapshot
rejects a different lease. The renderer subscribes before fetching and merges
only newer revisions into a status-only query-cache entry. Progress is absent
during selection. REQ-FUNC-de6ba478 uses processed paths and published passages
as independent measurements. Read-only visits have no live progress.
The stopped overlay uses the existing indexer host state and recovery, and
count guard paths pass through existing Display masking.

**Files and test seams.** Ingester, its collector, WorkbenchService, shared IPC
schemas and Electron main produce the snapshot. Files and the active navigation
indicator subscribe independently from App and chat; the button requests the
existing Shell Files panel or its configuration when hidden (REQ-UX-db99cdfe).
Integrate retrieval notices into the existing memoized transcript projection
with deduplication by turn and use structural metadata from #362
(REQ-UX-1c0aac4b). Extend native ingest/replay, IPC, renderer and core tests.
Use the existing instrumented Desktop harness on large and payload sessions
and exercise responsive real replay during held indexing (REQ-NFR-3a560b62).

**Risks and open decisions.** Source invalidation and rebuild affect searchable
counts only following a committed mutation. A queued follow-up is visible
before any settled phase. Stop and restart do not mutate the snapshot of an
earlier search. Lease and revision state is process local. Stored formats stay
at version 1. STATED follow-up performance evidence from the coordinator
found costly repeated semantic vector loads after a publishing conflict.
REQ-NFR-3a560b62 also keeps cheap requested-mode retries but switches to
validated keyword after an active-publication conflict that already spent
150 ms on its semantic attempt. The existing three-attempt cap,
revision checks, cancellation and actual-mode metadata still apply. Round 1 review required
recovering watcher errors via Reindex, keeping the in-memory rebuild state synchronized
with the guarded clear of its persisted marker, and clearing file query entries on
adoption of a new activation even when it reuses another folder's workbench id.
