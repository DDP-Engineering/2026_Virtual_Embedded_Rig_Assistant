## Frame

Problem: Plugins carry only an English summary and description and no user help; README.md is the technical reference
(STATED plan `00_Planning/plan/help.md` decision "Plugin help in all four languages"; OBSERVED
`shared/src/plugins.ts` manifest has `summary`/`description` only, no help files are read).
Desired outcome: `plugin.yaml` accepts per-language catalog texts; the catalog, the review and the installed plugin
rows show them in the interface language (English otherwise); an installed plugin's `help/<lang>.md` is listed and
shown in the Help view and opened from the plugin page, with English fallback; the catalog build ships `help/` in
each plugin zip (STATED plan HELP-04).
Actors: users browsing and using plugins; plugin authors.

help; help files are not listed as plugin data files.

## Design

**Approach.** Plugin help sits beside app help: core `readPluginHelp(folder, language)` reads
`<folder>/help/<lang>.md` (else `en.md`) through `readHelpFile`, so the realpath must stay under `<folder>/help`.
Main's `help.list` appends, after the app pages, every healthy plugin of `activePluginStore()` whose composition lists
help, sorted by title; `help.read` accepts `{plugin, language}` and loads the plugin from the same store
(NOT_FOUND when not installed or without help). The renderer keeps one Help state string: `plugin/<id>` for plugin
pages. A `HelpContext` (provided by `App`) gives `PluginCard` an `open` function for its Help button. Catalog texts:
a shared `pluginText(entry, language)` picks `translations[language]` fields, falling back per field to English.
**Interfaces and data.** Manifest `translations?: {ro|de|fr: {summary, description}}` (strict; same limits as the
English fields). Catalog entry `translations` optional, copied by the build. Composition `help?: ("en"|"ro"|"de"|"fr")[]`
(present only when non-empty). `help.read` request: `{page, language}` or `{plugin, language}`; summaries and pages
gain optional `plugin`. Errors: NOT_FOUND for a plugin that is not installed, has issues or no help.
**Files and test seams.** shared `plugins.ts`, `plugin-catalog.ts`, `help.ts` (+ `help-ipc.test.ts`,
`plugins.test.ts`); core `store.ts` `compose` (+ `store.test.ts`), `catalog-source.ts` (+ `catalog-source.test.ts`
zip and translations), `help/library.ts` `readPluginHelp` (+ `library.test.ts`); main `index.ts`; renderer
`components/help.tsx` (context, plugin entries), `App.tsx`, `plugins.tsx`, `plugin-catalog.tsx`, `plugin-packs.tsx`,
`mocks/help.ts`/`mockApi.ts`; locales; `plugins/CONTRIBUTING.md`.
**Risks.** Confinement as REQ-SEC-8e27b5ca: page name is fixed to the language code, and realpath stays under `help/`.
**Requirement map.** REQ-DATA-b8d0a387 schemas; REQ-UX-2cfd762a `pluginText`; REQ-FUNC-559bba00 core + main;
REQ-UX-0d64586a context + button; REQ-DATA-9cdef3e8 compose + build test.
