## Design

### Approach

- REQ-SEC-1b68aa62: a Desktop-main-only Git boundary selects typed operations. Git runs in a private metadata snapshot under app data with an empty config origin except for validated, built-in settings. Parse bounded local config bytes through stdin with isolated Git config --file - --no-includes. Reject includes, filters and unsupported active layout features. No Git process is given the original gitdir, even after preflight; changing the original config while Git is running cannot activate it. Disable fsmonitor, hooks path, system attributes, global/system config, optional locks, prompts, transport and lazy fetching. Use Git 2.40+ from OS installation locations/registry, absolute paths, trusted cwd and a freshly built environment. The allowlist contains version, config parser, cached index listing and one status operation; no user argv.
- REQ-SEC-b24a8722: walk physical ancestors to the first .git directory. Reject gitfiles, symlink/reparse layouts and unsupported alternate storage. The private gitdir contains bounded ordinary HEAD/current ref, packed-refs, index and info rules. Link only loose-object shards and the pack directory under private objects, so Git never interprets the source objects/info/alternates. Use a literal workbench scope. Preflight cached index paths before worktree status and reject directories shared by a nested repository and the outer index. Use --ignore-submodules=all, Git nested-repository detection for untracked areas, and no-follow path projection. Suppress out-of-scope rename sides. Git parses trusted commands; repository index, refs, objects and attribute rules remain untrusted data. A host administrator or same-user process rewriting the application data/install is outside this boundary.
- REQ-REL-92f883f5: one Desktop GitStatusService activation couples scope and a request-specific owner. Watch in-scope directories up to a fixed cap, pruning ignored and nested areas, and targeted Git metadata/ancestor ignore rules. Coalesce bursts, maintain at most one read with a queued rerun, abort on retirement and check ownership before publish. Manual refresh uses the same service. Git changes do not reach indexing, retrieval, session queries or the Changes panel.

### Interfaces and data

- REQ-DATA-7521ac37: format stays 1. interface.git_status defaults to false and is saved in the existing editor/create draft.
- REQ-FUNC-1883b36f and REQ-REL-3cbc93f2: Git status IPC accepts active workbench ID, indexLease and Files view ID plus open/refresh/close. Workbench-scoped status events carry the same owner. A ready result has branch (named, unborn, detached), path count, conflict count, and entries with independent staged/unstaged, conflict, virtual status and optional in-scope rename endpoint. Missing Git, no repository, unsupported repository and failed read are distinct from ready with zero changes. Use existing Display path identities and scrubbed labels before publishing.
- REQ-UX-d3f4505a and REQ-UX-7656913e: badges include visible staged versus worktree marks, localized accessible names and collapsed-folder counts. The existing tree model adds virtual entries without file actions and can filter to Git changes. It gates ordinary actions on verified Files metadata and keeps absent descendants visible when an ordinary file occupies their former folder path. Names, opening, search and file menus keep normal behavior for real rows.

### Files and test seams

- Shared workbench, Git contract and events plus Desktop main git modules and wiring. Tests use real small repositories and injected spawn/watcher dependencies for safety, status and activation.
- Renderer Files overlay and tree projection plus the Interface draft. Component tests check rows, actions, keyboard names and filtering. Localize help, text and release notes.

### Risks and open decisions

- Git status excludes gitlinks. The cached index preflight fails closed before status for an embedded repository that overlaps paths tracked by the containing repository. Ordinary nested repositories are excluded by Git. Object-content parsing is still performed by the trusted Git binary. Linked worktrees, submodule workbench roots, sparse/split layouts, alternates and unsafe config are unavailable; the normal Files tree remains usable.
- User-installed Git policy and local filesystem access are the trust roots. Git is never provisioned from a workbench. Limit command duration, bytes and metadata enumeration, and report unsupported or failed state for unusable inputs.
- Follow-ups add specifically owned read operations to the same boundary and revalidate literal paths against the active activation. Scope, Display identity, rename sides and absence stay in the typed data. No arbitrary Git argument API is exposed.
