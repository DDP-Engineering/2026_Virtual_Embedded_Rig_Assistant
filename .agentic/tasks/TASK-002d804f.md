## Design

### Approach
REQ-FUNC-f0170101/f0170102: add command-tools.ts and shell.ts beside program tools; reuse ProgramRunner, ProgramSession, program_output/program_stop and existing program approval presentation. A command request has tool run_command and a bound command execution payload, rather than a plugin declaration. No plugin packages change.

### Interfaces and data
REQ-SEC-f0170103/f0170104: extend exact-request approval/events with run_command; Ask and Auto-edit ask, Bypass grants through durable mode decisions, Read-only hides/refuses. The approval card renders literal command, cwd and shell without plugin risk claims.
REQ-PLAT-f0170105/UX-f0170106: shell host resolves the current settings.shell on each preparation. Windows argv uses NoProfile/NonInteractive and a UTF-8 script wrapper; POSIX uses bash -lc or sh-compatible -c. A custom executable must resolve, never silently fall back. Shell commands use the shared 4096-character run-record argument limit; larger inputs are rejected before preparation. PowerShell checks final success inside the scriptblock before propagating a final native failure, so a recovered failure returns success.
REQ-SEC-f0170107: the shell host filters the inherited environment by credential names, VERA/Electron state and the host credential scrubber. Existing program output redaction remains at disclosure boundaries; raw local logs follow Program runs policy.
REQ-REL-f0170108/f017010a: reuse runner timeout/tree stop/session/app ownership and NodeProcessHost closed stdin. Background calls retain session and Bypass epoch signals, excluding the completed tool-turn signal.
REQ-SEC-f0170109: bind canonical cwd and original input, then re-resolve the original immediately before spawn with toolPathGuard and current exclusions. Shell syntax is not parsed as confined file operations and no sandbox is promised.

### Files and test seams
Core plugins shell/command-tools and focused tests; runner optional inherited shell environment; approval gate/request/events and immediate session consumers; shared settings/tool catalog; desktop/CLI host composition; localized Settings shell panel/approval card; system prompt/help/release notes and inventories.
Real process integration covers Windows and WSL2 using the pinned Node executable and owned evaluation-outputs/term01/platform evidence. Native Ubuntu remains a stated limitation.

### Risks and open decisions
Shells execute arbitrary syntax under the OS account. Preserve protected cwd checks and mode epochs without claiming confinement of command side effects. Login-shell profiles can change environment after spawn; VERA filters what it supplies. No new dependencies or format versions.

### Requirement map
All ten coverage rows map to the decisions and test seams above. Full suites remain coordinator-owned and deferred by explicit delegation.
