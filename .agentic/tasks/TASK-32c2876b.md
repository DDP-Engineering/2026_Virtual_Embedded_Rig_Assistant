## Design

**Approach.** OBSERVED the Electron capability query initializes the same presenter as notice creation. Bypass the session-notification controller on Windows in portable mode before either call (REQ-PLAT-99eec2f1).

**Interfaces and data.** Reuse the startup-resolved portable boolean from configureDataLocations. It is immutable for the process lifetime. Continue to use the same saved preferences and in-app activity. There is no new data.

**Files and test seams.** Desktop main supplies the current mode to SessionNotifications. The controller test asserts that both events skip capability and constructor on Windows portable and still create notices on installed Windows and Linux. Localized Help names portable support, desktop service requirements and the existing fallback.

**Risks and open decisions.** This prevents registration for this feature. It leaves the installed runtime identity and click callback intact. Package delivery and OS click observations are independent of presenter availability. The authorized Linux desktop available so far is WSL2.

**Windows identity correction.** OBSERVED the first installed banner was named VERA, but subsequent attribution used Electron. The unsigned PE version resources also named Electron. Replace the builder option that disables both editing and signing with the option that controls signing only (REQ-PLAT-c8943ad9). The test AUMID and test product name stay distinct. The observed history click failure is independently retested and is not assumed to be solved by version resources.

**Requirement map.** REQ-PLAT-99eec2f1 owns the guard. REQ-REL-be721878 and REQ-PLAT-4a030007 retain their existing in-app and data paths.
