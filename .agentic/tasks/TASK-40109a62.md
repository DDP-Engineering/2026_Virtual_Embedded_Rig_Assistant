## Design

**Approach** — REQ-FUNC-f250eee7 removes the explicit username registration in environment ingestion and excludes the `username` field from `MemoryCredentials` registration for the `mqtt:` namespace. This scope keeps other fields and credential namespaces on the existing registration path.

**Interfaces and data** — OBSERVED the host stores the MQTT password as `key` and username as `env.username`. Both stay in that shape, and callers use the same approved `ProgramCredentials` port. Validation, error codes and credential lifetimes are unchanged. Register the password before validation as today so a rejected input remains covered by diagnostics.

**Files and test seams** — `plugin-credentials-env.ts` and `host-ports.ts` implement the rule; adjacent tests cover stored login, registration and logger escaping. `tests/integration/cli.test.ts` executes the bundled CLI through its replay harness. The shared credential spec and mqtt-tools README record the policy; plugin metadata and release entries follow the repository version rules.

**Risks and open decisions** — OBSERVED either old registration would independently redact `pin`. Match both the MQTT namespace and the exact username field. A username value independently registered as a real secret still masks under the shared policy. No open decisions.

**Requirement map** — REQ-FUNC-f250eee7 covers both CLI registration sites, the program port and the replay. REQ-FUNC-fb24a0e4 has no design impact and is exercised alongside MQTT.
