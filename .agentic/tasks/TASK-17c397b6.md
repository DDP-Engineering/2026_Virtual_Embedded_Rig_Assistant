## Design

### Approach
OBSERVED existing PluginStore review/install uses whole-package hashes and verified snapshots. Extend the store with a workbench-bound view; select one current machine hash with validated format-1 records and retain hash-addressed code snapshots using the same installed record machinery (REQ-SEC-13ab0002). Global install/builder/catalog stay global. No second manifest/hash system.
### Interfaces and data
Add forWorkbench(folder), reviewScoped(id), trustScoped(id, hash). All ids/list/load resolve scoped names first and block global collisions (REQ-FUNC-13ab0001/0005). Scoped snapshot root includes the machine-local canonical-path hash and package hash; reserved/<id> reuses an install record for current trust selection; load verifies source and returns snapshot plus a current-integrity callback (REQ-SEC-13ab0003/0004). Reuse install record format 1; no migrations.
Desktop scopedReview/scopedTrust IPC requires open workbench id; reuse review screen, display hash/source, scope label and trust action (REQ-UX-13ab0006). Program status/provision requests optionally name workbench; per-workbench and per-package-hash provisioner runtime roots isolate managed environments. ProvisionerHosts tracks request-bound hosts, cancels them at app quit and rejects new admission. Global actions cannot modify scoped source. CLI list/review/trust commands are explicit user actions with --data, --workbench and trust --sha256 (REQ-FUNC-13ab0007).
### Files and test seams
Store.ts + scoped-store.test.ts; workbench/service.ts uses bound store for warning/skill/runtime discovery. ProgramTools beforeSpawn calls plugin verification in addition to existing approval file hashes; provisioning rechecks callbacks before resolving/installing. SessionsHost prompt cache key includes freshly loaded package hashes; CLI uses same store/view/provisioner. Shared plugins.ts/ipc.ts, desktop main, renderer Plugins/mock/locales and CLI args/plugin/index/run/provisioning are immediate consumers. File tools changes.ts preserves the existing user-owned installed-files boundary for .vera/plugins (write-edit.test.ts). Hash-addressed snapshot paths retain earlier code for prepared/running processes, so a later trust never replaces their code. Over-limit source/reserved/combined lists fail closed; physical global id collision checks are independent of list limits. Existing store/program/skills/approval and native UI tests provide regression seams; local Git fixture and compiled CLI demonstrate real effects.
### Risks and open decisions
Source can change concurrently; executions use verified machine snapshot bytes with source recheck before spawn, preventing changed source code running under old trust. A change after final source check cannot alter snapshot bytes. Snapshot modification is checked using store integrity at load and final callback. Active processes are not killed by later source edits; subsequent consumption is refused. Existing requires is descriptive only and documented; no automatic dependencies/enablement. Symlink/junction ancestors are rejected; host-selected workbench itself can resolve through OS redirection. No unresolved product decision. UNKNOWN native Ubuntu availability.
### Requirement map
REQ-FUNC-13ab0001: scoped list. REQ-SEC-13ab0002: machine snapshot and user action. REQ-SEC-13ab0003: rehash/final callback. REQ-SEC-13ab0004: confined source scan. REQ-FUNC-13ab0005: collision reservation. REQ-UX-13ab0006: existing full review. REQ-FUNC-13ab0007: compiled CLI commands.
