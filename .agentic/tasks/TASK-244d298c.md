## Frame

Problem: The interface is available in English, Romanian and German only; there is no French catalog, the `language`
setting accepts `system|en|ro|de`, and the System choice resolves a French locale to English (OBSERVED
`shared/src/settings.ts` language enum, `renderer/lib/language.ts`, `renderer/i18n.ts`, `preferences.test.ts`
expecting `fr-FR` → `en`).
Desired outcome: French is a fourth interface language: `renderer/locales/fr.json` holds every English key, the
`language` setting and the Appearance picker offer Français, System resolves `fr-*` locales to French, `check:i18n`
audits four catalogs, and dates and numbers formatted with the interface language follow `fr` (STATED plan
`00_Planning/plan/help.md` HELP-01, user decision 2026-11-15 "French goes into the interface too").
Actors: a French-speaking engineer using the desktop app.
Primary scenario: the user opens Settings → Appearance and language, picks Français; every label, error and date in the
app shows in French without restart.
Examples: `language.label` "Interface language" → "Langue de l'interface"; a session date renders with
`Intl.DateTimeFormat("fr")` (e.g. "15/11/2026 10:30"); System with locale `fr-CA` resolves to `fr`.
Counterexamples: an unsupported locale such as `it-IT` still resolves to English; plugin help and app help pages are
not part of this package (HELP-06/08).
In scope: `fr.json`, i18n resources, settings enum, picker option, `resolveLanguage`, the main-process language used
for desktop-entry names, `check-i18n.mjs` catalog list, locale-less date formatting in the renderer that should follow
the interface language, tests and the renderer-foundation spec line on language resolution.
Out of scope: human review of the French text (STATED plan "Open": deferred like the ro/de review); help pages.
Constraints: on `master` (STATED coordinator: "on branch master (no new branch)"); pre-release, settings format stays 1,
no migration (STATED memory rule "No backward compat yet"); no helper texts in the UI (STATED UI rules).
Success signals: `check:i18n` passes with en/ro/de/fr; Settings shows Français and switching applies French labels;
`resolveLanguage("system","fr-FR")` is `fr`.
Evidence: OBSERVED 994 English keys (after adding `language.fr`), no plural keys, `auditCatalogs` iterates any number of
catalogs (`02_Tools/build/check-i18n.mjs`), the CLI reads only en/ro/de.
Assumptions: machine translation is acceptable until human review (INFERRED from the plan's deferred review item).
Unknowns: French label lengths at the minimum window size (checked in validate by the existing layout tests).
