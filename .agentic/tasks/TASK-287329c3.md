Desired outcome (STATED, ticket LAB-07 #108 "Livrabile și operații" and the coordinator brief):
- Plugin `zephyr`: detects west, the Zephyr SDK, CMake, Ninja and the project's Zephyr version; installation/configuration
  is explicit, with host tools compatible on Windows and Linux; a bare `west` package is not assumed to hold the SDK.
- An explicit request: workspace, manifest/revisions, application, exact board including revision/qualifiers,
  configurations, overlays and an owned build directory. `.west` projects or variables outside that scope are never

  also runs on the LAB-06 Renode profile). Porting arbitrary boards is not part of the integration.

Examples:
- `"board": "stm32f4_disco@B"` is refused before CMake runs: the board has no revisions (code `board-revision`).
- A `.conf` that sets an undefined Kconfig symbol fails the build; the result cites the log lines of Kconfig's error and the

## Design

Diagrams: [diagram_TASK-287329c3.md](diagram_TASK-287329c3.md)

**Approach.** A plugin package only; no core/shared/host change (the LAB-01 leases, LAB-04 probe kind and the runner are
reused unchanged). Outside the plugin only `plugins/catalog.yaml`, `packs.yaml` and `prepare-plugins.test.ts` change.
Two PEP 723 helper scripts share one support package `zephyr_support/`:
- `zephyr` (`zephyr_tool.py`): every operation except flash. Its pinned dependencies (west, cmake, ninja, pyelftools,
  PyYAML, pykwalify, jsonschema, packaging, anytree, intelhex, colorama, ply, tabulate, natsort, psutil, junitparser,
  python-dotenv and what Zephyr's build scripts import; exact list in plugin.yaml's scripts) are the host tools; the helper calls them by absolute
  path from its own environment (`sys.executable`, `Scripts/` or `bin/`). No `uses`: a missing SDK must be reportable
  (`uses` makes the helper unresolvable when a used program is missing - OBSERVED provisioning.ts), so the SDK is a
  request field (REQ-FUNC-b9bd62a7, REQ-REL-cb83210f).
- `zephyr-flash` (`zephyr_flash.py`, `uses: [stm32_programmer_cli]`, `resources {--probe, [probe]}`): flash and release
  (REQ-FUNC-62b1d407). Separate because a used program must resolve for every call of the program that uses it.

Primary flow of a process-starting operation: load and validate the request (`request.py`) -> resolve the workspace
model offline (`model.py`: west.yml through west's own `Manifest` API with imports, `.west/config` through
configparser, HEADs from `.git` files) -> board/SDK/version checks (`boards.py`, `sdk.py`) -> preflight findings
(`preflight.py`) -> build folder claim (`builddir.py`) -> run folder with `running` result (`result.py`) -> processes in
the scrubbed environment (`environment.py`) with logs -> diagnostics and artifacts -> final result. Refusals happen
before the run folder exists (exit 2).

Build uses CMake directly, not `west build` (REQ-SEC-f67c1f73, REQ-SEC-8c4432cd): `-DZEPHYR_MODULES` names exactly the
listed module folders, no extension command is loaded, sysbuild cannot start, `.west/config build.*` keys cannot
inject arguments. west runs only for prepare-workspace (west's built-in init/update) and flash (zephyr's own `flash`
extension, after the shadow check). Rejected: `west build` (loads `.west/config` build settings and any extension
named `build`), Zephyr's emulator targets (`-t run`: stock Renode/QEMU scripts), native_sim execution (Linux only; no
verifiable host here - left open, Twister build-only covers native scenarios when the host can build them).

test-run executes nothing: the execution is a LAB-06 `renode-sim capture-uart` run (virtual) or a LAB-03 HIL plan with
a flash and a serial capture step (hardware); test-run binds that run folder by the firmware SHA-256 and parses ztest
output (`ztest.py`), so the verdict always comes from a real run (REQ-FUNC-36e3ecdd, REQ-FUNC-ba432613).

**Interfaces and data.** The spec REQ-DATA-d8ecee6a holds the request, options, findings, environment, marker, result
and exit codes. Progressive result.json as in LAB-06 (no lease for build/test runs: Stop is a tree kill; a `running`
result older than 90 s reads as `stopped`) (REQ-REL-274a88e6). Build folder marker and deletion walker in
`builddir.py` (REQ-REL-2de3e20e, REQ-SEC-01b0aa08). Diagnostics are regex rules over the step logs with line numbers
(REQ-REL-4d0db53e). Artifacts: copies + SHA-256, ELF sections via the gdb-debug `elf.py` copy, memory regions from the
linker's "Memory region" table in the build log (REQ-FUNC-d30944ca). Twister: the helper reads `twister.json` and maps
every case to `not-run` regardless of Twister's own status (REQ-FUNC-889949fc). Flash: probe alias -> serial through
`lab/resources.json` (gdb-debug's registry pattern), HEX parsed and range-checked against the `zephyr,flash` node of
the build's `zephyr.dts`, runners.yaml args allowlisted (`--port=swd`, `--reset-mode=hw`, file keys), stm32cubeprogrammer
runner with the CLI's folder first on PATH (REQ-SEC-a4ed8466).

**Files and test seams.**
- Plugin `05_Software/plugins/zephyr/`: `plugin.yaml`, `README.md`, `skills/zephyr-builds/SKILL.md`,
  `scripts/zephyr_tool.py`, `scripts/zephyr_flash.py`, `scripts/zephyr_support/{cli,request,model,boards,sdk,
  preflight,cmake_scan,environment,builddir,ops,diagnostics,artifacts,prepare,tests,ztest,tools,flash,registry,
  lifecycle,result,errors,elf,workspace}.py` (as built: ops.py holds build/artifacts/clean/inspect, tests.py holds
  Twister test-build, test-run and differences; cmake_scan.py was added in review round 1).
- Fixtures `05_Software/tests/fixtures/zephyr/`: `workspace/manifest/west.yml` (zephyr v4.4.2 + cmsis_6 + hal_stm32
  allowlist), `apps/board-demo/` (stm32f4_disco: board-basics protocol - banner, version, UART echo, 10 Hz ticks,
  button -> LED; `prj.conf`, `fast.conf`), `tests/ztest-basic/` (scenarios pass/skip/fail via an app Kconfig symbol),
  `stand-ins/`: a fake Zephyr tree (VERSION, SDK_VERSION, board.yml, scripts/twister) and fake SDK, a CMake/Ninja
  stand-in wired through the test-only variable `ZEPHYR_TOOL_TEST_BIN` (honored only when `VERA_ZEPHYR_TEST=1`),
  fake west, fake STM32_Programmer_CLI, UART logs for ztest outcomes.
- Tests: `05_Software/tests/integration/zephyr.test.ts` (manifest/rules, request refusals, preflight, builddir/clean,
  stand-in build/test-build/test-run/flash through the helper, Stop through VERA's real runner); opt-in
  `VERA_ZEPHYR_REAL=<scratch root>` for the real workspace/SDK/Twister/Renode.
- Helper Python for tests: a uv venv with the pinned dependencies (PyPI pre-approved), path from
  `VERA_ZEPHYR_PYTHON`; without it the helper-dependent tests are skipped with a message.

**Risks and open decisions.** Project code (CMake, Kconfig, devicetree scripts of Zephyr and modules, Twister) runs on
the host: approval is not a sandbox, preflight only narrows it (REQ-SEC-50f66b49). Windows path length: workspaces and
build folders should be short (documented). Open until the real tools: Twister's build-only status, SDK 1.0.1 layout,
Renode boot of a Zephyr image, the stm32cubeprogrammer runner's CLI lookup.
