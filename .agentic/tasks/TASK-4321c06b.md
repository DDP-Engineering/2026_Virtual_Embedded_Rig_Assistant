## Frame

Problem: `docs.maxFiles` (default 10,000) is stored and validated but enforced nowhere, so opening a
large repository starts indexing tens of thousands of documents; cutting the selection to the first N
would make search silently incomplete (STATED #277 Problem; OBSERVED idx-02 hand-over note "maxFiles is
NOT enforced anywhere yet", ingest.ts reconcile ingests every selected path).
Desired outcome: when the indexable selection exceeds the workbench's file limit, the Ingester does not
ingest any document; the Docs tab shows the count, the ten folders with the most selected files,
"Index anyway" and "Edit exclusions"; "Index anyway" records an approval for that count in the workbench
database and indexing starts; a later selection within the approval's margin keeps indexing, one beyond
it stops again; "Edit exclusions" opens Edit workbench > Documents & RAG; help pages in en/ro/de/fr
describe it (STATED #277 Deliverables, #274 Decisions "Maximum indexed files as a guard, not a cut").
Actors: workbench user (Docs tab, workbench editor); Ingester in the desktop main process (selection runs
in the indexer process).
Primary scenario: a workbench of 12,000 Markdown files with maxFiles 10,000 opens; the Docs tab reads
"Indexing did not start: 12,000 documents selected, more than the limit of 10,000", lists the top folders,
and no document row is created; the user clicks "Index anyway" and all 12,000 index.
Examples: IDX-03-A..C (STATED #277): 12,000 files stop with the right count and top folders, 10,000 index
without a stop; after "Index anyway" 12,000 index, +500 keeps indexing, doubling stops again; no file is
indexed while the guard is active.
Counterexamples: exactly maxFiles selected files index (the guard is "exceeds", STATED #277); documents
skipped as too large (IDX-02) do not count, matching the volume (INFERRED from REQ-FUNC-133f57ee: volume
counts only what gets indexed).
In scope: guard decision and top-folder summary in core; Ingester stops before any row change (including
reindex, which must not clear the index while guarded); approval stored in the workbench database `meta`
table; `index.guard` workbench event and `docs.volume` response carrying the guard; IPC `docs.approve`;
Docs tab guard block with "Index anyway" and "Edit exclusions"; editor opening at Documents & RAG;
i18n x4; help "Documents and search" x4 (also first mention of "Maximum indexed files"); CHANGELOG +
release notes.
Out of scope: preview counting with the indexer's rules (IDX-04 #278, STATED #274); listing files "over
the file limit" in the Documents list (the guard never cuts, so no file is skipped for count - INFERRED
from #274 "never takes an arbitrary first part"); time budget, per-folder limits (STATED #274 Out of scope).
Constraints: pre-release, no migration, workbench.yaml stays format 1 (STATED CLAUDE.md); en/ro/de/fr, no
helper texts (STATED task brief); master, shared checkout, targeted tests only, no push (STATED task brief);

## Design

**Approach.** The guard decides inside the Ingester, right after the selection and before any row
change, so no path can ingest or remove a row while it stops (REQ-FUNC-9a05625c, IDX-03-C). A pure
module `knowledge/guard.ts` holds `fileLimit(maxFiles, approved) = max(maxFiles, floor(1.2 x approved))`,
`topFolders(paths)` and `documentGuard(paths, maxFiles, approved) -> DocumentGuard | null`
(REQ-FUNC-37067755, REQ-FUNC-065c8ad1, REQ-DATA-b12d0ef7). `reconcile(selection, { clear })` emits
`index.volume`, computes the guard, stores it, emits `index.guard`, and returns when guarded; only then
does it apply the embedding fingerprint, clear all rows (Reindex) and ingest. `reindex()` passes
`clear: true` instead of clearing before reconcile, so a guarded Reindex keeps the index
(REQ-FUNC-9a05625c). Rejected: truncating the selection to maxFiles (#274 "never an arbitrary first
part"); storing the approval in workbench.yaml (it is indexer state the user does not edit, and the
editor would show or overwrite it).

**Interfaces and data.** Shared `documentGuardSchema = { files, limit, folders: {path, files}[] <= 10 }`;
workbench event `index.guard { guard: DocumentGuard | null }`; `docs.volume` response gains `guard`;
new IPC `docs.approve { workbenchId, files: positive int } -> {}` (REQ-FUNC-09c7b5d0 schema part).
Core: `Ingester.guard()` and `Ingester.approve(files)` (meta `index_approved_files` written in a
mutation, then `request()`); `WorkbenchService.documentGuard(id)` and `approveDocuments(id, files)`
(CONFLICT for another id, DENIED via assertSessionWritable, NOT_FOUND without an Ingester, like
`reindexDocuments`) (REQ-DATA-b12d0ef7, REQ-FUNC-09c7b5d0). Main: handler `docs.approve`, `docs.volume`
returns guard; events.ts scrubs folder paths of `index.guard`. Renderer: `IndexGuard` component in the
Docs tab (role alert; count and limit via Intl number format; folder list; "Index anyway" disabled when
read-only or pending, sends the shown `files`; "Edit exclusions"); progress and VolumeWarning hidden
while guarded; the guard event resets progress (REQ-UX-0c1aea14). `DocsTab` gets an `editExclusions`
callback; App's `openEditor(snapshot, section?)` passes a fresh `{ section }` request to
`WorkbenchEditor` -> `WorkbenchConfigForm` which switches to it (REQ-UX-597b7c82).

**Files and test seams.** shared documents.ts, events.ts, ipc.ts (+ documents-ipc.test.ts); core
knowledge/guard.ts (+ guard.test.ts: limit, folders, margin), ingest.ts, workbench/service.ts
(+ ingest-guard.test.ts: generated 12,000 / 10,000 / +500 / doubled workbench, process call counter,
approval across Reindex and reopen, CONFLICT); main index.ts, events.ts (+ events.test.ts scrub),
ipc-router.test.ts, preload bridge.test.ts channel lists; renderer docs-tab.tsx, index-guard.tsx,
App.tsx, workbench-editor.tsx, workbench-config-form.tsx, mocks/mockApi.ts, locales x4
(+ documents.test.ts guard block in four languages, approve, edit callback, section). Help documents x4,
CHANGELOG, release notes.

**Risks and open decisions.** Concurrency: approve runs in a mutation outside the ingest queue; the
next queued reconcile reads it, so no race beyond one extra stop event. A watcher still covers the
guarded folders (as today). Pre-release: no migration; the meta key is new and absent means no approval.

**Requirement map.** REQ-FUNC-9a05625c: guard before rows, Reindex clear moved after it.
