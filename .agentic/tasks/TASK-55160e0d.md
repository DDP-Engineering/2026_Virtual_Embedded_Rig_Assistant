## Design

**Approach**: a new official plugin `wokwi` in the sibling pattern (arduino-cli for the pinned, blocked engine; mqtt-tools
for the stdin credential): program `wokwi-cli` downloaded by SHA-256 with every direct command blocked
(REQ-PLAT-59efa984), and the PEP 723 helper `wokwi-tool` with `uses: [wokwi-cli]` and `credentials {option:
--credential, scope: wokwi}`. Work is split into an offline half (inspect, validate, prepare-job, collect, report:
all safe) and one cloud call, run-scenario, rated irreversible because transmitted firmware cannot be recalled
(REQ-SEC-c0479ece). prepare-job freezes everything the cloud call will use into a job folder of exact copies
(REQ-DATA-14b295ed); run-scenario names its job.json, which VERA's approval binds by hash, and the helper re-verifies
every copy against it before reading stdin (REQ-SEC-450de6ab) and runs the CLI with that folder as project and
`--no-sdcard` (REQ-SEC-11ca382d). Rejected: running the CLI on the user's project folder - it reads `sdcard/`, chips
and ESP-IDF `build/` files by itself, so the send list would not be exact. Rejected: a fake WebSocket server through
`WOKWI_CLI_SERVER` - a server override would let a token leave for another host; the helper strips every `WOKWI_*`
variable instead (REQ-SEC-3ab66bb9). The credential path is IOT-05's, generalized: scope enum `["mqtt","wokwi"]`,
one desktop `PluginCredentialService(scope)` behind `mqtt.credentials.*` and new `wokwi.credentials.*` channels, one
parameterized Settings panel, one CLI environment reader (REQ-DATA-e6b1fa1a, REQ-SEC-3f57f781, REQ-SEC-2fda27e4,
REQ-UX-c553435b, REQ-FUNC-fb24a0e4); no second mechanism.

**Interfaces and data**: spec REQ-DATA-d985bb3d fixes the command line, inputs, job.json, run folder, outcome table,
remote states and exit codes. The CLI child environment is the helper's minus `WOKWI_*` plus `NO_COLOR=1` and, for
run-scenario only, `WOKWI_CLI_TOKEN`. run-scenario writes result.json `incomplete/running` before the CLI starts, then
`exit.json` and the final result; collect-results derives the outcome only from those records and the CLI logs, so a
helper killed by Windows' tree-kill Stop leaves a folder that collects as `interrupted` (REQ-FUNC-3c5b6470,
REQ-REL-88c06ac8). A watch loop (200 ms) enforces the real budget and output bounds and forwards a stop signal as
CTRL_BREAK_EVENT (Windows, new process group; the CLI handles SIGBREAK) or SIGTERM, then kills after 5 s
(REQ-REL-fb090330, REQ-REL-6d7d4558). Outcomes come from exit code plus stderr markers (REQ-FUNC-4ba54556,
REQ-REL-85779c4c); remote is never confirmed except `not-started` after a refused connection. Every CLI output byte
written passes the redactor (REQ-SEC-046ce69f). Scenario YAML is parsed with pinned PyYAML 6.0.3 safe_load.

**Files and test seams**: new `05_Software/plugins/wokwi/` (plugin.yaml, README.md, skills wokwi-simulation and
wokwi-scenarios, scripts/wokwi_tool.py, scripts/wokwi_support/{__init__, cli, report, workspace (byte-identical copy),
engine, project, diagram, scenario, job, credential, redact, run, outcome, collect, operations}.py), catalog.yaml and
packs.yaml entries; shared `mqtt-credentials.ts` -> `plugin-credentials.ts` (+ wokwi save schema), `plugins.ts`,
`ipc.ts`, `index.ts`; core `program-tools.ts` (per-scope not-stored message); desktop main `mqtt-credentials.ts` ->
`plugin-credentials.ts`, `index.ts`; renderer `mqtt-credentials.tsx` -> `plugin-credentials.tsx`, `settings.tsx`,
`mockApi.ts`, locales en/ro/de; CLI `mqtt-env.ts` -> `plugin-credentials-env.ts`, `run.ts`; their tests and the IPC
channel lists (`ipc-router.test.ts`, `bridge.test.ts`), `prepare-plugins.test.ts`. Plugin tests:
`tests/integration/wokwi.test.ts` runs the helper on the toolchain Python with PyYAML and a scripted fake CLI
(`tests/support/fake-wokwi-cli.py` behind a generated `.cmd`/shell wrapper, scenario JSON in `VERA_FAKE_WOKWI`, calls
with argv, cwd, env subset and project listing appended to a log) plus the real ProgramRunner for Stop; an opt-in block
uses `VERA_TEST_WOKWI_CLI` for the real 0.29.1 (REQ-TEST-dce7445c).

**Risks and open decisions**: T07-A (a real cloud run) is an open blocker by the user's decision; every cloud-side
behaviour (server end on close, billing, real error texts beyond the source) stays unproven. The stderr markers come
from the 0.29.1 source; another CLI version is refused, so a changed text cannot silently map to pass. Wokwi's quota is
unknown to VERA; the job states that. Native Ubuntu (linuxstatic binary, SIGTERM path) is not run here.
