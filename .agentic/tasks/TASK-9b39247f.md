## Frame

Problem: plugin programs have no risk classification and no approval path: rules[] are validated but never matched, `ChangeRequest` has only write/edit/web_download variants, the approval card shows diffs and downloads only, and the bypass warning knows nothing about plugins (OBSERVED: `shared/src/plugins.ts` ruleSchema; `core/src/tools/changes.ts` ChangeRequest; `renderer/components/session/approval-card.tsx`; `permission-picker.tsx`; knowledge/plugins.md "Nothing resolves programs, matches rules, asks for approval").
Desired outcome: every program command line gets one risk level from the declaring plugin's rules (highest wins, unmatched device-write, pre-rule refusals), the mode matrix and the trial override decide run / refuse / approval / typed confirmation in core, a `run_program` ChangeRequest binds an approval to the exact command line and the hashes of the workbench files it names, the desktop card shows risk, program and version, full command, notes, file hashes and a typed field, and switching to bypass lists the irreversible rules of the enabled plugins (STATED: ticket #59 scope; architecture §2.2, §4; ADR-0018).
Actors: PLG-04's run_program tool that will classify, request approval and consume it before running; the ApprovalGate; the engineer deciding on the approval card or the CLI prompt; plugin authors whose rules classify commands (STATED: plan PLG-04 depends on PLG-03).
Primary scenario: in `ask`, `espefuse --port COM3 burn-key BLOCK_KEY0 key.bin XTS_AES_128_KEY` of an enabled plugin with rule `espefuse * burn-key *` = irreversible is classified irreversible; the gate records a pending approval whose request lists key.bin with its SHA-256; the card asks the user to type `burn-key`; a wrong word such as `burn` is refused and the approval stays pending; typing `burn-key` approves it once (STATED: ticket "Typed confirmation", done-when "a wrong typed word is refused").
Examples: `esptool --chip esp32 write_flash 0x10000 build/app.bin` matches `esptool * {write-flash,erase-flash} *` = device-write (both spellings, STATED); `idf.py build flash` with build safe and flash device-write is device-write (highest wins, STATED); `esptool frobnicate` matches nothing -> device-write (STATED); `esptool @args.txt` is refused before any rule (STATED); `--driver=x` and `--driver x` match the same rule (STATED); in bypass the irreversible command runs and is recorded decided_by mode (STATED); a trial plugin's `version` (safe) waits for the user's approval in bypass (STATED); rebuilding build/app.bin after approval voids the approval (STATED).
Counterexamples: a safe command in read-only runs without any approval (STATED: matrix); a blocked command never runs, in any mode (STATED); an approval of one call never covers another call or a later command (STATED: "used once and never remembered").
In scope: shared pure matcher and policy (tokens, pattern grammar, highest wins, unmatched default, pre-rule refusals, mode matrix incl. trial, typed-word comparison); core program request preparation (declared-program lookup across enabled plugins, file hashing through the path guard) and the `run_program` ChangeRequest variant; ApprovalGate request/decide/approveBypass/assertGranted/consume for run_program; approval event, session state and export schemas; decide IPC with the typed text; desktop approval card; CLI prompt for run_program; irreversible rules in plugin summaries and the bypass warning listing them; browser mock scenario; en/ro/de strings; unit, gate and mock-mode Playwright tests.
Out of scope: the run_program/program_output/program_stop agent tools, tool class `program`, prompt block, executable resolution and composition with the runner (PLG-04, STATED plan); program version probes and provisioning (PLG-05, STATED); the Plugins settings UI (PLG-06, STATED); the catalog dangerous-token lint (PLG-07, STATED ADR-0019).
Constraints: work on master in this checkout, one commit, no push, no AI attribution (STATED: task brief); format versions stay 1, no compat or migration code; LF; core stays the authority for the typed comparison (STATED: ADR-0018 "checked in core"); all UI strings in en/ro/de (STATED).
Success signals: the five done-when boxes of #59: table-driven tests over every mode-matrix cell plus trial, highest-wins with several subcommands, both spellings, unmatched, @file; a changed image file voids an approval and a wrong typed word is refused; a trial safe command waits in bypass; Playwright approves a device-write run on the card, refuses a wrong typed word then completes with the right one in ask, and shows the bypass warning before the same command runs without a prompt in bypass; `--driver=x` and `--driver x` match the same rule.
Evidence: ApprovalGate request/decide/finish/approveBypass/consume/assertGranted with sqlite `approvals` rows and decided_by user|mode (OBSERVED: `core/src/agent/approvals.ts`); `requestSha256` sorts keys recursively (OBSERVED); the web_download variant shows how a ChangeRequest variant reaches events, session state, card and CLI (OBSERVED: grep web_download); `LoadedPlugin {manifest, record.tier, record.sha256, record.programs}` (OBSERVED: `core/src/plugins/store.ts`); `pluginRiskSchema`, `pluginTierSchema` incl. `trial` (OBSERVED: `shared/src/plugins.ts`); PathGuard.resolve confines and canonicalises (OBSERVED: `workbench/path-guard.ts`); existing bypass warning with suppression preference and its mock-mode e2e (OBSERVED: `permission-picker.tsx`, `tests/e2e/bypass.spec.ts`); the browser mock simulates approvals (OBSERVED: `renderer/mocks/sessions.ts`).
Assumptions: notes are the notes of every matching rule, in manifest order, without duplicates (INFERRED from §4 "every rule note"); the typed word is compared after the matcher's normalisation and trimming, so `BURN_KEY` equals `burn-key` (INFERRED from §2.2 normalisation; the tools accept both spellings).
Unknowns: which token is "the matched subcommand" when an irreversible pattern has no literal after the program (resolved in design: the program name); how two enabled plugins declaring the same program name should behave (no source; resolved conservatively in design); neither changes the done-when.

## Design

**Approach**
- Pure policy in shared, `shared/src/program-rules.ts`: `programTokens`, `classifyCommand(rules, program, args)` → `{risk, notes, confirm}`, `programArgumentRefusal(args)`, `programPolicy(mode, risk, trial)` → `run | refuse | mode | user | confirm`, `confirmationMatches(word, typed)`, `programCommandLine(program, args)` for the card and CLI, and the event payload schema `programApprovalSchema`. Shared because core's gate, the browser mock and the renderer all need the same answers and shared has no Node imports (spec REQ-FUNC-80b2033a; REQ-FUNC-5bb9429f, REQ-FUNC-80b2033a, REQ-FUNC-2819a97e, REQ-FUNC-9ca99463, REQ-FUNC-8d305364).
- Core `core/src/plugins/program-request.ts`: `findProgram(enabled: LoadedPlugin[], program)` (DENIED undeclared/ambiguous, REQ-SEC-59880d86, REQ-SEC-a4d1ac21) and `prepareProgramRequest({workbench, plugin, program, executable, args, cwd?, sessionId, turnId, callId, signal?})`: refusals first (REQ-SEC-28b53f44), classification, then file hashes through a workbench-scope `PathGuard` (REQ-DATA-b4e317de); returns a frozen `ProgramChangeRequest`. PLG-04 will call find → prepare → `gate.request` → re-prepare → `gate.consume` → runner.
- `ApprovalGate` gains a run_program branch keyed on `programPolicy(currentMode, risk, trial)`: refuse → `aborted`, no row (REQ-SEC-94998c85); run → `approved`, no row, and consume/assertGranted accept it without a row; mode → row + `finish(approved, mode)`; user/confirm → pending row. `decide` takes `confirmation?`: under confirm an approval needs `confirmationMatches` (REQ-SEC-e8695b28), else throws `{code INVALID, messageKey approval.confirmMismatch}` before any write, so the entry stays pending (REQ-SEC-08fbf962); `switchToAutoEdit` under confirm → INVALID (REQ-SEC-f40ac584). `approveBypass` approves only entries whose bypass policy is `mode` (REQ-FUNC-43114b84, REQ-SEC-2b4bcdf5). `assertGranted` for run_program replaces the file checks with: policy refuse → CONFLICT; row decided by mode needs current policy `mode` (REQ-SEC-ce28991b). Single use and file binding come from the existing `consume` on `(call, requestSha256)` (REQ-SEC-f98d4fd3).
- Rejected: computing policy in the renderer only (core must be the authority, ADR-0018); one IPC channel per plugin rule list (plugins.list already carries per-workbench summaries).

**Interfaces and data**
- `ChangeRequest` adds `ProgramChangeRequest {tool "run_program", workbench, sessionId, turnId, callId, pluginId, pluginSha256, trial, program, executable, programVersion: string|null, args, cwd, risk, confirm: string|null, notes, files[{arg, path, sha256}]}`; `workbench`, `trial` and `confirm` are added to architecture §4's shape (deviation in planning docs, code wins). `programVersion` = `record.programs[program] ?? null`; `pluginSha256` = `record.sha256`; `trial` = `record.tier === "trial"`.
- Files: each argument, and the value of `--name=value`, joined to cwd (absolute ones made workbench-relative, `..`-escaping ones skipped) that `PathGuard.resolve` accepts and `lstat` says is a regular file; SHA-256 by stream. Any guard error skips that argument; abort propagates.
- Event `approval.requested`: tool enum adds `run_program`; for it `path` = program, `diff` "", `bytes` 0 and `program: programApprovalSchema` (pluginId, trial, program, programVersion, executable, args, cwd, risk, confirm, notes, files); refined like `download`. Session state approvals mirror it; export reuses the event schema.
- IPC `session.approval.decide` adds `confirmation: string ≤ 4096` (optional); `ApprovalDecision.confirmation?`. Desktop main passes the request through unchanged.
- `pluginInstalledSchema.irreversible?: {match, note?}[] ≤ 512`, filled by `PluginStore.summary` only when the plugin has no issues (REQ-DATA-3f62c8c1).

**Files and test seams**
- shared: `program-rules.ts` + `program-rules.test.ts` (tokens, grammar, highest wins, unmatched, refusals, full policy table incl. trial and blocked, word); `events.ts`, `session-state.ts`, `ipc.ts`, `plugins.ts`, `index.ts` + their schema tests.
- core: `plugins/program-request.ts` + test (lookup, refusals, files); `tools/changes.ts` (union); `agent/approvals.ts` + `agent/program-approvals.test.ts` (gate on a real `openDb` sqlite file: matrix, typed word, mismatch, switch, bypass switch, revocation, changed file, single use); `plugins/store.ts` + `store.test.ts`; `index.ts` export.
- desktop: `approval-card.tsx` (badge, command, notes, files, typed field; A/D keys ignored inside the field), `error-message.tsx` (`approval.confirmMismatch`), `permission-picker.tsx` (`workbenchId` prop, irreversible list, shown despite suppression), `workspace.tsx` passes the session's workbench id through `composer.tsx` (the workbench form only sets the default mode of new sessions, so it stays unchanged), `styles.css`, `locales/{en,ro,de}.json`; mock `sessions.ts` (texts "flash" → device-write, "burn" → irreversible run_program approvals decided with the shared policy) and `mockApi.ts` (fixture irreversible rules for mock plugin `esp32-efuse`); e2e `tests/e2e/program-approvals.spec.ts` in mock mode (REQ-UX-9744e270, REQ-UX-12185f60).
- desktop main: `events.ts` redacts known credentials from the program payload of events and snapshots (REQ-SEC-cf3aa5a4, `events.test.ts`; added in validate).
- CLI: `approval-prompt.ts` returns `{decision, confirmation?}` and asks for the word; `run.ts` denies confirm requests under `--approve all|none` or without a TTY (REQ-FUNC-7cf311ae); `approval-prompt.test.ts`.

**Risks and open decisions**
- DEVIATION design: the done-when e2e "run" uses the browser mock, because the run_program tool that would run a real program in Electron is PLG-04; core's gate is proven with real sqlite in unit tests. PLG-04 owes a native replay e2e.
- Between consume and spawn a named file can still change (TOCTOU); PLG-04 should consume immediately before `runner.start`. Recorded for PLG-04.
- The confirmation word is shown on the card by design (the user types what the card names), so it is a deliberate-friction control, not a secret.
- No format version changes; `approvals.request_json` stores the new variant as-is.
