## Frame

Problem: VERA can capture bench waveforms (LAB-01 `scpi-instruments`) and simulate circuits (ELEC-04/05 ngspice,
LTspice), but nothing compares a measurement with a requirement or a simulated reference reproducibly, with its
conditions, preprocessing and uncertainty visible. OBSERVED: no plugin under `05_Software/plugins/` computes
metrics over a capture or a SPICE series against criteria; ngspice-tool `measure` works only on its own run folders
(spec REQ-DATA-29b9a988 §6); scpi `decode` only recomputes a capture.

Desired outcome (STATED, ticket LAB-02 #103, "Livrabile și funcții"):
- An official plugin `lab-validation` with a helper offering `inspect`, `normalize`, `measure`, `align`, `compare` and
  `report`, plus skills for choosing windows/metrics and explaining differences.
- Imports: LAB-01 captures, CSV with a declared channel/unit mapping, sigrok exports converted by existing tools, and
  ngspice/LTspice series in the ELEC contracts. No parser for arbitrary proprietary raw formats.
- A validation request with source and hash, the quantity, criterion/tolerance, time interval, circuit state, relevant
  bandwidth/probe/load, alignment method and missing-data handling.
- Metrics: min/max, mean, RMS, frequency/duty cycle, rise/fall, overshoot, settling, ripple and error against a
  reference; thresholds, window and steady-state definitions are shown, never inferred silently.
- Alignment by a declared trigger/marker or an explicit numeric method with lag limits; correlation never removes a
  delay that is itself the subject of a requirement; instrument clocks are not assumed synchronized from file times.
- Resampling/filtering with explicit method, rate and band; complex AC and time series are not compared directly; no
  samples are fabricated in large gaps or clipped captures.
- Pass/fail applies the declared tolerance and decision rule including the supplied uncertainty; when information does
  not support a verdict the criterion is incomplete/unknown, not a metrological certification.
- A report with overlay and difference, metrics, conditions, preprocessing and links to sources; criteria are never
  widened to obtain a pass.

Actors: the user (writes or approves the validation request, owns requirements and data), the agent (chooses windows and
metrics with the skills, runs the helper, explains differences), VERA's runner, the files (LAB-01 run folders, CSV,
sigrok CSV, ngspice/LTspice run folders), later LAB-03 HIL as a consumer of the verdict.

Primary scenario: after `scpi capture --instrument scope --channel CHAN1` wrote `embedded-lab-results/cap1/` and
ngspice-tool wrote `electronics-results/sim1/`, the agent writes `validation/rc-step.json` naming both sources, the
window, the conditions, a marker alignment, the criteria (rise time <= N us with uncertainty U, ripple <= X mV, max
error to the simulation <= Y mV) and the decision rule, and runs `lab-validate compare --request validation/rc-step.json`;
the helper writes a new run folder with result.json, report.md, overlay/difference SVG and CSV, and prints the verdict.

Examples: STATED Done criteria L02-A...L02-H (ticket). L02-A: synthetic data with an independent solution checks RMS,
frequency, rise time and ripple within tolerances fixed before the test. L02-D: a lag above the requirement's limit
stays `fail` even though a free alignment would make the curves coincide. L02-E: gaps, clipping, evident aliasing or
insufficient band/conditions produce a diagnostic and limit the verdict. No numeric example values were supplied; tests
fix their own before the implementation exists.

Counterexamples: STATED - no calibration certification, no inference of an unknown setup, no automatic circuit repair,
no simulation started by default; no LLM request for numeric computation; criteria never widened; clocks never assumed
synchronized from file times; no interpolation across large gaps or clipped samples.

## Design

**Approach.** A new official package `05_Software/plugins/lab-validation/` following the ELEC/LAB-01 helper pattern:
`scripts/lab_validate.py` (PEP 723, standard library only, `requires-python >=3.11`, no bytecode next to the installed
package) and support package `scripts/lab_validation/`. One in-memory pipeline per run: parse and validate the request
(REQ-DATA-53797d16) -> import sources through the importer registry (hash-checked bytes) -> normalize to SI with sign
and scale -> preprocess in declared order -> measurements (metric registry) -> comparisons (alignment, error
statistics) -> criteria (decision table) -> only then create the run folder exclusively and write files. Each operation
stops the pipeline at its stage (normalize, measure, align, compare); `inspect` stops before writing; `report`
aggregates finished folders. No core/shared/host change: the existing runner, approvals (`safe` rules) and provisioner
run it. Rejected: numpy/scipy (download, platform wheels, not needed for these sizes); importing LAB-01's `scpi_support`
from the installed scpi plugin (fragile cross-plugin import, plan section 3) - the capture is read through its files.

**Interfaces and data.** Command line, request, importers, metrics, alignment, decisions and result: spec
REQ-DATA-53797d16. Registries: `importers.REGISTRY` name -> function(source spec, ctx) -> `Source` with signals;
`metrics.REGISTRY` name -> `Metric(unit rule, kind amplitude|event, definition text, function)`; `--help` and
result `definitions` read them, so later plans add entries without a second engine (RULING-004). Errors: `Refused(code,
message)` -> exit 2 before any folder; a write failure removes the new folder -> exit 3. Paths through a byte-identical
copy of the ELEC `workspace.py` (REQ-SEC-68c33dd4); results `embedded-lab-results/<run-id>/` as LAB-01.

**Files and test seams.** Package: `plugin.yaml`, `README.md`, `skills/validation-planning/SKILL.md`,
`skills/difference-explanation/SKILL.md`, `scripts/lab_validate.py`, `scripts/lab_validation/{__init__, errors, units,
workspace, request, series, importers, preprocess, metrics, align, diagnostics, decide, report, aggregate, cli}.py`.
Registration: `plugins/catalog.yaml` (official, activity measurement), `plugins/packs.yaml` (lab pack group
"Measurement validation", default true). Tests: `tests/integration/lab-validation.test.ts` (package/rules, refusals,
importers incl. a real scpi capture through LAB-01's fake PyVISA, metrics vs `tests/fixtures/lab-validation/README.md`
solutions fixed before code, alignment, decisions, diagnostics, results, reproducibility, report, inspect, network
guard via `sitecustomize`, real-runner ask-mode session, opt-in `VERA_LABVAL_UV`); `tests/fixtures/lab-validation/`
(README with derivations, spice run folders, `guard/sitecustomize.py`); existing tests adjusted:
`tests/packaging/prepare-plugins.test.ts` (21 plugins), `tests/integration/scpi-instruments.test.ts` (lab pack now
has two groups), `tests/integration/ngspice.test.ts` (workspace.py copies include lab-validation).

**Risks and open decisions.** Pure-Python speed: cross-correlation capped at N x (2K+1) <= 1e7 and CSV at 2e6 rows
(spec). sigrok-cli CSV bytes unverified here (no sigrok-cli): the importer also takes a declared rate. Real capture of a
real circuit (L02-F) and native Ubuntu are open proofs. No security surface beyond file reads inside the workbench.

workspace.py; REQ-SEC-58dd05f7 stdlib-only modules, guard test; REQ-DATA-53797d16 request.py; REQ-FUNC-8342826a,

REQ-FUNC-a9ddc5de metrics.py; REQ-FUNC-2f239a32 align.py; REQ-FUNC-257ed295 preprocess.py; REQ-REL-851774fc
