## Frame

Problem: `Disclosure` always renders its children and only toggles `hidden` (OBSERVED `renderer/components/session/disclosure.tsx:27`), so every collapsed tool row builds `JSON.stringify(args, null, 2)` and its preview `<pre>`; `Transcript` maps every row inline with no memoization and `Markdown` passes fresh plugin arrays and a fresh `components` object to `ReactMarkdown` each render (OBSERVED `transcript.tsx:130-244`, `markdown.tsx:116-133`), so every live event re-parses every message; per-row `toLocaleLowerCase`, `state.approvals.filter` and `[...items].reverse().find` repeat per render (OBSERVED `transcript.tsx:80,172-182,219`). After PERF-02 a 2,000-message session still loads in ~1.8-2.3 s, mostly renderer time (STATED coordinator brief).
Desired outcome: collapsed tool details cost nothing until opened; a finished message is parsed once and skipped on later transcript renders; search and approval lookups are computed once per state change (STATED #251 Goal).
Actors: the user reading/opening a session in the desktop renderer; the live session-event subscription.
Primary scenario: the user opens a long session; collapsed tool rows contain only their toggle; while a reply streams, only the streaming message row re-renders.
Examples: a collapsed tool row has no preview text in the DOM, and its toggle's `aria-controls` resolves to an (empty, hidden) element; pressing Enter/Space shows the arguments and preview. Appending one `message.delta` to a 200-item state re-renders only the touched row.
Counterexamples: approval cards, failed-tool rows, downloads, Retry and stopped status stay visible exactly as today (they are outside collapsed content or are rows, not disclosure children).
In scope: lazy `Disclosure` children (keep `id`/`hidden` container); memoized `MessageRow`/`ToolRow`/`ErrorRow`/group row components in `transcript.tsx` with shallow props; hoisted `ReactMarkdown` plugin arrays and `components` map, memoized `Markdown`; `useMemo` for approval-by-call, lower-cased search text, latest error, rows and navigator messages; tool title args summary capped; targeted tests incl. a render-count test (STATED #251 plan 1-5, Tests; coordinator brief scope 3-4).
Out of scope: virtualization/windowing, event batching (PERF-04), validation on read (PERF-05), main-process changes (STATED #249 ordering); find-in-page over collapsed output (STATED #251 Risks: acceptable).
Constraints: no new dependency; Windows and Linux; behaviour identical (search, citations, approvals, CHAT-NAV-01 navigator, keyboard on disclosures); targeted tests only; 1-2 review rounds (STATED coordinator brief).
Success signals: targeted session component tests green (except the known pre-existing `workspace.test.ts` Settings `parts` failure); render-count test green; `perf:sessions` quick payload presentationMs near medium and lower rendererGapMs vs `perf02-after.json` (STATED #251 Measurement).
Evidence: OBSERVED file reads above; `aegis explain disclosure.tsx` lists REQ-UX-4bea0002 (Streamed transcript) and the transcript-projection header cites REQ-UX-0165dafe (detail levels).
Assumptions: INFERRED from PERF-02 (commit 2cd182c) that `applySessionEvent` keeps unchanged items' identity, so default shallow `React.memo` comparison suffices; INFERRED `t` from `useTranslation` is stable across renders while the language does not change.
