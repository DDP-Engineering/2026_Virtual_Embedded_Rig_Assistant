## Frame

Problem: New Workbench only asks for a name and folder and mixes create with open (STATED: "cand dau click pe new workbench - imi apare sa selectez folder si open workbench. Open workbench e deja optiune separata"). The page also repeats the sidebar's Open and Recent entries (OBSERVED: renderer/components/workbench.tsx 241-310). Configuration exists only after creation, in the modal WorkbenchEditor (OBSERVED: workbench-editor.tsx). Documentation folders are free-text globs with no picker or autodetection (OBSERVED: ingest.ts 96-115, editor "documents" section). Retrieval defaults are hardcoded (OBSERVED: core knowledge/search.ts 15-22). Office formats are not indexed (OBSERVED: ingest.ts documentKind supports pdf, md, html and text extensions only).
Desired outcome: New Workbench creates only. The user picks a folder, reviews and edits the full workbench configuration, then creates it (STATED: "As fi preferat sa apara setarile de workbench cu selectie tool-uri, skill-uri, editare md, buton selectie sau autodetectie foldere documentatie, indectare, setari rag si indexare"). The same configuration surface edits an existing workbench as a full page (STATED: the user accepted all three recommendations: a single sectioned page instead of a wizard, a full-page editor, and folders outside the workbench deferred). Documents include txt, doc, ppt, docx and similar office formats (STATED: "documente nu sunt doar pdf si markdown. Avem si txt, doc, ppt, docx etc.").
Actors: the embedded engineer who creates and configures workbenches in the desktop app. The agent consumes the resulting configuration (tools, skills, instructions, retrieval).
Primary scenario: New Workbench → choose folder → name defaults to the folder name → detected documentation folders are offered for selection → optionally adjust instructions, agent, tools, skills, indexing and RAG → Create → the workbench opens and indexing progress is visible.
Examples: Folder `C:\bench\esp32-s3-devkit` with `datasheets/` (PDF) and `notes/` (md, docx) → both offered, checked, name "esp32-s3-devkit". A folder that already has .vera/workbench.yaml → offered to open instead of failing with CONFLICT.
Counterexamples: a documentation library on another drive, outside the workbench folder, is not selectable in this task (STATED: deferral recommendation accepted).
In scope: child tasks, run sequentially in this checkout:
  1. Creation page and shared configuration form. Create-only page, folder first, name default, existing-workbench open offer, draft configuration (instructions, agent, tools, skills, embeddings) written on create, full-page editor reusing the same form, post-create indexing progress, shared e2e creation helper.
  2. Documentation folder detection and selection: scan, checklist with counts and size, Add folder picker (inside the workbench only), advanced globs, indexing preview.
  3. Configurable retrieval defaults in workbench.yaml, consumed by document search.
  4. Office document ingestion (docx, pptx, xlsx, odt and others, plus legacy doc/ppt/xls, per the child's decision).
Out of scope: document folders outside the workbench root (STATED: deferral accepted); plugin backends and MCP (OBSERVED: Plugins is a placeholder; not requested now); schematic image interpretation (STATED: "vom vedea mai tarziu cum"); migrations for earlier development layouts (STATED: AGENTS.md development compatibility policy).
Constraints: implementation on master in the shared checkout, one implementation chat at a time (STATED: AGENTS.md). Core stays Electron-agnostic and the renderer uses shared IPC (OBSERVED: project.md). en/ro/de catalogs must stay in parity (OBSERVED: scripts/check-i18n.mjs). Focused tests per ticket and full suites only at milestone gates (STATED: 02_Tools/verification-policy.md). The CLI composes WorkbenchService too (OBSERVED: apps/cli run.ts 130, documents.ts 28). The current branch is the default branch master; AGENTS.md directs implementation there.
Success signals: creating a workbench from the New page writes the chosen configuration and instructions in one create; the New page offers no Open/Recent duplication; the edit page shows the same sections; selected detected folders appear in docs.include; retrieval defaults change search_docs defaults; office documents produce indexed chunks.
Evidence: subagent code map of the renderer, IPC, core and schema (2026-10-31); ingest.ts and workbench-editor.tsx read directly; .agentic/knowledge/workbench.md.
Assumptions: none beyond the labelled claims.
Unknowns: whether legacy binary formats (doc/ppt/xls) are extracted through an installed LibreOffice or a pure-JS library (decided in child 4); the default retrieval values exposed (child 3).
Decision-blocking questions: none for the parent; the legacy-format approach blocks only child 4 and is asked when that child starts.
Proposed behaviors: (not accepted) the name defaults to the folder basename; detected folders are pre-checked; Create is enabled once a folder is chosen.
