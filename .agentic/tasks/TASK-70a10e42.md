## Design

### Approach

- REQ-UX-9fc1fb7c: Use the existing file menu without delaying its ordinary or diff actions. Only the open file or virtual-deletion menu requests eligibility. Main checks exact index entries and an applicable HEAD deletion against the literal path and approved parent chain. No workbench-wide index preflight runs for these history-only reads.
- REQ-FUNC-52bd38ff and REQ-SEC-788f3385: Reuse GitReader's private metadata and fixed command settings. Resolve HEAD in the snapshot and inspect raw NUL-delimited file events with Git's single-path rename following. Validate each candidate against the exact path, stop before an out-of-scope predecessor, and check selected deletions and ambiguous additions with bounded rename detection. If a verified in-scope rename into a former directory was missed by the path log, resume from the actual parent with the verified old path, with at most four path-log segments. For admitted hashes, request only author, author date and subject in a bounded NUL-framed Git projection with explicit UTF-8 re-encoding and exact hash order. Never send raw tree names, status records or process diagnostics.
- REQ-SEC-5ac0eca4: Use typed eligibility and history IPC with the same workbench ID and lease admission, main-side Display identity resolution, cancellation and pre-response checks as diff. Apply live masking to labels, author and subject before bounding the final text.
- REQ-REL-6b7f009b and REQ-UX-a033771c: Add a distinct transient target to the shared tab provider with workbench, lease and path identity. Share Chat visibility, navigation, close, retry and Display invalidation. Present statuses and inert commit text in the central panel.

### Interfaces and data

- OBSERVED (current GitReader and #366): Existing scope and Display helpers already support a literal selection and an app-owned Git snapshot. The two new channels accept only the existing index scope and opaque path.
- INFERRED (#367 bound and scope constraints): Use a 50-entry first page, one lookahead candidate, fixed byte/time limits, and no continuation in v1. Track a detected scope boundary independently of the page cap. If a command or format fails, discard partial bytes. Distinguish unavailable, malformed, input exceeding the bound, no reachable commits, and unborn HEAD.

### Files and test seams

- Reader and service tests use disposable native repos and injected lease transitions. Renderer tests verify a selected-menu lookup and tab requests. The existing native Git tabs spec grows a history scenario alongside TXT, PDF and both diffs.
- Shared IPC defines result bounds. DisplayDocuments owns masking. Files and central tabs render translations; the localized help explains local HEAD and rename and page limits.

### Risks and open decisions

- OBSERVED (native Git probe): a forward move out of scope appears as a deletion for the old pathname. Its unsliced path metadata must be checked inside main before admitting the commit. Git rename detection is heuristic. The history view has no patch or arbitrary revision/argv interface.
