## Design

**Approach.** Add `NotificationSettings` under `Settings`, using native select and checkbox-switch
controls. Reuse `SettingsPageHeader`, `useSettingsDraft` and the dirty callback. Save sends only the edited
fields through `app.settings.update`. Confirmed snapshots clear matching edits. Failed saves show
the existing Settings error and keep the draft (REQ-UX-f7a53a4c, REQ-UX-032aab57, REQ-UX-6a1c936e).

**Interfaces and data.** The shared format-1 `notifications` object requires `turnCompletion` with
`never`, `background` (default) or `always`, and `approvalRequests` as a boolean defaulting true.
The typed IPC accepts a strict partial nested patch. `SettingsService` serializes saves, calls
`mergeSettings` and publishes the confirmed snapshot after its atomic write. The mock uses
the same defaults and merge (REQ-DATA-1ec20f7a, REQ-DATA-fadf40d6).

**Files and test seams.** Update the shared settings contract and its format-1 specification,
the settings panel and locales, literal settings fixtures, Interface, Settings Help and release notes.
Shared schema tests cover strict validation; service tests cover persisted partial writes; browser
tests cover keyboard navigation, all locales and failed saves; native Electron covers actual restart.

**Risks and open decisions.** The strict settings parser applies the current pre-release reset policy.
Native delivery will read the saved preferences via the existing settings service in #390. Help treats
system support as capability, with OS controls governing delivery (REQ-UX-ee964ea7).

**Requirement map.** REQ-DATA-1ec20f7a and REQ-DATA-fadf40d6 map to shared contract and persistence;
REQ-UX-f7a53a4c, REQ-UX-032aab57 and REQ-UX-6a1c936e map to the page and browser/native proofs;
REQ-UX-ee964ea7 maps to the localized Settings Help content and the Help audit.
