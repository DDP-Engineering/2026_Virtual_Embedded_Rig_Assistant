## Design

**Approach.** Share the IMG-02 raster file reader and transformer. The new read-class
tool uses the ordinary primary-workbench guard and a canonical link refusal option
(REQ-FUNC-19936eec, REQ-SEC-1d25462f, REQ-FUNC-33cb0bb1).

**Interfaces and data.** The tool takes a strict path argument and returns small JSON
path text plus a typed image part. ToolRegistry and ReferenceRuntime keep the part
separate from capped text and durable events. The runtime attaches it to the matching
tool result only in the current turn's request view. Image reads run serially and prepare up to
eight successes per step, with only the eight most recent images retained for the
turn. ContextPolicy counts them and
omits it with text-only capabilities. Model capability controls schemas and execution,
including a recheck at dispatch (REQ-FUNC-19936eec, REQ-FUNC-ac4610c1).

**Files and test seams.** Core tools, path guard, agent runtime, context and session
gateway implement the tool path. A real loopback provider checks pixels and gating.
Tools uses typed IPC and ProviderGateway to resolve the draft default or its inherited
application default. The editor test covers model switching (REQ-UX-6cfb7f2f).

**Risks and open decisions.** Explicit IMG-05-B confinement holds even in Bypass
and outside-folder grants. Normal ignore and excluded-root rules apply. The
managed IMG-02 namespace opens only for the exact delivered current-session path
confirmed by a targeted query of durable user rows,
so a composer image can be viewed again from its retained path. The codec
shares IMG-02 detection, size, scaling and cancellation. The session only stores the
tool path text, and the model can call the tool again to see the current file.

**Requirement map.** Raster output and refusal share the codec. Path refusal belongs
to PathGuard. Runtime and gateway gate schemas and execution. The editor and main
gateway own draft capability display. The Help topic explains tool use and masking.
