## Frame

Problem: OBSERVED: the gateway does not expose model input modalities in VERA's capability
contract, and custom pi-ai models always declare text input (core llm/providers.ts and shared
providers.ts).
Desired outcome: STATED (#293 and chat-images.md): expose each model's image capability from
the ChatGPT catalog, OpenAI model list or saved custom switch, and provide acceptsImages(model).
Actors: STATED: VERA users configuring LM Studio, Ollama or an OpenAI-compatible endpoint,
and callers consuming model metadata.
Primary scenario: STATED: users open Settings > Providers, enable Accepts images for a
specific custom model, save and see the setting for that model when they return.
Examples: STATED: an enabled custom model accepts images. OBSERVED: ChatGPT input_modalities
can include image; the pinned OpenAI provider supplies its own model definitions.
Counterexamples: STATED: a newly configured custom model starts with the switch off.
In scope: STATED: IMG-01 capability, per-model settings, test proof, EN/RO/DE/FR help and release copy.
Out of scope: STATED (chat-images.md): message payloads, composer and transcript images, and view_image.
Constraints: STATED: use the epic sibling checkout and branch, focused proofs, static checks,
strict AEGIS and both independent reviews. The candidate stays unstaged and uncommitted
for the coordinator's authorized local ticket commit.
Success signals: STATED (IMG-01-A): capability tests for ChatGPT, OpenAI, LM Studio, Ollama
and other OpenAI-compatible endpoints, plus switch persistence in settings.
Evidence: OBSERVED: Gitea issue 293, chat-images.md, the ChatGPT parser, provider gateway,
provider settings service and both custom editors. The public OpenAI GET /models response
lists basic metadata without modalities (OpenAI API reference).
Assumptions: INFERRED: the OpenAI model list is the gateway's pinned pi-ai model catalog
because VERA already resolves these models there and the public API listing omits modalities.
Unknowns: UNKNOWN: capabilities of models outside the catalogs VERA currently supports.

## Design

### Approach

- OBSERVED: ChatGPT already parses the account's input_modalities. Deduplicate recognized modalities and project them through gateway capabilities so the same values reach the provider catalog and the selected model (REQ-FUNC-95c412df).
- INFERRED: the pinned pi-ai OpenAI catalog already supplies authoritative input lists for models the gateway can select. The HTTP model list remains a reachability probe (REQ-FUNC-4dbd29dd).
- STATED: custom image support is opt-in per model. Build pi-ai input from exact membership in the saved provider's model IDs (REQ-FUNC-59607b77).

### Interfaces and data

- INFERRED: the shared capability contract supplies an input array of recognized modalities, so acceptsImages can also inspect a pi-ai model structurally (REQ-FUNC-7ea3fa8c). Replay is text-only.
- INFERRED: optional imageModels on a custom provider holds enabled IDs. Missing and empty both mean all off. An explicit empty list clears the setting. The current settings save and read paths own validation and persistence (REQ-UX-1eb152b7, REQ-FUNC-8446181d).
- OBSERVED: generic endpoints use a model ID field and LM Studio uses a discovered-model selector. A shared switch edits the current ID in each form and submits with the existing save (REQ-UX-1eb152b7).

### Files and test seams

- Core gateway and catalog tests exercise ChatGPT, pinned OpenAI and each custom provider kind. The shared helper test checks membership, and the main provider test rejects malformed and duplicate IDs.
- Browser provider tests exercise model switching and rediscovery, and the native provider test reopens the saved form after restarting.

### Risks and open decisions

- OBSERVED: two connections may report the same model ID. The setting is local to a saved connection. Rediscovery for that connection uses the same model ID. No storage version change is required under the pre-release policy.
- OBSERVED: provider catalog IDs and saved settings already pass credential guards. The existing save transaction remains the write boundary. No open design decisions.

### Requirement map

- REQ-FUNC-95c412df and REQ-FUNC-4dbd29dd map catalog modalities to both gateway surfaces.
- REQ-FUNC-59607b77 and REQ-FUNC-8446181d map validated custom IDs to pi-ai input.
- REQ-UX-1eb152b7 maps the switch to the existing save and reload flow.
- REQ-FUNC-7ea3fa8c maps the shared input contract to the capability predicate.
