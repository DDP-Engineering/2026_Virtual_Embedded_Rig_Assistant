## Frame

Problem: The 37 official plugins have no user help and English-only catalog texts, so the plugin Help buttons and the
help tool have nothing to show (STATED plan `00_Planning/plan/help.md` HELP-08; OBSERVED no `plugins/*/help/`).
Desired outcome: `help/<en|ro|de|fr>.md` for all 37 official plugins, written for the user from each plugin's
README, plugin.yaml and skills (what it does, what it needs, how to ask the agent, risk and approvals), and
`translations` with ro/de/fr summary and description in every `plugin.yaml` (STATED plan HELP-08).
Actors: users of the plugin page, Help and the catalog; the agent.
Primary scenario: a French user installs esp32-esptool from the catalog, sees its French summary, opens its Help and
reads `help/fr.md`.
Examples: `serial-monitor/help/en.md` title "# Serial monitor"; `serial-monitor/plugin.yaml` `translations.fr.summary`.
Counterexamples: README.md stays the technical reference (STATED plan); vendor programs are described, never bundled.
In scope: 148 plugin help pages, 37 plugin.yaml `translations` blocks, the browser E2E `tests/e2e/help-plugins.spec.ts`
(it needs these pages), CONTRIBUTING notes already landed with HELP-04.
Out of scope: community plugins; human review of ro/de/fr (STATED plan "Open", deferred).
Constraints: manifests stay `format: 1` (STATED memory rule); summary ≤ 160, description ≤ 1024 (REQ-DATA-b8d0a387).
