## Design

**Approach.** OBSERVED - BrowserRuntime, BrowserHost, BrowserAccessPolicy and AgentBrowser already split provisioning, ownership, authorization and browser operations. Add strict trusted Desktop IPC and localized React surfaces over those owners. REQ-UX-4c16a20f, REQ-UX-8c54a766, REQ-SEC-39c979a5.

**Interfaces and data.** Settings reads runtime state and current workbench opt-in. It uses existing settings and workbench config writes, and separate explicit provisioning and removal actions. Removal blocks new leases until all browser sessions drain. Chat requests include the current workbench and session IDs and main verifies ownership before reading state or mutating it. Core's current session context locates the Desktop adapter. Its view projects typed activity and the currently authorized selected URL, plus typed failures. Renderer caches are keyed by both IDs; no location or grants persist on disk. REQ-UX-59086d40, REQ-SEC-1f3fba00, REQ-REL-df91d9fe, REQ-REL-6fecfe63, REQ-REL-646a1376, REQ-REL-3dc8d834.

**Files and test seams.** Use existing Zod IPC validation, Settings Web access panel, Chat workspace and session Stop handler. Add focused browser runtime and adapter assertions plus the packaged real-UI replay spec. Keep help and renderer localization aligned. REQ-UX-74f740e9, REQ-FUNC-ae3000ef, REQ-UX-da941b4d.

**Risks and open decisions.** The request owner is checked on the current sessions queue, including archived sessions. Policy revocations precede asynchronous cleanup. Existing package inputs and network boundaries remain unchanged; native Ubuntu execution is unavailable.

**Requirement map.** The design column above identifies the owning sources. Browser controls replay covers user actions and lifecycle, and runtime, adapter and IPC tests cover trust and error boundaries.
