## Design

**Approach.** STATED REQ-FUNC-c1af1946 and REQ-UX-72b09d3a use a validated session IPC call for both external bytes and existing primary-workbench references. The Files menu gains an image action for supported raster files; ordinary context actions remain available.

**Interfaces and data.** INFERRED The existing main-side session/workbench queue owns admission, including archived state, open-workbench identity and lock checks. For REQ-SEC-a86087cf and REQ-SEC-2beadc98, reuse primary-workbench PathGuard and raster signatures, opening only the managed attachment namespace for image readers, bound bytes before decoding, compare recognized extensions with the signature, and create a bounded PNG preview before publishing the original bytes to a generated name. An existing file uses the guarded read and its existing path.

**Files and test seams.** OBSERVED Shared IPC validation owns message schemas. INFERRED New shared raster metadata and a core composer image store support the Desktop IPC handlers; App owns image draft lists and pending/error state, Composer handles file events and chip rendering, Files emits a dedicated drag type. Focused native Playwright covers the complete renderer/main flow; browser Playwright and native filesystem tests cover the input paths, limits and negative boundaries.

**Risks and open decisions.** INFERRED Recheck ordinary import directories and exclusive destination identity before writing. Send and image import must stay ordered while drafts are pending. Use existing Blob CSP and revoke previews after unmount. No dependency or stored-format changes.

**Requirement map.** REQ-UX-c3961c76 uses a bounded per-session draft and mount-owned thumbnail URLs. REQ-UX-9427b929 looks up current effective model capability through the same model resolver as dispatch, with image sends waiting for the initial result, and settled failures leaving capability unknown. Catalog I/O releases the session queue while it is pending. REQ-FUNC-4436607c passes the images list to the existing send IPC and clears only acknowledged entries. Other mappings are described in Approach and Interfaces and data.
