## Frame

Problem: Nothing checks that help stays complete: a page missing in one language, a broken link between pages or an
empty page would ship unnoticed (STATED plan `00_Planning/plan/help.md` HELP-07 and decision "The check script
requires all four for the app and for official plugins; community plugins may ship English only").
Desired outcome: `02_Tools/build/check-help.mjs` (`npm run check:help`) fails, naming each problem, when an app
language lacks a page English has (or has one English lacks), when an official plugin lacks `help/<lang>.md` for one
of en/ro/de/fr, when a relative link in any help page does not name an existing app page, or when a page has no text
besides its title; it is part of `npm run verify` (STATED plan HELP-07).
Actors: developers and CI running `npm run verify`.
Primary scenario: a writer adds `help/en/updates.md` but not the French page; `npm run check:help` prints
`app fr missing page: updates` and exits 1.
Examples: `[Permissions](permissions.md)` is valid when `help/en/permissions.md` exists; `[x](missing.md)`,
`[x](../README.md)` and `[x](permissions.md#modes)` are broken; a page containing only `# Title` is empty.
Counterexamples: a community plugin (not in `plugins/catalog.yaml` `official`) with only `help/en.md` passes;
`https:` links are not checked (no network).
In scope: the checker with an exported `auditHelp`, its CLI, `check:help` in package.json and verify, the AEGIS
config check list, a tooling test and a CLI fixture.
Out of scope: the pages themselves (HELP-06, HELP-08); spelling or translation quality.
Constraints: no network, no new dependency (yaml is already a 05_Software dependency, OBSERVED
`tests/packaging/packaging.test.ts` imports it). On `master`.
Success signals: the tooling test shows each failure kind; `npm run check:help` passes on the finished content.
Evidence: OBSERVED `check-i18n.mjs` pattern (exported audit + `--fixture` CLI) and `catalog.yaml` `official` list of
37 ids.
Assumptions: help links use the bare `name.md` form only (INFERRED from HELP-02 link handling and the writers' rules).
Unknowns: none.
Decision-blocking questions: none.
Proposed behaviors: anchors in links are reported as broken (the Help view resolves pages, not headings).
Path and reason: full.

## Design

**Approach.** Same shape as `check-i18n.mjs`: a pure `auditHelp({app, plugins, official})` returns sorted error
strings; the CLI loads `05_Software/help/<lang>/*.md`, `05_Software/plugins/<id>/help/<lang>.md` and the official ids
from `plugins/catalog.yaml`, or a `--fixture` JSON, prints the errors and exits 1, else one summary line.
**Interfaces and data.** `app: {lang: {page: text}}`, `plugins: {id: {lang: text}}`, `official: string[]`. Messages:
`app <lang> missing page: <page>`, `app <lang> page not in English: <page>`, `plugin <id> missing help: <lang>`,
`broken link in <where>: <target>`, `empty page: <where>` where `<where>` is `app/<lang>/<page>` or
`plugin/<id>/<lang>`. Links are `](target)` outside fenced code; `http:`, `https:` and `mailto:` are skipped.
**Files and test seams.** `02_Tools/build/check-help.mjs`; `05_Software/package.json` (`check:help`, verify);
`.agentic/aegis.toml` (`help` command in the check run list); `05_Software/tests/tooling/help.test.ts`;
`05_Software/tests/fixtures/help/broken-link.json`.
**Risks.** Wired into verify: committed after the content so every commit on master stays green.
**Requirement map.** REQ-TEST-9f88aab3 page sets; REQ-TEST-af2cc3f5 links and empty pages.
