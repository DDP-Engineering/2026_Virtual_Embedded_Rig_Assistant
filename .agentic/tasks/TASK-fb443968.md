## Frame

Problem: At the Verbose chat detail level the statistics line under each user message shows input/output tokens and initial context but no date or time (STATED by the user: "imi arata si tockeni intrare iesire - dar nu imi arata data si ora"; OBSERVED in `session/prompt-usage.tsx`, which renders input, output, initial context and shared only). A directly sent prompt carries no time in its `message.user` event or user transcript item (OBSERVED: `shared/src/events.ts` message.user has messageId/text/images; `session-state.ts` sets `timestamp` only for `message.queued`).
Desired outcome: At Verbose, each user message whose send time is known shows that date and time, to the minute, in the app language, on its statistics line; Normal and Minimal show no such line, as today.
Actors: The user reading a session transcript in the desktop app at Verbose.
Primary scenario: The user switches a session to Verbose and sees, under each of their messages, the date and time it was sent next to the token counts.
Examples: A message sent on 2026-11-20 at 17:54 in a Romanian UI shows a date-and-time value equivalent to "20.11.2026, 17:54"; in English the same instant shows "11/20/26, 5:54 PM" (exact separators follow Intl formatting; INFERRED from the user choosing minute precision and language-dependent order). A message queued while a turn runs shows the time it was queued (STATED: "Message sent (Recommended)" option text "when you sent the message (or put it in the queue)").
Counterexamples: At Normal or Minimal no time shows. Assistant replies show no time (STATED: user chose "Message sent", not "Sent + reply finished"). No seconds are shown (STATED: "Minute").
In scope: Recording the send time of directly sent user prompts in the durable session events; carrying it into the shared user transcript item; showing it, localized to minutes, on the Verbose statistics line in en/ro/de/fr.
Out of scope: Reply finish times or durations (STATED: user chose sent time only). Filling a time for messages recorded before this change (STATED standing rule, memory no-backward-compat: pre-release, no migrations or compat code). Constraints: Work on master, the repository's default branch (STATED: "pe acelasi branch"). Session events stay schemaVersion 1 (STATED standing rule: version fields are never bumped pre-release). The time must not reach the model request or change what the agent sees (INFERRED from REQ-UX-bc9adf3a being display-only).
Success signals: A Verbose user message shows its localized date and time to the minute after send, after app restart and for queued messages; Normal/Minimal show none; messages without a recorded time show no time and no placeholder error.
Evidence: OBSERVED `prompt-usage.tsx`, `transcript.tsx:390` (PromptUsage only at Verbose), `shared/src/events.ts` (message.queued has `timestamp`, message.user has none), `shared/src/session-state.ts` (user item `timestamp` optional, set on queue), `core/src/agent/runtime.ts:140-142` (prompt built with `this.host.now()`, `message.user` emitted without it), `core/src/storage/repos/events.ts` (rows also hold `created_at`).

## Design

**Approach**: Stamp the time where the prompt is admitted. `ReferenceRuntime.send` already builds the model prompt with `this.host.now()`; it now keeps that value and emits it as `timestamp` on `message.user` (REQ-DATA-22f13161). The shared reducer copies it to the user item, as `message.queued` already does; an existing item (a delivered queued prompt) is never replaced, so it keeps its queue time. The renderer formats the item's `timestamp` in `PromptUsage`. Rejected: deriving the time from the events table `created_at` column, because the renderer folds live `(seq, event)` pairs that do not carry row metadata, and backfilling old rows is excluded by RULING-002.

**Interfaces and data**: `message.user` gains optional `timestamp` (the shared `count` schema, epoch milliseconds), and the core `AgentEvent` union gains the same field. Optional, so events recorded earlier still parse and fold without a time (RULING-002, no schemaVersion change). The model request is unchanged: the `pi-ai` message already carried this timestamp, and nothing is added to the content. In the renderer, `PromptUsage` takes `timestamp?: number` and shows `Intl.DateTimeFormat(language, { dateStyle: "short", timeStyle: "short" })`, minute precision, memoized per language like the number formatters (REQ-UX-8ec4dc82, RULING-001). With no timestamp, no date span is shown. `transcript.tsx` renders the line at Verbose when the item has usage or a timestamp, so a just-sent prompt shows its time before usage arrives.

**Files and test seams**:
- `shared/src/events.ts`, `shared/src/session-state.ts`: a test in `shared/src/session-state.test.ts` (fold, the queued-then-delivered case, a legacy event with no time).
- `core/src/agent/types.ts`, `core/src/agent/runtime.ts`: `core/src/sessions/prompt-time.test.ts` covers the runtime stamp through the session service, the queued time, restart, and the unchanged model prompt.
- `renderer/components/session/prompt-usage.tsx`, `transcript.tsx`: tests in `transcript-detail.test.ts` (en/ro formatting, no seconds, no date without a time, Normal/Minimal none). `activity-usage.test.ts` stays the regression test for the token values.
- Mock `renderer/mocks/sessions.ts` stamps `message.user`, so browser mock mode shows times.

**Risks and open decisions**: Time zone is the machine's local zone through Intl. Clock skew is not handled. None open.

**Requirement map**: REQ-DATA-22f13161 runtime stamp plus reducer copy. REQ-UX-8ec4dc82 PromptUsage date span and the render condition. REQ-UX-bc9adf3a and REQ-DATA-e31bdc18 have no design impact (regression only).
