## Frame

Problem: `applySessionEvent` deep-copies the event and the whole state with `JSON.parse(JSON.stringify(...))` per event (OBSERVED `05_Software/src/libraries/shared/src/session-state.ts:112-114`). `SessionHub.get` and `buildSessionMarkdown` fold every stored event through it (OBSERVED `libraries/core/src/sessions/hub.ts:28-36`, `export.ts:21`), so opening a session is quadratic; the renderer applies every streamed delta through it (OBSERVED `renderer/hooks/use-session-events.ts:58`), giving every item a new identity per token. Baseline: 2,000-message snapshot 2.5-4.0 s, 64 KiB payload case 455 ms (STATED #249 section 2).
Desired outcome: stored events fold in linear time in place (`foldSessionEvents`), and a live event copies only the touched collection and item (`applySessionEvent`, structural sharing); terminal states are identical to today for every event type (STATED #250 Goal).
Actors: SessionHub.get (main), session export, renderer live subscription, browser mocks.
Primary scenario: the user opens a saved 2,000-message session; main folds the events once without per-event full copies; while a reply streams, unchanged transcript items keep their object identity.
Examples: a `message.delta` for message m returns a new state whose `items` array and item m are new, while every other item is `toBe` the previous one; folding the golden mixed sequence gives the same state as the old implementation.
Counterexamples: an event that does not change a collection (e.g. `reasoning.delta`, `tool.update`) must not copy `items`.
In scope: session-state.ts reducer split (in-place fold with id index, copy-on-write live apply), hub.ts and export.ts callers, renderer mocks folding whole histories, targeted tests (oracle against the old implementation for every event type, deep-freeze/identity) (STATED #250 plan 1-5, Tests).
Out of scope: removing `sessionEventSchema.parse` in hub.ts (PERF-05, STATED), transcript memoization (PERF-03), batching (PERF-04), an index in the renderer path (STATED #250 plan 3: measure first).
Constraints: no new dependency; Windows and Linux; no format change; behaviour identical; targeted tests only, 1-2 review rounds (STATED coordinator brief).
Success signals: oracle tests green for every event type; deep-freeze test green; core sessions/export and renderer hook tests green; `perf:sessions` quick large/payload snapshotMs drops by an order of magnitude versus the baseline report.
Evidence: OBSERVED file reads above; requirement REQ-FUNC-5e2438d5 (fold consistently) governs session-state.ts (`aegis explain`).
Assumptions: INFERRED the reducer never mutates event-owned objects (it only stores references to args, citations, todos, approval download/program), so folding owned or re-used events in place is safe for read-only consumers.
Unknowns: native Ubuntu run of the tests (no Ubuntu machine in this session; pure TypeScript, so INFERRED no platform difference).
